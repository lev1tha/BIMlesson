# CLAUDE.md — Интерактивный учебный портал кафедры БИжЭМ

## 🎯 Назначение и Философия
Учебный портал для студентов бакалавриата направлений **«Бизнес-информатика»** и **«Математика в экономике»**.
Главный принцип: **«Сначала визуальный и интерактивный опыт, потом теория»**.

Проект объясняет, как устроена цифровое железо и инфраструктура современного бизнеса — от транзистора и IP-адреса до облачных бэкендов ERP-систем и безопасности финтеха.

### Таблица дисциплин (`content/`):

| slug                  | Дисциплина                                       | Профильный интерактив & Геймификация |
| --------------------- | ------------------------------------------------ | --------------------------------------------- |
| `computer-systems`    | Вычислительные системы, сети и телекоммуникации  | Симулятор конвейера CPU, интерактивный OSI-пазл, VLSM-калькулятор подсетей для IT-отделов, анимация маршрутизации |
| `systems-programming` | Системное программирование (JavaScript / Node)   | Песочница кода, автопроверка алгоритмов, оптимизация бизнес-логики |
| `web-development`     | Разработка сайтов и Web-дизайн (HTML/CSS, Figma) | Live-редактор, сборка бизнес-лендингов по эталону, CSS Flex/Grid визуализатор |

> **Локализация: Кыргызстан.** Валюта в примерах — сом (тыйын как минимальная единица), статистика и регуляторы — КР (Нацстатком, НБКР, ГНС), домены в примерах — .kg, часовой пояс — Asia/Bishkek (UTC+6), города — Бишкек, Ош. Российские реалии (₽, Росстат, ЦБ РФ, Москва) в примерах не использовать.

> **Аудитория:** Студенты 1–2 курса. До 70% трафика — с мобильных устройств. Мобильная адаптивность (от 360px) — безусловный приоритет №1.

## 🛠 Технологический стек

- **Next.js (App Router) + TypeScript** — строгий режим (`noImplicitAny`, без `any`).
- **Fumadocs** — каркас документации, оглавления, сайдбары, MDX-роутинг.
- **Tailwind CSS** — только токены из `globals.css` (переменные design system), без произвольных hex-значений в JSX.
- **Sandpack** (`@codesandbox/sandpack-react`) — изолированные JS/HTML/CSS песочницы (загружаются только динамически!).
- **Framer Motion + Canvas API** — для интерактивных анимаций (движение пакетов по сети, работа конвейера процессора).
- **Zustand** — легкий клиентский стейт для геймификации, XP, ачивок и дерева навыков.
- **Orama** — встроенный в Fumadocs полнотекстовый поиск (route `app/api/search`), индексируется на сборке.
- **Vercel** — деплой и превью-стенды.

## ⚡ Главное правило тренажеров

Вся вычислительная математика, калькуляция подсетей, парсинг промптов и алгоритмы проверки ответов должны выноситься в `logic.ts`. Компонент `index.tsx` отвечать ТОЛЬКО за отображение и пользовательский ввод. `logic.ts` обязан быть на 100% покрыт тестами!

## ✍️ Контент: Правила написания MDX-лекций

Каждый файл лекции должен содержать строгий Frontmatter:

```yaml
---
title: "Адресация IPv4 и планирование сетей компании"
description: "Как рассчитывать IP-адреса, маски подсетей и делить сеть предприятия на отделы (VLSM)"
subject: computer-systems
order: 3
duration: 20
tags: [ipv4, подсети, vlsm, бизнес-инфраструктура]
---
```

Стандарты текста для БИжЭМ:

1. Язык общения: Живой, профессиональный, без академического сухостоя.
2. Бизнес-контекст: Каждая лекция объясняет зачем это экономисту/аналитику (например: "Почему задержка сети (latency) в 100мс снижает конверсию интернет-магазина на 7%").
3. Правило 3 экранов: Запрещено выводить более 3 экранов сплошного текста подряд без интерактивного элемента (`<Widget />`, `<MiniGame />`, `<Quiz />` или визуальной диаграммы).
   Для схем есть компонент `<Mermaid title="..." chart={...} />` (flowchart/sequenceDiagram; грузится динамически, тема и мобильная ширина поддержаны). Каждый процесс/структуру в лекции показывать схемой, а не только текстом. Практика обязана включать **граничные случаи** (пустой ввод, /31–/32, 29 февраля, NaN, переполнение и т.п.).
4. Объяснение терминов: Новый термин подсвечивается и раскрывается простой фразой прямо в месте появления.

## 🎮 Контракт Интерактивных Виджетов и Игр

Любой компонент в `components/widgets/` должен соответствовать критериям:

1. Автономность: Функция должна отрендериться `<SubnetCalculator />` без обязательных внешних пропсов (использовать дефолтные значения).
2. Мгновенная обучающая обратная связь (Actionable Feedback): При ошибке писать не просто «Неверно», а детально объяснять причину (например: «Маска /26 дает 62 доступных хоста, а в отделе продаж 70 ПК — сеть переполнена»).
3. Безупречная мобильная вёрстка (360px+): Интерактивные схемы и D&D (Drag-and-Drop) должны иметь дублирование обычной кнопкой или кликом для удобства на сенсорных экранах.
4. Уважение к системным настройкам: Поддержка dark/light тем и отключение анимаций при `prefers-reduced-motion`.
5. Безопасность SSR: Запрещено обращаться к `localStorage` во время первичного SSR-рендера (во избежание Hydration Mismatch). Использовать React hooks с флагом mounted или `useSyncExternalStore`.

## 🤖 Модуль работы с ИИ (Исключение по работе с сетью)

Виджет «Анализ и оценка промпта» отправляет данные на сервер:

* Сетевой ключ OpenAI/Claude хранить ИСКЛЮЧИТЕЛЬНО в `.env.local` и читать только в Route Handler (`app/api/prompt-review/route.ts`).
* Реализовать IP Rate-limiting и жесткое ограничение длины строки (max 1000 символов).
* При отсутствии интернета или ошибке API виджет обязан аккуратно переключаться на локальный чек-лист самопроверки.

## 📐 Дизайн-система

* Основной шрифт: `Nunito` (подключается через `next/font/google`).
* Стиль: Минималистичный, плоский, светлый интерфейс с высокой контрастностью текста.
* Цветовая гамма: Цвета определяются CSS-переменными из `globals.css`. Использование случайных Hex-значений в Tailwind-классах запрещено.
* Акценты: Каждая дисциплина имеет свой мягкий пастельный цветовой маркер в меню navigation и бейджах.
