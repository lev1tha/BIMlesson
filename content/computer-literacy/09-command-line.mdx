Чёрное окно, куда что-то печатают, — **командная строка** (терминал). Выглядит пугающе, но на деле
это просто другой способ отдавать компьютеру команды: не мышкой по кнопкам, а текстом. Бытовая
аналогия: графический интерфейс — меню с картинками в кафе, где вы тыкаете пальцем в готовые
позиции. Терминал — разговор с официантом, которому можно сказать «то же, что вчера, но без сахара,
и повторяйте каждый день в девять утра». Второй способ требует знать слова, зато умеет то, чего меню
не умеет в принципе.

<BusinessNote>
Посчитаем деньги. Аналитик бишкекской торговой сети получает из 1С 800 файлов-выгрузок, которые
нужно переименовать: вручную — секунды по три на файл, то есть 40 минут монотонной работы; одной
командой — 2 секунды. При зарплате 60 000 сом в месяц час работы стоит около 340 сом, значит одна
такая задача — это 220 сом, выброшенные на клики. А 5 часов подобной рутины в неделю за год съедают
порядка 88 000 сом на одного сотрудника. Терминал возвращает эти деньги — и вдобавок избавляет от
ожидания «когда IT-отдел освободится».
</BusinessNote>

## Что такое CLI и зачем он нужен

**CLI** (command-line interface, интерфейс командной строки) — программа, которая принимает
текстовые команды и выполняет их. Её плюсы:

- **Скорость.** Одна команда заменяет десяток кликов по папкам и кнопкам.
- **Массовость.** Скопировать 500 файлов по маске — одна строка, а не полчаса выделения мышкой.
- **Автоматизация.** Команды можно записать в скрипт и запускать по расписанию — хоть каждый вечер
  в 21:00 по бишкекскому времени.
- **Удалённые серверы.** У арендованного сервера за 2 000 сом в месяц нет «рабочего стола» —
  только терминал. Сайт компании, база данных, система аналитики живут именно там.
  Подключаются к такому серверу командой `ssh` (secure shell — защищённый удалённый доступ),
  например `ssh aigerim@shop.kg`, — и дальше все команды из этой лекции работают на нём
  точно так же, как на вашем ноутбуке.

Команда обычно выглядит так: `команда аргументы`. Например, `mkdir Отчёты` — «создай папку Отчёты».

## Как вообще открыть терминал

Лекции про «чёрное окно» бесполезны, пока вы не знаете, где это окно взять.

- **Windows:** правый клик по кнопке «Пуск» (или сочетание Win+X) → пункт «Терминал» или
  «Windows PowerShell». Либо нажмите Win, наберите «terminal» и Enter.
- **macOS:** Cmd+Пробел (поиск Spotlight), наберите «Терминал», Enter. Программа лежит
  в Программы → Утилиты.

Тут важная тонкость, о которой молчат многие инструкции: **на Windows живут три разные оболочки**,
и советы из интернета работают не во всех.

| Оболочка | Как отличить | Что это |
| --- | --- | --- |
| **cmd** | приглашение вида `C:\Users\aigerim>` | старая оболочка из 90-х: `copy`, `del`, `dir` |
| **PowerShell** | строка начинается с `PS` | современная оболочка Windows, понимает и свои команды, и многие Linux-подобные |
| **Git Bash** | приглашение оканчивается на `$` | «мини-Linux» для Windows, ставится вместе с Git |

На macOS и Linux оболочка одна семья — **bash/zsh** (приглашение оканчивается на `$` или `%`),
поэтому команды `ls`, `cp`, `rm` там работают всегда.

<Callout title="Почему «команда из интернета не работает»">
Самая частая причина — вы вставили рецепт для bash в окно cmd (или наоборот). Прежде чем печатать,
посмотрите на приглашение: `PS` — это PowerShell, `C:\...>` без PS — cmd, `$` — bash или zsh.
В этой лекции для каждой команды указано, где она работает.
</Callout>

## Анатомия команды: флаги и аргументы

Разберём команду на части:

```text
ls -l Отчёты
```

- `ls` — сама команда: «покажи содержимое папки»;
- `-l` — **флаг** (он же **опция**): уточнение к команде, начинается с дефиса;
- `Отчёты` — **аргумент**: над чем выполнять команду.

Флаг — как уточнение к заказу кофе: «без сахара», «навынос». Кофе тот же, детали другие:

| Команда | Что делает |
| --- | --- |
| `ls` | краткий список файлов |
| `ls -l` | подробный список: размер, дата изменения, права |
| `ls -a` | показать все файлы, включая скрытые (их имена начинаются с точки) |
| `ls -la` | флаги можно объединять: подробно и со скрытыми |

В cmd флаги пишутся через слэш: `dir /a` — показать скрытые файлы. Смысл тот же, синтаксис другой.

## Справка: как спросить у самой команды, что она умеет

Никто не держит флаги в голове. У каждой команды есть встроенная инструкция — как этикетка
с составом на упаковке: всегда при товаре, просто её редко читают.

| Где вы | Как спросить справку |
| --- | --- |
| macOS (zsh) | `man ls` — руководство (manual): листать пробелом, выйти клавишей q |
| Linux и Git Bash | `ls --help` — краткая справка сразу на экран |
| PowerShell | `Get-Help Copy-Item` |
| cmd | `dir /?` |

<Callout title="Профессиональный секрет">
Опытный пользователь терминала помнит наизусть примерно десять команд — остальное он
спрашивает у справки или ищет по фразе «как в bash сделать …». Умение прочитать `man`
ценнее зазубренных пятидесяти флагов: команды меняются, навык остаётся.
</Callout>

## Навигация по папкам

Вы всегда «находитесь» в какой-то папке (вспомните пути из урока про файлы). Команды перемещения:

| Задача | Mac/Linux (bash/zsh) | Windows (cmd) |
| --- | --- | --- |
| где я сейчас | `pwd` | `cd` без аргументов |
| показать содержимое | `ls` | `dir` |
| зайти в папку | `cd Отчёты` | `cd Отчёты` |
| подняться на уровень выше | `cd ..` | `cd ..` |
| в домашнюю папку | `cd ~` | `cd %USERPROFILE%` |

Символ `~` (тильда) — сокращение для домашней папки. Классический cmd его не понимает, а вот
PowerShell — понимает, как и многое другое из мира Linux.

## Работа с файлами: два словаря

Здесь Windows-студента чаще всего ждёт ловушка: команды `cp`, `mv`, `rm` — из мира Linux/macOS,
и в cmd их просто нет. Держите обе колонки:

| Задача | Mac/Linux (bash/zsh) | Windows (cmd) |
| --- | --- | --- |
| создать папку | `mkdir имя` | `mkdir имя` |
| скопировать | `cp что куда` | `copy что куда` |
| переместить | `mv что куда` | `move что куда` |
| переименовать | `mv старое новое` | `ren старое новое` |
| удалить файл | `rm файл` | `del файл` |
| показать содержимое файла | `cat файл` | `type файл` |

<Callout title="Хорошая новость про PowerShell">
PowerShell понимает `ls`, `cp`, `mv`, `rm`, `cat` как псевдонимы своих команд. Так что если вы
работаете в PowerShell (а не в старом cmd), большинство рецептов «для Linux» из этой лекции
заработают без перевода. Ещё одна причина открывать именно его.
</Callout>

<Callout title="Осторожно: rm не спрашивает и не кладёт в корзину">
Команда `rm` (и `del` в Windows) удаляет **сразу и навсегда**, мимо корзины. А `rm -rf папка`
удалит папку со всем содержимым без единого вопроса. В терминале нет кнопки «Отменить». Правило:
прежде чем удалять, командой `ls` убедитесь, что находитесь там, где думаете, и удаляете именно то,
что нужно. С мощью приходит ответственность.
</Callout>

## Пробелы и кавычки

Терминал разделяет команду на части по пробелам. Поэтому `cd Мои документы` он поймёт как «зайди
в папку Мои, а документы — это что-то лишнее» и выдаст ошибку. Имя с пробелом берут в кавычки:

```bash
cd "Мои документы"
```

Отсюда и привычка опытных пользователей называть рабочие файлы латиницей, без пробелов:
`sales-2026-03.csv` вместо `продажи за март (итог).csv`. Такое имя переживёт и терминал, и
загрузку на сервер, и отправку коллеге.

## Маски файлов: одна команда — сотни файлов

**Маска** (wildcard) — шаблон имени, где `*` означает «любые символы в любом количестве». Это
джокер в колоде: подходит вместо чего угодно. Примеры (bash/zsh и PowerShell):

```bash
cp *.csv arhiv/        # скопировать ВСЕ csv-файлы в папку arhiv
rm *.tmp               # удалить все временные файлы
ls sales-2026-03-*.csv # показать все мартовские выгрузки
```

Живой сценарий: у аналитика в папке 500 файлов вида `sales-bishkek-2026-01-15.csv` и
`sales-osh-2026-02-03.csv` — выгрузки по филиалам в Бишкеке и Оше за полгода. Нужно собрать всё
по Ошу в отдельную папку:

```bash
mkdir osh
cp sales-osh-*.csv osh/
```

Две строки — и готово. Мышкой это 10 минут выделения файлов по одному со скроллом и риском
пропустить парочку.

<Callout title="Маска плюс удаление — двойная осторожность">
Прежде чем выполнять `rm sales-osh-*.csv`, выполните `ls sales-osh-*.csv` с той же маской
и посмотрите на список: именно эти файлы будут удалены. Секунда проверки против часа
восстановления из бэкапа.
</Callout>

## Конвейер и перенаправление: соединяем команды

Обычно команда печатает результат на экран. Но вывод можно **перенаправить**:

- символ `>` — записать вывод в файл (старое содержимое затирается);
- двойной `>>` — дописать в конец файла;
- вертикальная черта (клавиша с ней находится над Enter) — **конвейер** (pipe): передать вывод
  одной команды на вход другой, как эстафетную палочку.

```bash
ls -l > inventar.txt        # список файлов — в файл, а не на экран
dir > inventar.txt          # то же самое в cmd
cat sales.csv | grep "Ош"   # показать только строки, где встречается «Ош»
```

Команда `grep` ищет строки по образцу (в cmd её роль играет `findstr`). Зачем это экономисту:
файл выгрузки на 120 000 строк Excel открывает полминуты и подвисает, а связка `cat` и `grep`
вытаскивает нужные строки за секунду. Перенаправление `>` — это готовая «выгрузка в файл»:
одной строкой вы получаете список всех документов папки для акта инвентаризации.

Ещё один соединитель — двойной амперсанд `&&`, логическое «И»: вторая команда запустится,
только если первая завершилась успешно.

```bash
mkdir arhiv && cp *.csv arhiv/   # копируем ТОЛЬКО если папка создалась
```

Это страховка для сценариев из нескольких шагов: если первый шаг провалился (нет прав, диск
полон), цепочка остановится, а не продолжит сыпать ошибки. Работает в bash/zsh и в cmd;
в PowerShell — начиная с 7-й версии.

## Файлы-гиганты: смотреть, не открывая

У Excel есть жёсткий потолок: **1 048 576 строк** на лист. Годовая выгрузка кассовых операций
торговой сети — 3–5 млн строк и пара гигабайт: Excel такой файл не откроет вовсе, а Блокнот
повиснет. Терминал читает файл потоком, как воду из крана — не пытаясь «поднять весь бак
разом», поэтому размер ему безразличен.

| Задача | bash/zsh (macOS, Linux, Git Bash) | PowerShell |
| --- | --- | --- |
| первые 5 строк | `head -n 5 sales.csv` | `Get-Content sales.csv -Head 5` |
| последние 20 строк | `tail -n 20 app.log` | `Get-Content app.log -Tail 20` |
| сколько всего строк | `wc -l sales.csv` | `(Get-Content sales.csv).Count` |

`head` — «голова» файла, `tail` — «хвост», `wc` (word count) с флагом `-l` (lines) считает
строки. Типовые сценарии аналитика:

- `head -n 5` — проверить структуру выгрузки: какие колонки, какой разделитель, есть ли заголовок;
- `wc -l` — сверить полноту: партнёр обещал 3,2 млн транзакций — в файле должно быть
  3 200 001 строка (плюс строка заголовка);
- `tail -n 50` — посмотреть свежие ошибки в логе сервера, не листая гигабайты старых;
- `head -n 1000 sales.csv > proba.csv` — вырезать образец в маленький файл, который уже
  спокойно открывается в Excel для черновой разведки.

<BusinessNote>
Финансовый партнёр прислал сверку — 2 ГБ, 3,2 млн операций. Вариант «мышкой»: просить
IT-отдел или покупать мощный ноутбук за 120 000 сом, и всё равно ждать. Вариант «терминал»:
`wc -l` отвечает за 3–4 секунды, `grep` вытаскивает операции одного филиала, `head` делает
образец для Excel. Ноль сом дополнительных затрат — и сверка, которая занимала полдня,
превращается в 15 минут.
</BusinessNote>

## Стоп-кран и спасательные клавиши

Терминал станет быстрым инструментом, когда рука запомнит четыре вещи:

| Клавиша | Что делает |
| --- | --- |
| **Tab** | дополняет имя файла или папки: наберите первые буквы и жмите Tab |
| **Стрелка вверх** | возвращает предыдущие команды — не печатайте одно и то же дважды |
| **Ctrl+C** | останавливает зависшую или бесконечную команду (стоп-кран) |
| `clear` (в cmd — `cls`) | очищает экран от старого вывода |
| `history` (в cmd и PowerShell — клавиша F7) | показывает список последних команд — удобно вспомнить вчерашний рецепт |

<Callout title="Автодополнение — не роскошь, а техника безопасности">
Tab не просто экономит время: он подставляет имя файла **без опечаток**. Опечатка в команде
просмотра — мелочь, а опечатка в команде удаления — потерянный файл. Привычка дополнять имена
Tab-ом защищает от обеих.
</Callout>

## Первый скрипт: автоматизация за пять минут

**Скрипт** — это обычный текстовый файл, в который записаны команды: терминал выполняет их сверху
вниз, как повар — рецепт. Вечерний бэкап отчётов для bash/zsh (файл `backup.sh`):

```bash
mkdir -p ~/backup
cp ~/Documents/reports/*.csv ~/backup/
echo "Бэкап готов"
```

То же самое для Windows (файл `backup.bat`, работает в cmd):

```bat
mkdir C:\backup
copy C:\Users\aigerim\Documents\reports\*.csv C:\backup\
echo Бэкап готов
```

Дальше скрипт ставят на расписание: в Windows — «Планировщик заданий» (Task Scheduler), в
macOS/Linux — `cron`. Строка в cron выглядит так:

```text
0 21 * * * /home/aigerim/backup.sh
```

Читается: «каждый день в 21:00 запусти backup.sh». Часовой пояс берётся системный — для нас это
Asia/Bishkek, UTC+6.

<BusinessNote>
Реальный масштаб: сеть из 12 магазинов в Бишкеке и Оше каждый вечер собирает кассовые выгрузки
в одну папку и копирует в резерв. Вручную это 20 минут работы администратора ежедневно — около
113 сом в день, 41 000 сом в год. Скрипт из трёх строк плюс планировщик делают то же самое
бесплатно, не забывают, не болеют и не увольняются. Именно с таких трёхстрочных скриптов
начинается вся автоматизация бизнеса.
</BusinessNote>

## Практика: 10 минут, после которых терминал перестанет пугать

Сделайте руками, сверяя каждый шаг с ожидаемым результатом. Команды даны для bash/zsh и
PowerShell; для cmd — в скобках.

1. Откройте терминал: macOS — Cmd+Пробел → «Терминал»; Windows — Win+X → «Терминал».
2. Наберите `pwd` (в cmd — `cd` без аргументов). **Ожидаемо:** путь вашей домашней папки,
   например `/Users/aigerim` или `C:\Users\aigerim`.
3. Выполните `mkdir praktika-cli`, затем `cd praktika-cli`, затем снова `pwd`.
   **Ожидаемо:** путь оканчивается на `praktika-cli`.
4. Создайте три файла — эти команды работают во всех оболочках:
   `echo 100 > report-jan.csv`, затем `echo 200 > report-feb.csv`, затем `echo test > notes.txt`.
5. Наберите `ls` (в cmd — `dir`). **Ожидаемо:** ровно три файла.
6. Выполните `mkdir arhiv`, затем `cp *.csv arhiv` (в cmd — `copy *.csv arhiv`). Проверьте:
   `ls arhiv` (в cmd — `dir arhiv`). **Ожидаемо:** два csv-файла; `notes.txt` не скопировался —
   маска отобрала только нужное.
7. Наберите `cat report-jan.csv` (в cmd — `type report-jan.csv`). **Ожидаемо:** на экране `100`.
8. Удалите заметку: `rm notes.txt` (в cmd — `del notes.txt`) и проверьте `ls`. **Ожидаемо:**
   файла нет — и в корзине его тоже нет, он удалён навсегда.
9. Выполните `ls > spisok.txt`, затем `cat spisok.txt`. **Ожидаемо:** список файлов лежит
   внутри файла — вы только что сделали свою первую «выгрузку в файл».
10. Посчитайте строки в этой выгрузке: `wc -l spisok.txt` (в PowerShell —
    `(Get-Content spisok.txt).Count`; в cmd этот шаг пропустите). **Ожидаемо:** 4 — две
    csv-выгрузки, папка `arhiv` и сам `spisok.txt`: файл создаётся ДО запуска `ls`,
    поэтому успевает попасть в собственный список. Такие мелкие сюрпризы — норма,
    привыкайте проверять результат глазами.
11. Потренируйте ускорители: наберите `cat rep` и нажмите Tab — имя допишется само; нажмите
    стрелку вверх — вернётся предыдущая команда; наберите `clear` (в cmd — `cls`) — экран чист.
12. Вернитесь домой: `cd ..` — и `pwd` снова показывает домашнюю папку.

**Самопроверка:** если на шаге 6 в `arhiv` оказалось три файла — вы скопировали без маски
(`cp * arhiv`); если на шаге 2 команда `pwd` не найдена в Windows — вы в cmd, а не в PowerShell
(это нормально, пользуйтесь колонкой для cmd); если на шаге 9 файл пустой — проверьте, что между
`ls` и именем файла стоит символ `>`.
