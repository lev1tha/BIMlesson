Flexbox отлично выстраивает элементы **в одну линию** (ряд или столбец). Но для настоящих **сеток**
— галерея товаров, дашборд из плиток, макет целой страницы — нужен инструмент, который управляет
строками **и** столбцами одновременно. Это **CSS Grid** («сетка»): вы описываете каркас из колонок
и строк, а браузер сам раскладывает по нему содержимое.

<BusinessNote>
Каталог товаров, витрина, дашборд с показателями — это всё сетки. Фрилансер в Бишкеке берёт за
вёрстку лендинга порядка 20 000–40 000 сом, а каждая правка «поехавшей» на телефоне сетки — ещё
1 000–2 000 сом в час работы. Grid собирает аккуратную адаптивную галерею буквально в три строки
CSS вместо десятков костылей. Для интернет-магазина уровня shop.kg это разница между «каталог готов
за день» и «неделя переделок» — то есть десятки тысяч сом бюджета. А помните из вводной лекции:
70% ваших посетителей придут с телефона, и сетка, которая не перестраивается под экран 360px,
теряет им деньги напрямую.
</BusinessNote>

## Grid или Flex?

Простое правило:

- **Flexbox** — одно измерение: ряд ИЛИ столбец. Меню, кнопки в ряд, шапка.
- **Grid** — два измерения сразу: строки И столбцы. Галереи, макеты, таблицы-плитки.

Их используют вместе, это не конкуренты:

| Задача | Инструмент |
| --- | --- |
| Меню из пяти ссылок в ряд | Flexbox |
| Галерея товаров 4 колонки на N строк | Grid |
| Карточка внутри сетки (иконка + текст + цена) | Flex внутри Grid |
| Макет страницы: шапка, сайдбар, контент, подвал | Grid (области) |

## Основы Grid

Сетка включается на контейнере `display: grid`, число и ширину столбцов задаёт
`grid-template-columns`, высоту строк — `grid-template-rows`:

```css
.grid {
  display: grid;
  grid-template-columns: 200px 200px 200px; /* три столбца по 200px */
  gap: 16px;                                /* зазор между ячейками */
}
```

Дети контейнера сами разложатся по ячейкам слева направо, перенося на новую строку. Никаких
дополнительных классов на самих карточках не нужно — в этом главное отличие от старых способов
вёрстки.

## Единица `fr` — доли свободного места

Жёсткие пиксели неудобны для адаптива. **`fr`** (от англ. *fraction* — «доля») делит свободное
место контейнера на части, как делят лепёшку на едоков:

```css
grid-template-columns: 1fr 1fr 1fr;  /* три равных столбца */
grid-template-columns: 2fr 1fr;      /* левый вдвое шире правого */
```

Посчитаем на числах. Контейнер шириной 1000px, колонки `2fr 1fr 1fr`, `gap: 20px`:

1. Два зазора съедают 40px, свободного места остаётся 960px.
2. Всего долей: 2 + 1 + 1 = 4, значит одна доля = 960 / 4 = **240px**.
3. Итог: колонки **480px, 240px и 240px**. Сузили окно до 700px — браузер пересчитает сам,
   пропорции 2:1:1 сохранятся.

А `repeat()` избавляет от повторов: `repeat(3, 1fr)` — то же, что `1fr 1fr 1fr`. Функция
`minmax(150px, 1fr)` задаёт коридор: «не уже 150px, но если есть место — растягивайся до доли».

<Callout title="Магия адаптивной галереи в одну строку">
`grid-template-columns: repeat(auto-fit, minmax(150px, 1fr))` — это «столько столбцов минимум по
150px, сколько влезет, а остаток места раздели поровну». На широком экране — 5 колонок, на телефоне
— 1–2, и всё это **без единого media-запроса**. Идеальный каталог товаров: вместо 30–40 строк CSS
с тремя брейкпоинтами — одна строка.
</Callout>

Попробуй сам — меняй `minmax`, число карточек и `gap`, тяни окно предпросмотра:

## auto-fit против auto-fill: в чём разница

В рецепте выше можно написать `auto-fit` или `auto-fill`, и пока карточек много — разницы не видно.
Она проявляется, когда карточек **мало**, а экран широкий:

- **`auto-fill`** («заполнить») размечает столько колонок, сколько влезло бы, — даже пустых.
  Три карточки на широком экране останутся узкими, справа — невидимые пустые дорожки.
- **`auto-fit`** («подогнать») схлопывает пустые колонки в ноль, и реальные карточки растягиваются
  на освободившееся место во всю ширину.

Для каталога магазина почти всегда хотят `auto-fit`: три оставшихся в наличии товара красиво займут
всю полку, а не сожмутся в левый угол. `auto-fill` берут, когда важно сохранить одинаковую ширину
ячеек — например, в календаре, где пустые дни всё равно занимают место.

Сравни вживую — в обеих сетках по 3 карточки, правило одно и то же, отличается одно слово:

## Линии сетки: у каждой ячейки есть адрес

Сетка размечена **нумерованными линиями** — невидимыми границами между колонками и строками.
Важно: у сетки из 3 колонок **4 вертикальные линии** (как у 3 секций забора 4 столба). Нумерация
идёт с единицы слева направо и сверху вниз.

Элемент можно «прибить» к линиям вручную:

```css
.hero  { grid-column: 1 / 3; }   /* от линии 1 до линии 3 = первые ДВЕ колонки */
.promo { grid-column: 2 / 4; }   /* вторая и третья колонки */
.wide  { grid-column: span 2; }  /* просто «займи 2 колонки», где стоишь */
.banner { grid-column: 1 / -1; } /* от первой до ПОСЛЕДНЕЙ линии: во всю ширину */
.tall  { grid-row: span 2; }     /* то же самое по вертикали: 2 строки */
```

Запись `1 / 3` читается «от линии 1 до линии 3», а не «колонки с 1-й по 3-ю» — это самая частая
ошибка новичка. Отрицательный номер считает с конца: `-1` — последняя линия, поэтому `1 / -1`
растягивает элемент на всю ширину при любом числе колонок — идеально для баннера распродажи.

## Явная и неявная сетка

Колонки и строки, которые вы описали в `grid-template-*`, — это **явная сетка**. Но если карточек
больше, чем ячеек, браузер молча создаёт новые строки — **неявную сетку**. По умолчанию их высота
`auto` (по содержимому), из-за чего строки получаются разнокалиберными.

Высоту авто-созданных строк задаёт `grid-auto-rows`:

```css
.dashboard {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(140px, 1fr));
  grid-auto-rows: 120px; /* КАЖДАЯ новая строка ровно 120px */
  gap: 12px;
}
```

Это секрет аккуратных дашбордов: сколько бы плиток ни добавилось, все строки одной высоты.

## grid-template-areas: макет страницы словами

Для каркаса целой страницы — шапка, сайдбар, контент, подвал — есть приём наглядней линий:
**именованные области**. Вы буквально «рисуете» макет текстом:

```css
.page {
  display: grid;
  grid-template-columns: 220px 1fr;
  grid-template-rows: auto 1fr auto;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
  min-height: 100vh;
  gap: 12px;
}
.page header { grid-area: header; }
.page aside  { grid-area: sidebar; }
.page main   { grid-area: main; }
.page footer { grid-area: footer; }
```

Каждая строка в кавычках — строка сетки, каждое слово — ячейка. Повторили слово дважды — область
растянулась на две колонки. Макет виден прямо в коде, как схема на салфетке.

<Callout title="Адаптив одной заменой">
Главный бонус областей: в media-запросе достаточно переписать одну «картинку», и весь макет
перестроится. Для телефона: `grid-template-areas: "header" "main" "sidebar" "footer"` и
`grid-template-columns: 1fr` — сайдбар уехал под контент, ни один элемент в HTML не тронут.
Именно так каталог shop.kg на мониторе показывает фильтры слева, а на телефоне — под товарами.
</Callout>

## Выравнивание внутри ячеек

По умолчанию элемент **растягивается** на всю ячейку (значение `stretch`). Если ячейка больше
содержимого — например, логотип 40px в ячейке 120px — нужно управлять положением:

| Свойство | Ось | Где ставится |
| --- | --- | --- |
| `justify-items` | горизонталь | на контейнере, для всех ячеек |
| `align-items` | вертикаль | на контейнере, для всех ячеек |
| `place-items` | обе сразу (сокращение) | на контейнере |
| `justify-self` / `align-self` | обе, но для одного элемента | на самом элементе |

Знаменитый рецепт идеального центрирования чего угодно — две строки:

```css
.center {
  display: grid;
  place-items: center; /* по горизонтали И вертикали */
}
```

Так центрируют экран загрузки, модальное окно, значение показателя в плитке дашборда. До Grid этот
трюк требовал позиционирования с `transform` и регулярно ломался.

## Дашборд из плиток: собираем всё вместе

Соберём мини-дашборд продаж: одна крупная плитка (итог по сети магазинов) через `grid-column: span 2`,
ровные строки через `grid-auto-rows`, центровка цифр через `place-items` — все инструменты лекции
в одном экране:

<Sandbox template="static" code={`<!doctype html>

<BusinessNote>
Почему аналитику это важно: такие плитки — стандартный вид любого BI-отчёта, от Power BI до
самописной админки. Умея читать Grid, вы за 15 минут поправите дашборд под себя (переставить
плитки, укрупнить ключевой показатель), не дожидаясь разработчика и не платя 2 000 сом в час
за правку из двух строк. Заметьте и контроль качества данных: 2 900 000 + 850 000 + 500 000 =
4 250 000 — плитки сходятся, а 4 250 000 / 1 240 заказов ≈ 3 430 сом среднего чека. Дашборд,
в котором плитки не сходятся, — первый признак сломанной выгрузки.
</BusinessNote>

## Практика: сделай руками и проверь себя

Задание 1 — **почувствуй minmax**. В первой песочнице (каталог) замени `minmax(120px, 1fr)` на
`minmax(240px, 1fr)`. Ожидаемо: колонок станет заметно меньше — карточкам запрещено сжиматься уже
240px. Теперь сузь окно предпросмотра до ширины телефона: должна остаться одна колонка, и ничего
не должно вылезать за край.

Задание 2 — **поймай разницу auto-fit / auto-fill**. Во второй песочнице удали по одной карточке
из каждой сетки, чтобы осталось по две. Ожидаемо: в верхней (`auto-fill`) карточки останутся узкими,
в нижней (`auto-fit`) — растянутся на всю ширину пополам.

Задание 3 — **растяни плитку по вертикали**. В дашборде, не меняя HTML, допиши прямо в CSS
правило `.tile:nth-child(2) { grid-row: span 2; }`. Ожидаемо: плитка Бишкека
станет вдвое выше (две строки по 110px плюс зазор), а остальные плитки перетекут вокруг неё —
сетка сама заполнит дыры.

Задание 4 — **посмотри на линии в DevTools**. Открой любой крупный сайт (или этот портал), нажми
F12 → вкладка Elements (Элементы), кликами по дереву найди элемент, у которого в стилях есть
`display: grid` — рядом с ним в дереве появится серый бейдж **grid**. Кликни по бейджу. Ожидаемо:
поверх страницы прорисуется сетка с пронумерованными линиями (1, 2, 3… и отрицательные с конца),
а зазоры `gap` заштрихуются. Это главный инструмент отладки сеток — так видно, к каким линиям
реально прибит каждый блок.
