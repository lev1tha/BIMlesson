Любой сайт — это три слоя: **HTML** задаёт содержимое и структуру (скелет), **CSS** — внешний вид
(одежда), а **JavaScript** — поведение (мышцы). Начнём с первых двух: их достаточно, чтобы собрать
настоящую страницу — лендинг кофейни, прайс-лист услуг или страницу-визитку для бизнеса.

<BusinessNote>
Понимание HTML/CSS — это способность самому поправить текст на лендинге, оценить работу подрядчика
и не платить за «поменять кнопку местами» как за ракету. Простой лендинг в Бишкеке фрилансеры делают
за 20 000–60 000 сом, а мелкая правка вроде «замените цену и номер телефона» у подрядчика стоит
1 000–2 000 сом и день ожидания. Зная основы, вы делаете такую правку за 10 минут сами. Для малого
бизнеса это десятки тысяч сом экономии в год — только на мелких правках, не считая умения читать
смету подрядчика и видеть, где вам продают час работы за десять.
</BusinessNote>

## HTML: страница из тегов

**Тег** — это команда разметки в угловых скобках. Обычно теги парные: открывающий и закрывающий,
а между ними — содержимое. Пара тегов + содержимое = **элемент**:

```html
<h1>Заголовок</h1>
<p>Это абзац текста.</p>
```

Здесь `<h1>` — заголовок, `<p>` — абзац. У тегов бывают **атрибуты** — дополнительные настройки
внутри открывающего тега. Например, у ссылки атрибут `href` задаёт адрес:

```html
<a href="https://coffee.kg">Открыть сайт кофейни</a>
```

В коде можно оставлять **комментарии** — заметки для людей, которые браузер полностью игнорирует
и на странице не показывает:

```html
<!-- Это комментарий: объясните здесь коллеге (или себе через месяц), зачем нужен блок ниже -->
```

Каждая страница имеет обязательный каркас:

```html
<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8" />
    <title>Моя страница</title>
  </head>
  <body>
    <!-- всё видимое содержимое здесь -->
    <h1>Привет!</h1>
  </body>
</html>
```

- `<!doctype html>` — первая строка, говорит браузеру «это современный HTML».
- `<head>` — служебная информация (кодировка, заголовок вкладки, подключение стилей). На странице
  не видна.
- `<body>` — всё, что видит пользователь.

Вот основные теги, которые покрывают 80% разметки:

| Тег | Зачем |
| --- | --- |
| `<h1>`…`<h6>` | заголовки, от главного к мелким |
| `<p>` | абзац текста |
| `<a href="...">` | ссылка |
| `<img src="..." alt="...">` | картинка (одиночный тег) |
| `<ul>` / `<ol>` / `<li>` | списки: маркированный / нумерованный / пункт |
| `<div>` | блок-контейнер (для группировки и раскладки) |
| `<span>` | строчный контейнер (кусочек текста) |
| `<button>` | кнопка |

## Теги-этажи: семантический каркас

`<div>` — безликая коробка: по коду не понять, шапка это, меню или подвал. Поэтому для крупных
частей страницы есть именные теги-ориентиры — их называют **семантическими** (то есть «несущими
смысл»):

| Тег | Роль на странице |
| --- | --- |
| `<header>` | шапка: логотип, название, меню |
| `<nav>` | блок навигации со ссылками |
| `<main>` | главное содержимое — ровно один на страницу |
| `<section>` | смысловой раздел внутри страницы («Меню», «Отзывы», «Контакты») |
| `<footer>` | подвал: адрес, контакты, копирайт |

Каркас типичного лендинга выглядит так:

```html
<body>
  <header>
    <nav>…ссылки меню…</nav>
  </header>
  <main>
    <section>…о нас…</section>
    <section>…цены…</section>
  </main>
  <footer>…контакты…</footer>
</body>
```

<Callout title="Семантика важнее, чем кажется">
Заголовок стоит помечать именно `<h1>`, а шапку — `<header>`, а не «просто крупным текстом в
диве». По этим тегам ориентируются поисковики (SEO) и программы экранного доступа для незрячих
(скринридеры): пользователь скринридера прыгает сразу к `<main>`, минуя меню. Правильная разметка —
это и доступность, и позиции в поиске. А позиции — деньги: первая строка выдачи Google собирает
порядка 28% кликов, десятая — около 2,5%.
</Callout>

Поменяй разметку в редакторе и посмотри, как меняется страница справа. Обрати внимание на
семантический каркас и на комментарий, которого нет на странице:

## CSS: оформление

**CSS** описывает, как элементы выглядят. Правило состоит из **селектора** (что оформляем) и
**объявлений** «свойство: значение»:

```css
/* комментарий в CSS пишется вот так */
p {
  color: gray;      /* цвет текста */
  font-size: 16px;  /* размер шрифта */
}
```

## Три способа подключить CSS

Стили сами по себе на страницу не попадают — их нужно подключить. Способов три:

| Способ | Как выглядит | Когда уместен |
| --- | --- | --- |
| Атрибут `style` прямо на теге | `style="color: red"` | точечный эксперимент, HTML-письма рассылок |
| Тег `<style>` внутри `<head>` | стили лежат в самой странице | одностраничка, учебные примеры |
| Внешний файл через `<link>` | отдельный файл `style.css` | боевые сайты — всегда так |

Как это выглядит в коде:

```html
<head>
  <!-- способ 2: стили внутри страницы -->
  <style>
    p { color: gray; }
  </style>

  <!-- способ 3: стили в отдельном файле style.css -->
  <link rel="stylesheet" href="style.css" />
</head>

<!-- способ 1: инлайн-стиль прямо на теге -->
<p style="color: red">Срочное объявление</p>
```

<Callout title="Почему в бою всегда внешний файл">
Во-первых, один файл обслуживает весь сайт: поправили цвет кнопки в `style.css` — он поменялся на
всех 50 страницах сразу. Во-вторых, браузер скачивает файл один раз и запоминает (кэширует):
файл стилей на 40 КБ загрузится при первом визите, а дальше все страницы будут открываться
быстрее — для мобильного интернета это заметно. Инлайн-стили же «прибиты гвоздями» к месту:
их нельзя переиспользовать, и они побеждают любой каскад — об этом ниже.
</Callout>

## Селекторы: кого красим

| Селектор | Что выбирает | Пример |
| --- | --- | --- |
| по тегу | все такие теги | `p { ... }` — все абзацы |
| по классу `.` | элементы с этим классом | `.btn { ... }` → `<a class="btn">` |
| по id `#` | один элемент с этим id | `#header { ... }` → `<div id="header">` |
| вложенный | элементы внутри других | `.card p { ... }` — абзацы внутри `.card` |

Чаще всего используют **классы** — они переиспользуемы: один класс `.btn` можно повесить на десять
кнопок. Идентификатор `id` должен быть уникальным на странице, его обычно оставляют для якорей
(ссылка `#menu` из песочницы выше) и JavaScript.

## Каскад: кто побеждает, если правила спорят

Первый же практический вопрос новичка: на один абзац действуют два правила с разными цветами —
каким он будет? Слово «каскад» в названии CSS (Cascading Style Sheets) как раз про это. Побеждает
более **специфичный** селектор. Упрощённая шкала веса:

```text
тег (1 очко)  меньше  класс (10 очков)  меньше  id (100 очков)  меньше  инлайн-style (1000 очков)
```

Пример. В HTML есть абзац с классом и id одновременно:

```html
<p class="warning" id="total">Итого: 4 500 сом</p>
```

```css
p       { color: gray; }    /* вес 1   */
.warning { color: orange; } /* вес 10  */
#total  { color: red; }     /* вес 100 */
```

Абзац будет **красным**: id тяжелее класса, класс тяжелее тега. Если же два правила весят
одинаково (например, два класса), побеждает то, что написано **ниже** в файле — последнее слово
остаётся за последним правилом.

Второй механизм — **наследование**: часть свойств «стекает» с родителя на детей. Задали
`font-family` и `color` на `body` — весь текст страницы их унаследовал. А вот `border`, `padding`
и `margin` не наследуются никогда: рамка вокруг `body` не означает рамку вокруг каждого абзаца.

<Callout title="Практическое правило и грабли !important">
Стройте оформление на классах — они дают ровную, предсказуемую специфичность. В CSS есть приписка
`!important`, которая перебивает вообще всё, но это как чинить дверь сваркой: следующему человеку
придётся перебивать её ещё одним `!important`, и стили превращаются в поле боя. В нормальном коде
она почти не встречается.
</Callout>

## Цвета: имена, hex и rgb

Цвет в CSS задаётся тремя основными способами:

| Формат | Пример | Что это |
| --- | --- | --- |
| имя | `red`, `white`, `gray` | ~140 готовых имён, удобно для черновиков |
| hex | `#2563eb` | три пары шестнадцатеричных цифр: красный, зелёный, синий |
| rgb | `rgb(37, 99, 235)` | те же три канала десятичными числами 0–255 |

Разберём `#2563eb` по косточкам: `25` — это 37 красного, `63` — 99 зелёного, `eb` — 235 синего.
Каждый канал принимает 256 значений, итого 256 × 256 × 256 = **16 777 216 оттенков**. Белый —
`#ffffff` (все каналы на максимум), чёрный — `#000000`. Одинаковые пары можно сокращать:
`#fff` — тот же белый. А `rgba(37, 99, 235, 0.5)` добавляет четвёртым числом прозрачность:
0.5 — полупрозрачный.

## Блочная модель: почему всё «толще», чем кажется

Каждый элемент на странице — это прямоугольная «коробка» из четырёх слоёв (изнутри наружу):

```text
┌─────────── margin (внешний отступ) ───────────┐
│  ┌──────── border (граница) ──────────────┐   │
│  │  ┌───── padding (внутренний отступ) ──┐ │   │
│  │  │        content (содержимое)        │ │   │
│  │  └────────────────────────────────────┘ │   │
│  └──────────────────────────────────────────┘   │
└──────────────────────────────────────────────────┘
```

- **content** — сам текст или картинка;
- **padding** — воздух внутри, между содержимым и границей;
- **border** — рамка;
- **margin** — отступ снаружи, между этой коробкой и соседями.

<Callout title="Частая путаница padding и margin">
`padding` — отступ **внутри** коробки (фон растягивается вместе с ним), `margin` — **снаружи**
(прозрачный зазор до соседей). Кнопка «дышит» за счёт padding; расстояние между двумя кнопками —
это margin.
</Callout>

Теперь посчитаем. Вот карточка товара:

```css
.card {
  width: 300px;
  padding: 16px;
  border: 2px solid gray;
  margin: 20px;
}
```

По умолчанию `width` задаёт ширину **только содержимого**, а padding и border прибавляются снаружи:

```text
300 (content) + 16×2 (padding слева и справа) + 2×2 (border) = 336 px видимой ширины
336 + 20×2 (margin) = 376 px занятого места в строке
```

Вы просили 300 — получили коробку на 376. Именно из-за этой арифметики у новичков «расползаются»
колонки: две карточки «по 50%» с padding уже не влезают в строку и падают одна под другую.

## box-sizing: border-box — арифметика становится честной

Свойство `box-sizing` меняет смысл `width`. Значение по умолчанию — `content-box` (та самая
арифметика с сюрпризом). Значение `border-box` включает padding и border **внутрь** заявленной
ширины:

```text
content-box:  width: 300px  →  видимая ширина 336 px (padding и border сверху)
border-box:   width: 300px  →  видимая ширина 300 px (содержимое ужалось до 264 px)
```

Поэтому практически каждый настоящий проект начинается со сброса:

```css
* {
  box-sizing: border-box; /* звёздочка = «для всех элементов» */
}
```

С ним колонка `width: 50%` с любым padding остаётся ровно половиной строки. Дальше в курсе (и в
любом чужом коде) этот сброс будет стоять молча — теперь вы знаете, что он делает.

## Блочные и строчные элементы: display

Почему `width: 200px` работает у `div`, но молча игнорируется у `span`? Потому что у элементов
разный **тип отображения** — свойство `display`:

| Тип | Кто по умолчанию | Поведение |
| --- | --- | --- |
| `block` | `div`, `p`, `h1`, `section` | занимает всю ширину строки, следующий элемент — с новой строки; width/height работают |
| `inline` | `span`, `a`, `strong` | стоит в потоке текста; width/height **игнорируются** |
| `inline-block` | задаётся вручную | стоит в строке, как inline, но размеры и отступы работают, как у block |

Классический пример — кнопка из ссылки: `<a>` по умолчанию строчный, и padding по вертикали ведёт
себя криво. Строка `display: inline-block` превращает ссылку в «кирпичик», которому можно задать
размеры, но который не занимает всю строку. Именно она стоит в классе `.btn` ниже.

Соберём всё вместе — HTML + CSS в одном файле. Здесь есть сброс `box-sizing`, каскад (общий цвет
задан на `body` и наследуется) и `inline-block` у кнопки. Меняй цвета, отступы, размеры:

<Sandbox template="static" code={`<!doctype html>
<html lang="ru">
  <head>
    <meta charset="utf-8" />
    <style>
      * { box-sizing: border-box; }
      body { font-family: sans-serif; padding: 24px; color: #222; }
      .card {
        width: 300px;
        border: 1px solid #ddd;
        border-radius: 12px;
        padding: 16px;
        margin-bottom: 12px;
      }
      .price { color: #16a34a; font-weight: bold; }
      .btn {
        display: inline-block;
        background: #2563eb;
        color: white;
        padding: 10px 16px;
        border-radius: 8px;
        text-decoration: none;
      }
    </style>
  </head>
  <body>
    <div class="card">
      <h2>Тариф «Старт»</h2>
      <p>Всё для первого сайта.</p>
      <p class="price">990 сом/мес</p>
      <a class="btn" href="#">Выбрать</a>
    </div>
  </body>
</html>`} />

## Практика: сделай руками и проверь себя

**Задание 1 — вторая карточка.** В песочнице выше добавь вторую карточку «Тариф „Бизнес“» за

второй карточки зелёной — добавь в CSS класс `.btn-green { background: #16a34a; }` и допиши его
ссылке: `class="btn btn-green"` (у элемента может быть несколько классов через пробел).
**Ожидаемый результат:** две карточки одинаковой ширины друг под другом, первая кнопка синяя,
вторая зелёная. Если обе позеленели — ты поменял сам `.btn`, а не добавил новый класс.

**Задание 2 — блочная модель в DevTools.** Открой любой сайт (хоть эту страницу), нажми F12 →
вкладка «Elements» («Элементы») → щёлкни по любому заголовку в дереве разметки. Внизу панели
Styles найди разноцветную схему коробки: синее — content, зелёное — padding, оранжевое — margin.
**Ожидаемый результат:** при наведении на схему соответствующий слой подсвечивается прямо на
странице, и видно реальные числа отступов. Бонус: двойной щелчок по значению в Styles позволяет
поменять его вживую — так верстальщики подбирают отступы, не трогая код (изменения живут до
перезагрузки страницы и видны только тебе).

**Задание 3 — мини-визитка.** Собери в песочнице ниже страницу-прайс для вымышленного бизнеса

- есть семантический каркас: `header`, `main`, `footer`;
- заголовок страницы — ровно один `h1`;
- прайс оформлен списком `ul`, цены в сомах;
- есть минимум один класс в CSS и кнопка-ссылка с `display: inline-block`;
- стоит сброс `box-sizing: border-box`.
