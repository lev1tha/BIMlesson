Почти вся работа программиста — и почти вся работа аналитика — это **обработка списков
данных**: строк из выгрузки CRM, товаров в заказе, платежей за месяц. Инструмент для списков —
**массив**, а умение его перебрать, отфильтровать и отсортировать — это и есть «алгоритмы»
на старте.

<BusinessNote>
Представьте выгрузку из CRM бишкекского интернет-магазина: 12 000 строк заказов за квартал.
Задача «найти все заказы дороже 5 000 сом и посчитать их сумму» вручную в Excel — минут сорок
с перепроверкой. Кодом — три строки: `filter`, `reduce`, `console.log`, и ответ через две
секунды. При зарплате аналитика 60 000 сом в месяц час его работы стоит примерно 340 сом —
каждый отчёт, переведённый со «вручную» на «скриптом», возвращает компании живые деньги.
Эта лекция — ровно тот набор приёмов.
</BusinessNote>

## Массивы: списки по порядку

**Массив** — это упорядоченный список значений в квадратных скобках. У каждого элемента есть
**индекс** — его номер, и — важно — **нумерация начинается с нуля**:

```js
const города = ['Бишкек', 'Ош', 'Каракол'];

города[0];        // 'Бишкек'  — первый элемент, индекс 0
города[2];        // 'Каракол' — третий элемент, индекс 2
города.length;    // 3         — сколько элементов
города[города.length - 1]; // 'Каракол' — последний
```

<Callout title="Ловушка индекса с нуля">
В массиве из 3 элементов индексы — 0, 1 и 2, а элемента с индексом 3 **нет** (будет `undefined`).
Самая частая ошибка новичка — «уехать» на один за край. Последний индекс всегда `length - 1`.
</Callout>

### Добавить и убрать: push, pop, shift, unshift

У массива четыре «двери» — по две с каждого конца:

| Метод | Что делает | Пример на `['Айбек', 'Бермет']` |
| --- | --- | --- |
| `push(x)` | добавляет **в конец** | → `['Айбек', 'Бермет', 'Чолпон']` |
| `pop()` | убирает **с конца** | → `['Айбек']` |
| `unshift(x)` | добавляет **в начало** | → `['VIP', 'Айбек', 'Бермет']` |
| `shift()` | убирает **из начала** | → `['Бермет']` |

Бытовая аналогия: `push`/`pop` — стопка тарелок (кладём сверху и берём сверху), а
`shift`/`unshift` — очередь в кассу (новые встают в конец, обслуживают первого).

```js
const очередь = [];
очередь.push('Айбек');    // ['Айбек']
очередь.push('Бермет');   // ['Айбек', 'Бермет']
очередь.shift();          // обслужили 'Айбека' → ['Бермет']
```

Нюанс на будущее: на массиве в 100 000 элементов `shift` заметно медленнее `pop` — при
удалении из начала все остальные элементы приходится сдвинуть на одну позицию влево.
Для маленьких списков разницы нет, для больших выгрузок — есть.

## Найти элемент: includes и indexOf

Самая частая операция со списком — «а есть ли тут такой элемент?». Для этого два метода:

- `includes(x)` — отвечает просто «да/нет» (`true`/`false`). Как список гостей на входе:
  есть в списке — проходи.
- `indexOf(x)` — отвечает, **на каком месте** элемент, а если его нет — возвращает `-1`.
  Как номер в очереди: «вы третий» или «вас тут нет».

```js
const стопСписок = ['0700123456', '0555000111'];

стопСписок.includes('0700123456'); // true  — номер в чёрном списке
стопСписок.includes('0222333444'); // false — можно звонить
стопСписок.indexOf('0555000111');  // 1     — второй элемент
стопСписок.indexOf('0999888777');  // -1    — не найден
```

<Callout title="Ловушка indexOf и минус единицы">
«Не найдено» — это `-1`, а не `0` и не `undefined`. Проверка `if (список.indexOf(x))`
работает **неправильно**: для элемента на позиции 0 условие окажется ложным (ноль — «ложь»),
и код решит, что элемента нет, хотя он первый в списке. Правильно: либо
`indexOf(x) !== -1`, либо просто `includes(x)` — он для того и придуман.
</Callout>

## Перебор: пройти по всем элементам

Чтобы что-то сделать с каждым элементом, массив **перебирают** циклом. Когда индекс не важен —
удобнее `for...of`:

```js
let сумма = 0;
for (const число of [10, 20, 30]) {
  сумма = сумма + число;   // накопитель
}
// сумма === 60
```

Когда индекс нужен (например, «каждый второй»), берут обычный `for`:

```js
const arr = ['a', 'b', 'c'];
for (let i = 0; i < arr.length; i = i + 1) {
  console.log(i, arr[i]);  // 0 'a', 1 'b', 2 'c'
}
```

## Три метода, которые заменяют половину циклов

У массивов есть готовые методы. Их стоит выучить — они делают код короче и понятнее:

| Метод | Что делает | Пример |
| --- | --- | --- |
| `map` | превращает каждый элемент → **новый массив той же длины** | `[1,2,3].map(x => x * 2)` → `[2,4,6]` |
| `filter` | оставляет только подходящие → **массив короче или равен** | `[1,2,3,4].filter(x => x % 2 === 0)` → `[2,4]` |
| `reduce` | «сворачивает» весь массив → **одно значение** | `[1,2,3].reduce((s, x) => s + x, 0)` → `6` |

Их можно соединять в **цепочку** — как конвейер на производстве: каждый метод берёт результат
предыдущего. «Возьми заказы → оставь только дорогие → примени скидку → посчитай сумму» —
это буквально `заказы.filter(...).map(...).reduce(...)`.

Поиграй в песочнице — поменяй числа и условия:

  .reduce((s, p) => s + p, 0);

console.log('Дорогие:', дорогие);
console.log('Итого:', итого, 'сом');
console.log('Средний чек:', среднийЧек, 'сом');

## Срез и копия: slice и spread

`slice(от, до)` вырезает **кусок** массива, не трогая оригинал. Индекс «до» не включается.
Отрицательный индекс — отсчёт с конца:

```js
const заказы = [12500, 8900, 7400, 5100, 3300, 1200]; // сом, по убыванию

заказы.slice(0, 3);  // [12500, 8900, 7400] — топ-3 заказа
заказы.slice(-2);    // [3300, 1200]        — два самых мелких
заказы.slice();      // полная копия всего массива
```

Второй способ сделать копию — **spread** (читается «спред», значок из трёх точек):
`[...arr]` «рассыпает» элементы в новый массив. Бытовая аналогия: `slice()` и `[...arr]` —
это ксерокопия документа. Правки на копии оригинал не портят. А вот `const b = a` — это
**не копия**: это второй ярлык на тот же документ, о чём следующий раздел.

## Мутация: главный подводный камень

**Мутация** — это изменение массива «на месте», без создания нового. Часть методов мутирует
исходник, часть — возвращает новый массив и оригинал не трогает:

| Меняют исходный массив (мутируют) | Возвращают новый, исходник цел |
| --- | --- |
| `push`, `pop`, `shift`, `unshift` | `map`, `filter` |
| `sort`, `reverse` | `slice`, `concat`, `[...arr]` |

Почему это важно: если отсортировать «сырую» выгрузку методом `sort` напрямую, исходный
порядок строк **потерян навсегда** — а он мог быть хронологией платежей. И да, `const` не
спасает: `const` запрещает переприсвоить **имя** переменной, но не запрещает менять
**содержимое** массива. Проверь сам:

<Sandbox code={`const продажи = [4200, 900, 15000, 2500]; // хронология платежей, сом

// ОПАСНО: sort меняет исходный массив
const поВозрастанию = продажи.sort((a, b) => a - b);
console.log('Исходник тоже изменился:', продажи);

// БЕЗОПАСНО: сначала копия, потом сортировка
const данные = [4200, 900, 15000, 2500];
const копия = [...данные].sort((a, b) => a - b);
console.log('Копия отсортирована:', копия);
console.log('Исходник цел:', данные);
`} />

<Callout title="Правило гигиены данных">
Исходную выгрузку не мутируем никогда. Хочешь сортировать, переворачивать, чистить —
сначала копия (`slice()` или `[...arr]`), потом любые операции. Это же правило спасёт
в React и при работе с общими данными в команде.
</Callout>

## Сортировка: sort и его знаменитая ловушка

`sort()` без аргументов сортирует элементы **как строки**, по алфавиту. Для слов это
нормально, для чисел — катастрофа:

```js
['Ош', 'Бишкек', 'Каракол'].sort(); // ['Бишкек', 'Каракол', 'Ош'] — ок

[10, 9, 1].sort();                  // [1, 10, 9]  — !!!
```

Почему `10` встал раньше `9`? Числа превратились в строки `'10'` и `'9'`, а строки
сравниваются посимвольно: первый символ `'1'` меньше `'9'` — значит, `'10'` «меньше».
Так `100` в отчёте оказывается раньше `25`, и топ продаж превращается в кашу.

Лечение — **компаратор**: функция двух аргументов, которая говорит sort, как сравнивать.
Отрицательный результат — «a раньше b», положительный — «b раньше a»:

```js
[10, 9, 1].sort((a, b) => a - b);  // [1, 9, 10]  — по возрастанию
[10, 9, 1].sort((a, b) => b - a);  // [10, 9, 1]  — по убыванию
```

Тот же приём сортирует **массив объектов** по любому полю — а это уже настоящая работа
аналитика:

```js
const клиенты = [
  { имя: 'Айбек',  сумма: 12000 },
  { имя: 'Бермет', сумма: 45000 },
  { имя: 'Чолпон', сумма: 8000 },
];

клиенты.sort((a, b) => b.сумма - a.сумма);
// Бермет (45 000) → Айбек (12 000) → Чолпон (8 000)
```

<BusinessNote>
«Топ-10 клиентов по выручке за квартал» — это `[...клиенты].sort((a, b) => b.сумма - a.сумма).slice(0, 10)`.
Одна строка кода. В компании с оборотом 2 млн сом в месяц на этих десяти клиентах обычно
висит 60–70% выручки — и менеджер, который получает такой список каждое утро автоматически,
а не раз в квартал от аналитика, реагирует на отток топ-клиента за дни, а не за месяцы.
</BusinessNote>

## Строки: тоже последовательность

Строка похожа на массив символов: у неё есть `length` и доступ по индексу. А ещё — полезные
методы:

```js
const s = 'привет';
s.length;            // 6
s[0];                // 'п'
s.toUpperCase();     // 'ПРИВЕТ'
s.split('');         // ['п','р','и','в','е','т']  — в массив символов
['п','р','и'].join(''); // 'при'                    — обратно в строку
```

<Callout title="split и join — мостик между строкой и массивом">
Часто задачу со строкой проще решить, если превратить её в массив (`split`), поработать методами
массива, а потом собрать обратно (`join`). Например, перевернуть строку: split → reverse → join.
</Callout>

### Чистка данных: trim, replace, includes, toLowerCase

Реальные данные всегда грязные: лишние пробелы, разный регистр, разные разделители.
Четыре метода решают 90% таких проблем:

```js
'  Бишкек  '.trim();               // 'Бишкек' — убрали пробелы по краям
'АЙГУЛЬ'.toLowerCase();            // 'айгуль' — единый регистр
'чек: 1500 сом'.includes('сом');   // true    — есть ли подстрока
'0700-12-34-56'.replace('-', '');  // '070012-34-56' — заменился ТОЛЬКО первый
'0700-12-34-56'.replaceAll('-', ''); // '0700123456' — заменились все
```

Обрати внимание на капкан: `replace` меняет только **первое** вхождение. Чтобы заменить
все — `replaceAll`. А связка `trim().toLowerCase()` — стандартный приём «нормализации»
перед сравнением: `'  Айгуль '` и `'АЙГУЛЬ'` после неё становятся одинаковой строкой
`'айгуль'`.

<BusinessNote>
В CRM магазина 3 200 клиентов, из них 214 — «призраки»: один и тот же человек записан как
«Айгуль», « айгуль» и «АЙГУЛЬ ». Отчёт по уникальным клиентам завышен на 7%, маркетинг
планирует бюджет рассылки от неверной цифры, а сама Айгуль получает три одинаковых SMS
и жалуется. Нормализация строк перед подсчётом — две строки кода — возвращает отчёту
честность.
</BusinessNote>

## Граничные случаи: где всё ломается

- **Пустой массив в reduce без начального значения.** `[].reduce((s, x) => s + x)` бросает
  ошибку `TypeError: Reduce of empty array with no initial value`. Почему: без стартового
  значения reduce пытается взять первый элемент за накопитель, а брать нечего. Как правильно:
  всегда передавай второй аргумент — `[].reduce((s, x) => s + x, 0)` вернёт `0`, а не упадёт.

- **Индекс за границей массива.** `['a','b','c'][10]` не бросает ошибку и не возвращает
  `null` — возвращает `undefined`. Почему: обращение по индексу в JS просто читает
  несуществующее свойство объекта-массива. Как правильно: перед использованием элемента
  проверяй `if (arr[i] !== undefined)` или сравнивай индекс с `arr.length`.

- **`sort` на массиве из одного элемента или пустом.** `[].sort()` и `[5].sort()` не ломаются
  и возвращают тот же массив — но это ложное чувство безопасности: баг с сортировкой чисел
  как строк на таких массивах просто не проявляется, потому что сравнивать нечего. Как
  правильно: тестировать сортировку минимум на 2–3 элементах, иначе капкан `[10, 9, 1].sort()`
  останется незамеченным до продакшена.

- **`indexOf` и `includes` со строкой, а не с числом.** `[10, 20, 30].indexOf('20')` вернёт
  `-1`, хотя число 20 в массиве есть. Почему: `indexOf` сравнивает строго (`===`), а строка
  `'20'` и число `20` — разные типы. Как правильно: следи, чтобы тип искомого значения совпадал
  с типом элементов массива, особенно если число пришло из `input` формы (там оно всегда строка).
