Программирование — это умение объяснить компьютеру, что делать, на понятном ему языке. Мы возьмём
**JavaScript**: на нём работают все сайты, серверы (через Node.js) и куча автоматизации. И это один
из самых дружелюбных языков для старта.

<BusinessNote>
Аналитик, который умеет написать даже простой скрипт, перестаёт делать руками то, что можно
автоматизировать. Посчитаем в деньгах: младший аналитик в Бишкеке зарабатывает порядка 45 000 сом
в месяц — примерно 280 сом за рабочий час. Если ручная сборка еженедельного отчёта из выгрузки
занимает 3 часа, за год набегает около 150 часов и 42 000 сом, потраченных на копирование ячеек.
Скрипт, написанный за один вечер, делает ту же сборку за 20 секунд. Один вечер против полутора
рабочих месяцев в год — вот цена этой лекции.
</BusinessNote>

## Как компьютер выполняет код

Программа — это список команд. Компьютер (точнее, **интерпретатор** JavaScript — программа, которая
читает и тут же выполняет твой код) идёт по командам **сверху вниз, строку за строкой**, и выполняет
их по очереди. Самая частая команда для начала — `console.log(...)`: она выводит значение в
**консоль** (окно вывода).

## Где запускать JavaScript у себя

Песочница в лекции удобна, но JavaScript живёт не только здесь. Есть два «дома», и оба у тебя уже
почти есть.

**Способ 1: консоль браузера.** В каждый браузер встроен полноценный движок JavaScript и консоль
для команд. Сделай прямо сейчас, это две минуты:

1. Открой любую страницу и нажми **F12** (на macOS — Cmd+Option+J, на Windows подойдёт и
   Ctrl+Shift+J). Откроется панель инструментов разработчика.
2. Перейди на вкладку **Console**.
3. Набери `250 * 12` и нажми Enter — консоль ответит `3000`. Ты только что посчитал годовую
   стоимость подписки по 250 сом в месяц.
4. Набери `'Бишкек'.length` — получишь `6`: у любой строки есть встроенное свойство «длина».
5. Набери `const price = 990`, Enter, затем `price * 3` — увидишь `2970`. Переменные в консоли
   живут до перезагрузки страницы.

Если все три числа совпали — поздравляю, ты уже выполнял JavaScript без всяких песочниц.

**Способ 2: Node.js.** Это тот же движок JavaScript (V8 из Chrome), «вынутый» из браузера и
превращённый в отдельную программу. Благодаря Node на JavaScript пишут серверы, боты и скрипты
автоматизации — весь наш предмет держится на нём. Проверить у себя:

1. Скачай установщик с nodejs.org (бери версию с пометкой LTS — «долгая поддержка») и установи.
2. Открой терминал и набери `node -v` — в ответ придёт номер версии, например `v22.11.0`.
3. Создай файл `hello.js` со строкой `console.log('Салам, Бишкек!');`
4. Выполни `node hello.js` — терминал напечатает приветствие. Это твоя первая программа вне
   браузера.

<Callout title="Браузер и Node — два дома одного языка">
В браузере JavaScript двигает интерфейс: реагирует на клики, перерисовывает страницу. В Node тот же
язык читает файлы, отвечает на сетевые запросы, гоняет расчёты. Синтаксис одинаковый, различается
окружение: в браузере нет доступа к файлам на диске, в Node нет кнопок и страниц.
</Callout>

## Комментарии: заметки для людей

**Комментарий** — кусочек текста в коде, который интерпретатор полностью игнорирует. Он нужен не
компьютеру, а людям: тебе-через-месяц и коллегам. Два вида:

```js
// однострочный: всё после двух косых черт и до конца строки

/* многострочный:
   всё между этими «скобками со звёздочками»,
   хоть на десять строк */

const vatRate = 0.12; // НДС в Кыргызстане — 12%, поэтому 0.12
```

Правило хорошего тона: комментарий объясняет **зачем**, а не пересказывает **что**. Написать
`// прибавляем единицу` над строкой с прибавлением единицы — бесполезно. Написать
`// цены приходят в тыйынах, переводим в сомы` — ценно: этого из самого кода не видно.

<Callout title="Комментарий как выключатель">
Поставь `//` в начале строки — и строка перестанет выполняться. Так временно «выключают» кусок кода
при поиске ошибки. В редакторах и песочницах есть горячая клавиша Ctrl+/ (Cmd+/ на macOS) — она
комментирует выделенные строки одним нажатием.
</Callout>

## Переменные: коробки с ярлыками

**Переменная** — это именованная «коробка», в которой хранится значение. Создают её словом `let`
(значение можно менять) или `const` (значение менять нельзя — «константа»):

```js
let score = 10;       // коробка «score», внутри 10
score = 15;           // можно поменять — теперь 15

const vatRate = 0.12; // константа: попытка изменить вызовет ошибку
```

<Callout title="let или const — что выбрать">
Правило простое: **по умолчанию бери `const`**. Так ты защищаешь себя от случайного изменения
значения. И только если точно знаешь, что переменная будет меняться (например, счётчик в цикле), —
бери `let`. Старое слово `var` сегодня не используют.
</Callout>

### Как называть переменные

JavaScript формально разрешает почти любые имена — даже кириллицей. Но в реальных проектах весь код
пишут **латиницей** в стиле **camelCase** («верблюжья запись»): первое слово с маленькой буквы,
каждое следующее — с большой, как горбы у верблюда.

| Имя | Годится? | Почему |
| --- | --- | --- |
| `totalPriceSom` | да | camelCase, имя честно говорит, что внутри |
| `total_price_som` | нет | это snake_case из мира Python; в JS так не принято |
| `цена` | работает, но нет | кириллица допустима технически, но в командах и библиотеках весь код на латинице |
| `x`, `d2` | нет | имя не отвечает на вопрос «что внутри» |
| `Price` рядом с `price` | опасно | JS различает регистр: это две **разные** переменные |

Хорошее имя — маленькая инвестиция: через месяц ты откроешь свой скрипт и по `revenuePerDay`
поймёшь всё без чтения кода, а по `r1` — ничего.

## Типы данных: что вообще можно хранить

У каждого значения есть **тип** — вид данных. Вот основные, которые нужны с первого дня:

| Тип | Что хранит | Пример |
| --- | --- | --- |
| number | числа, целые и дробные | `42`, `3.14`, `-7` |
| string | текст (обязательно в кавычках) | `'привет'`, `"Бишкек"` |
| boolean | «да / нет» | `true`, `false` |
| array | список значений по порядку | `[1, 2, 3]` |
| object | набор «ключ: значение» | `{ name: 'Айдай', age: 20 }` |
| undefined | «значение не задано» | `let x;` → x равен undefined |
| null | «намеренно пусто» | `let y = null;` |

<Callout title="Частая ловушка: строки и числа">
`5 + 5` даст `10`, а `'5' + '5'` даст `'55'` — потому что для строк `+` это склейка (конкатенация),
а не сложение. Если число пришло как строка (например, из поля ввода), его сначала превращают в
число: `Number('5') + 5` уже даёт `10`.
</Callout>

## Арифметика: шесть операторов на каждый день

**Оператор** — значок действия над значениями. Арифметических в JavaScript шесть, и знать нужно
все:

| Оператор | Что делает | Пример | Результат |
| --- | --- | --- | --- |
| `+` | сложение | `7 + 3` | `10` |
| `-` | вычитание | `7 - 3` | `4` |
| `*` | умножение | `250 * 4` | `1000` |
| `/` | деление | `10 / 4` | `2.5` |
| `%` | остаток от деления | `10 % 4` | `2` |
| `**` | возведение в степень | `2 ** 10` | `1024` |

Два последних — самые недооценённые, разберём на деньгах.

**Остаток `%`** отвечает на вопрос «что не поместилось в целые части». На складе 158 коробок сока,
в машину входит 12: `Math.floor(158 / 12)` даёт `13` полных рейсов (Math.floor — округление вниз),
а `158 % 12` даёт `2` — столько коробок останется на последний недогруженный рейс. Ещё `%`
проверяет чётность: `n % 2` равно `0` только у чётных чисел. А в финансах он разбирает тыйыны:
сумма `1250` тыйынов — это `Math.floor(1250 / 100)` = `12` сом и `1250 % 100` = `50` тыйынов.

**Степень `**`** — это сложный процент одной строкой. Депозит 100 000 сом под 12% годовых с
капитализацией на 3 года: `100000 * 1.12 ** 3` — примерно 140 493 сома (точнее, 140 492.8). Никаких
таблиц: одна формула вместо трёх умножений подряд.

Порядок действий — как в школе: сначала степень, потом умножение и деление, потом сложение.
`2 + 3 * 4` даст `14`, а скобки всё меняют: `(2 + 3) * 4` даст `20`. Сомневаешься — ставь скобки,
они бесплатные.

И удобное сокращение: вместо `total = total + 500` пишут `total += 500` («увеличь на 500»).
Аналогично работают `-=`, `*=`, `/=`.

<Callout title="Осторожно: дробные деньги">
Набери в консоли `0.1 + 0.2` — получишь `0.30000000000000004`. Это не баг JavaScript, а свойство
двоичных дробей в любом языке. Почему так и как правильно считать деньги (спойлер: в тыйынах,
целыми числами) — отдельная лекция 12 про числа, деньги и даты.
</Callout>

## Шаблонные строки: текст с подстановками

Склеивать текст и переменные плюсами неудобно: легко потерять пробел, а длинные фразы превращаются
в частокол кавычек. Поэтому в JS есть **шаблонные строки** (template strings) — текст в **обратных
кавычках** (клавиша слева от цифры 1, там же, где буква Ё), внутрь которого можно вставлять любые
выражения через знак доллара и фигурные скобки:

```js
const name = 'Данияр';
const total = 2500;

// старый способ — склейка плюсами (легко потерять пробел):
console.log('Клиент ' + name + ' оплатил ' + total + ' сом');

// шаблонная строка — читается как обычный текст:
console.log(`Клиент ${name} оплатил ${total} сом`);

// внутри подстановки можно считать:
console.log(`Три таких заказа: ${total * 3} сом`);
```

Обе первые строки печатают одно и то же: `Клиент Данияр оплатил 2500 сом`. Третья — `Три таких
заказа: 7500 сом`. Бонус: шаблонная строка может занимать несколько строк текста без всяких
ухищрений — обычным кавычкам такое запрещено.

## Функции: главный инструмент программиста

**Функция** — это кусочек кода, которому дали имя, чтобы вызывать его сколько угодно раз. Она
принимает **входные данные** (аргументы), что-то с ними делает и **возвращает результат** словом
`return`.

<Callout title="Аналогия: кофемашина">
Функция — как кофемашина: на вход даёшь воду и зёрна (аргументы), внутри происходит процесс, на
выходе получаешь кофе (`return`). Тебе не нужно знать, что там внутри, — достаточно знать, что дать
и что получишь. Один раз «собрал» — пользуешься тысячу раз.
</Callout>

Синтаксис такой:

```js
function functionName(param1, param2) {
  // тело функции — что делаем с параметрами
  return result;    // что отдаём наружу
}

// вызов:
functionName(value1, value2);
```

Поменяй код в песочнице и посмотри, как функция считает площадь для разных чисел:

<Sandbox code={`function area(width, height) {
  return width * height;
}

console.log('Площадь 3 x 4:', area(3, 4));
console.log('Площадь 5 x 5:', area(5, 5));
console.log('Площадь 10 x 2:', area(10, 2));`} />

<Callout title="Важно: return не то же самое, что console.log">
`console.log` просто **печатает** значение на экран — и всё. `return` **возвращает** значение
обратно в программу, чтобы им можно было пользоваться дальше (сложить, сравнить, передать в другую
функцию). Задачи проверяются именно по тому, что функция **возвращает**, а не печатает. Забыл
`return` — функция вернёт `undefined`, и тест не пройдёт.
</Callout>

## Чуть-чуть условий и циклов — они пригодятся

**Условие** `if` выполняет код, только если проверка истинна:

```js
if (age >= 18) {
  console.log('совершеннолетний');
} else {
  console.log('нет');
}
```

**Цикл** повторяет действие много раз. Чтобы пройти по всем элементам массива, удобен `for...of`:

```js
let sum = 0;
for (const n of [10, 20, 30]) {
  sum += n;   // накопитель: то самое сокращение «увеличь на n»
}
// sum теперь 60
```

<Callout title="Ещё короче: reduce">
У массивов есть готовый метод `reduce`, который «сворачивает» список в одно значение. Сумма в одну
строку: `[10, 20, 30].reduce((sum, n) => sum + n, 0)`. Оба способа — цикл и reduce — правильные;
выбирай, что понятнее.
</Callout>

выкатить новую версию сайта или расчёта зарплаты, автоматика прогоняет сотни таких проверок — и
если хоть одна упала, релиз не выходит. Это дешевле, чем ловить ошибку уже на живых клиентах:
один неверный расчёт скидки в интернет-магазине с оборотом 500 000 сом в день стоит дороже, чем
месяц работы над тестами.
</BusinessNote>
