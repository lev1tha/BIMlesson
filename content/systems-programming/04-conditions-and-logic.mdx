## Введение

Пока наши программы шли строго сверху вниз. Но настоящая сила — в **решениях**: «если оплата
прошла — покажи чек, иначе — ошибку». За это отвечают **условия** — развилки, на которых программа
выбирает, по какой дороге пойти дальше. Как навигатор на перекрёстке: «если пробка на Чуй —
поворачиваем на Боконбаева».

<BusinessNote>
Любое бизнес-правило — это условие: «скидка, если сумма больше 5 000 сом», «блокировать заказ, если
товар кончился», «звать менеджера, если клиент VIP». Кто умеет описать правило кодом — тот
автоматизирует проверки, которые иначе делаются руками и с ошибками. Цена ошибки в условии вполне
конкретна: бишкекский интернет-магазин с 2 000 заказов в месяц однажды перепутал оператор в правиле
скидок — и каждый заказ получал лишние 300 сом скидки. Это 600 000 сом убытка в месяц из-за одной
строчки. В конце лекции вы будете точно знать, где именно прячется такой баг.
</BusinessNote>

**Что вы узнаете:**

- как программа выбирает дорогу через if, else if и else и почему порядок проверок решает всё
- чем отличаются `=`, `==` и `===` и какой баг рождает одна лишняя черта
- как читать составные условия: сравнения, логические И, ИЛИ, НЕ, скобки и приоритет
- чем оператор `??` отличается от `||` и где из-за этого пропадают сотни тысяч сом
- когда удобнее switch, тернарный оператор или ранний выход (guard clauses)
- как проверять границы правил, например скидку, которая начинается ровно с 5 000 сом

Пригодится из прошлых лекций: «Первая программа».

## if / else: развилка

Оператор `if` выполняет блок, только если условие **истинно** (`true`). `else` — что делать иначе:

```js
if (возраст >= 18) {
  console.log('доступ разрешён');
} else {
  console.log('доступ запрещён');
}
```

Развилок может быть несколько — через `else if`. Проверки идут сверху вниз, и выполняется **первая
подошедшая** ветка, остальные пропускаются:

```js
if (баллы >= 90) {
  оценка = 'отлично';
} else if (баллы >= 75) {
  оценка = 'хорошо';
} else {
  оценка = 'нужно подтянуть';
}
```

Порядок важен. Если поставить проверку `баллы >= 75` первой, студент с 95 баллами получит «хорошо»:
95 больше 75, условие сработало, до проверки «90 и выше» дело просто не дойдёт.

<Callout title="Осторожно: = и == и ===">
Один знак `=` — это **присваивание** (положить значение). Два `==` — сравнение с приведением типов
(коварное: `'5' == 5` вернёт `true`). Три `===` — **строгое сравнение** без сюрпризов
(`'5' === 5` → `false`). В условиях почти всегда используйте `===`. Классический баг: написать
`if (статус = 'оплачен')` вместо `===` — присваивание всегда «истинно», и код пропустит все заказы
как оплаченные, включая неоплаченные.
</Callout>

## Операторы сравнения и логики

Условие — это выражение, которое даёт `true` или `false`:

| Оператор | Значение | Пример |
| --- | --- | --- |
| `===` / `!==` | равно / не равно (строго) | `x === 5` |
| `>` `<` `>=` `<=` | больше / меньше | `цена > 1000` |
| `&&` | И (оба истинны) | `возраст >= 18 && гражданин` |
| `\|\|` | ИЛИ (хотя бы одно) | `выходной \|\| праздник` |
| `!` | НЕ (переворот) | `!оплачено` |

Обратите внимание на разницу `>` и `>=` на границе. Правило «бесплатная доставка от 5 000 сом»
кодом пишется `сумма >= 5000`. Если написать `сумма > 5000`, клиент с чеком ровно 5 000 сом
доставку не получит — и такие «граничные» жалобы поддержка ловит пачками.

<Callout title="Truthy и falsy">
В условии число `0`, пустая строка `''`, `null`, `undefined` и `NaN` считаются «ложными» (falsy) —
как `false`. Всё остальное «истинно» (truthy) — даже строка `'0'` и пустой массив `[]`. Поэтому
`if (массив.length)` читается как «если в массиве что-то есть»: у пустого длина 0 → falsy.
</Callout>

### Двойное отрицание !! — приведение к «честному» boolean

Иногда нужно превратить любое значение в настоящий `true` или `false`. Для этого пишут два
восклицательных знака подряд: первый `!` переворачивает значение (и заодно приводит к boolean),
второй переворачивает обратно:

```js
!!'Бишкек'  // true  (непустая строка — truthy)
!!''        // false (пустая строка — falsy)
!!0         // false
!!'0'       // true  (это НЕ ноль, это строка из одного символа!)
!!150       // true
```

Зачем это нужно? Например, чтобы записать в отчёт не сам номер телефона клиента, а факт «телефон
указан: да/нет»: `const естьТелефон = !!клиент.телефон;`. Это как выключатель света: неважно,
какая лампочка вкручена — важно только «горит или нет».

## Скобки и приоритет: в каком порядке думает JavaScript

Логические операторы имеют **приоритет** (порядок выполнения), как в математике умножение
выполняется раньше сложения. Порядок такой: сначала `!`, потом сравнения (`>`, `===`...), потом
`&&`, и только потом `||`. То есть `&&` «прилипает» сильнее, чем `||`:

```js
a || b && c     // на самом деле это:  a || (b && c)
```

Из-за этого рождаются дорогие баги. Хотим правило доступа к базе заказов: «пускать админа или
менеджера, но обоих — только в дневную смену». Пишем без скобок:

```js
роль === 'admin' || роль === 'manager' && смена === 'день'
// JavaScript прочитал:  admin  ИЛИ  (manager И день)
// Итог: админ проходит и НОЧЬЮ — часть «только днём» к нему не применилась
```

Вывод простой и железный: **в смешанных условиях всегда ставьте скобки явно** — `(a || b) && c`.
Скобки бесплатны, а ночной доступ уволенного сотрудника в базу заказов — нет.

```js
const доступ = (роль === 'admin' || роль === 'manager') && смена === 'день';
```

## Короткое замыкание: && и || умеют лениться

Операторы `&&` и `||` вычисляют ровно столько, сколько нужно, и **возвращают одно из своих
значений**, а не обязательно `true`/`false`. Это называется **короткое замыкание** (short circuit).
Представьте ленивого охранника: если у первого посетителя нет пропуска, второго он даже не смотрит.

- `a || b` — если `a` truthy, вернуть `a` (до `b` дело не дойдёт), иначе вернуть `b`.
- `a && b` — если `a` falsy, вернуть `a`, иначе вернуть `b`.

```js
'Ош' || 'Бишкек'      // 'Ош'   — первое truthy, второе не проверялось
0 || 'запасной'       // 'запасной' — ноль falsy, пошли дальше
null && платёж()      // null — функция платёж() даже НЕ ВЫЗОВЕТСЯ
```

Классическое применение — значение по умолчанию:

```js
const город = формаДоставки.город || 'Бишкек';
// если поле пустое ('' — falsy) — подставим Бишкек
```

## ?? против ||: где прячутся 600 000 сом

У приёма `x || 'дефолт'` есть тёмная сторона: `||` считает «пустым» **любое** falsy-значение,
включая `0` и пустую строку. А ноль — это часто совершенно законные данные!

<BusinessNote>
Вот тот самый баг из начала лекции. В CRM магазина у заказа есть поле «скидка менеджера, сом».
Программист написал `const скидка = заказ.скидка || 300;` — хотел подставить стандартные 300 сом,
когда поле не заполнено. Но менеджеры честно ставили `0` для заказов без скидки — а `0` falsy, и
`||` заменял его на 300. Каждый заказ «без скидки» получал 300 сом скидки: 2 000 заказов × 300 сом =
600 000 сом в месяц. Ошибку нашли только в квартальном отчёте.
</BusinessNote>

Для таких случаев в JavaScript есть оператор `??` — **nullish coalescing** («объединение с
нулевым»). Он подставляет запасное значение **только** если слева `null` или `undefined` — то есть
данных действительно нет. Ноль и пустая строка для него — нормальные значения:

```js
0 || 300        // 300  — упс, ноль потеряли
0 ?? 300        // 0    — ноль сохранён, скидка честная
null ?? 300     // 300  — данных нет, берём дефолт
'' || 'гость'   // 'гость'
'' ?? 'гость'   // ''   — пустая строка осталась
```

Правило на память: **если 0 или пустая строка — это осмысленные данные, берите `??`; `||` — только
когда любое «пустое» значение и правда надо заменить.**

## Тернарный оператор — короткое if/else

Когда надо просто выбрать одно из двух значений, пишут коротко, через `? :`:

```js
const статус = баллы >= 60 ? 'зачёт' : 'незачёт';
// если баллы >= 60 → 'зачёт', иначе 'незачёт'

const доставка = сумма >= 5000 ? 0 : 250;  // сом
```

Тернарник хорош ровно для одного выбора из двух. Вкладывать тернарники друг в друга
(`a ? b : c ? d : e`) — плохая практика: читается как скороговорка. Три и больше веток — это уже
работа для `else if` или `switch`.

## switch / case: гардеробщик со списком

Когда одна переменная сравнивается с целым списком конкретных значений, лестница из `else if`
становится однообразной. Для этого есть `switch` — как гардеробщик, который смотрит на номерок и
идёт точно к нужному крючку:

```js
function тарифДоставки(город) {
  switch (город) {
    case 'Бишкек':
      return 200;   // сом
    case 'Ош':
      return 350;
    case 'Каракол':
      return 400;
    default:
      return 500;   // все остальные населённые пункты
  }
}
```

`switch` сравнивает **строго** (как `===`), а ветка `default` срабатывает, если ни один `case`
не совпал — это ваш «else».

<Callout title="Ловушка: провал без break">
Если ветка не заканчивается `return` или `break`, выполнение **проваливается** в следующий case —
это называется fallthrough. Иногда это делают нарочно, чтобы объединить варианты:

```js
switch (день) {
  case 'суббота':
  case 'воскресенье':   // суббота «проваливается» сюда — и это удобно
    console.log('выходной, склад в Бишкеке закрыт');
    break;
  default:
    console.log('рабочий день');
}
```

Но забытый `break` в обычном коде — один из самых частых багов: заказ вдруг получает и тариф Оша,
и тариф Каракола разом. Правило: каждая содержательная ветка заканчивается `break` или `return`.
</Callout>

## Guard clauses: выход у двери, а не лестница вложенности

Новички часто строят «лестницу» вложенных `if` — каждый следующий внутри предыдущего:

```js
function оформить(корзина) {
  if (корзина) {
    if (корзина.товары.length > 0) {
      if (корзина.сумма > 0) {
        return 'оформляем заказ';
      } else {
        return 'некорректная сумма';
      }
    } else {
      return 'корзина пуста';
    }
  } else {
    return 'корзина не найдена';
  }
}
```

Читать это — как искать выход в лабиринте. Приём **guard clause** (защитная проверка, «ранний
return») переворачивает логику: сначала проверяем все плохие случаи и **сразу выходим**, а основной
сценарий остаётся внизу без вложенности. Как фейс-контроль на входе в клуб: развернули у двери —
внутри уже только «свои»:

<Mermaid
  title="Guard clauses: ранний выход вместо вложенности"
  chart={`flowchart TD
    A["оформить(корзина)"] --> B{"корзина есть?"}
    B -->|"нет"| B1["return корзина не найдена"]
    B -->|"да"| C{"товары.length > 0?"}
    C -->|"нет"| C1["return корзина пуста"]
    C -->|"да"| D{"сумма > 0?"}
    D -->|"нет"| D1["return некорректная сумма"]
    D -->|"да"| E["return оформляем заказ"]`}
/>

```js
function оформить(корзина) {
  if (!корзина) return 'корзина не найдена';
  if (корзина.товары.length === 0) return 'корзина пуста';
  if (корзина.сумма <= 0) return 'некорректная сумма';

  return 'оформляем заказ';   // основной сценарий — без единой вложенности
}
```

Тот же приём делает элегантной задачу про оценки: `if (score >= 90) return 'A';` — и дальше можно
писать `if (score >= 75) return 'B';` уже без `else`, ведь из функции с 90+ баллами мы вышли ещё
на первой строке.

## Практика

Сначала — разминка руками, без песочницы. Откройте консоль браузера: клавиша F12 → вкладка
Console (на телефоне этот шаг можно пропустить и поверить таблице выше — но на ноутбуке сделайте
обязательно). Введите по очереди и сверьте с ожиданием:

1. `0 || 250` — должно вывести `250` (ноль falsy, `||` его заменил).
2. `0 ?? 250` — должно вывести `0` (для `??` ноль — законные данные).
3. `'' || 'Бишкек'` — выведет `'Бишкек'`; а `'' ?? 'Бишкек'` — пустую строку.
4. `!!'0'` — выведет `true`: строка из символа «ноль» непустая, значит truthy.
5. `true || console.log('привет')` — выведет `true`, а «привет» НЕ напечатается: короткое
   замыкание не дало правой части выполниться.

## Граничные случаи: где всё ломается

- **`NaN === NaN` → `false`.** Ситуация: проверяем `if (скидка === NaN)`, чтобы отловить ошибку
  вычисления. Что происходит: условие никогда не сработает, даже когда `скидка` реально `NaN`.
  Почему: по стандарту `NaN` не равен даже самому себе — единственное значение в JavaScript с таким
  свойством. Как правильно: используйте `Number.isNaN(скидка)`.
- **Сравнение строки и числа через `==`.** Ситуация: поле формы всегда приходит строкой, `'0' == false`
  и `'' == 0` дают `true`. Что происходит: код случайно считает пустую строку равной нулю. Почему:
  `==` перед сравнением приводит типы по неочевидным правилам. Как правильно: всегда `===`, а строку
  из формы явно приводить к числу (`Number(значение)`) до сравнения.
- **`0` и `''` как законные данные с `||`.** Ситуация: `qty || 1` для количества товара. Что
  происходит: заказ с `qty = 0` (например, «товар зарезервирован, ещё не выдан») превращается в
  `qty = 1`. Почему: `0` и `''` — falsy, `||` заменяет их так же, как `null`. Как правильно:
  `qty ?? 1` — подставляет запасное значение только вместо `null`/`undefined`.
- **Пустой массив в условии.** Ситуация: `if (корзина.товары)` вместо `if (корзина.товары.length > 0)`.
  Что происходит: условие истинно, даже если товаров ноль — сам массив `[]` truthy, это не то же
  самое, что «пусто». Почему: любой объект и массив в JS truthy независимо от содержимого. Как
  правильно: проверять именно `.length`, а не сам массив.
