Данные можно хранить по-разному, и от выбора «коробки» зависит, будет ли код простым и быстрым или
громоздким и медленным. **Структура данных** — это способ организовать данные в памяти: список,
словарь, стопка, очередь. Как в кладовке: одни вещи удобно держать на полке по порядку, другие — в
подписанных ящиках, третьи — стопкой у двери. Разберём основные структуры JavaScript и научимся
выбирать нужную за пять секунд.

<BusinessNote>
Правильная структура данных — это скорость, а скорость — это деньги. Реальный сценарий: магазин
shop.kg при открытии каждой карточки товара проверял перебором, входит ли товар в список из 80 000
акционных позиций. В пик распродажи страницы открывались за 1,2 секунды вместо 0,3 — а каждые лишние
100 мс задержки, по отраслевой статистике, отнимают около 1% конверсии. При обороте 5 млн сом в
месяц это минус примерно 450 000 сом. Лечение — замена одной строки: массив на `Set`. Понимание
таких различий отличает код, который «падает под нагрузкой», от кода, который держит рост бизнеса.
</BusinessNote>

## Массив: упорядоченный список

**Массив** хранит элементы **по порядку**, доступ — по **индексу** (номеру места, счёт с нуля).
Идеален, когда важен порядок и вы перебираете всё подряд: список товаров, история операций, строки
отчёта.

```js
const очередьЗадач = ['A', 'B', 'C'];
очередьЗадач[0];              // 'A' — мгновенно, по номеру места
очередьЗадач.includes('B');   // true — но для этого массив перебрали
очередьЗадач.indexOf('C');    // 2 — тоже перебором, слева направо
```

Слабое место — поиск. Чтобы понять, есть ли элемент, приходится проверять элементы один за другим.
Такую стоимость записывают как `O(n)`: время растёт **пропорционально количеству** элементов n.
В массиве из 10 строк это незаметно, а в базе на 1 000 000 клиентов каждая проверка — до миллиона
сравнений. Один раз — миллисекунды, но если таких проверок 200 в секунду, сервер начинает
захлёбываться.

## Объект как словарь: быстрый поиск по ключу

**Объект** хранит пары «ключ → значение» и находит значение по ключу **сразу**, не перебирая всё
подряд. Такую стоимость записывают как `O(1)`: время **не зависит от размера** — что 10 записей, что
миллион. Это «словарь»: по слову сразу открываете нужную страницу, а не листаете от корки до корки.

```js
const цены = { кофе: 250, чай: 120, десерт: 340 }; // сом
цены['кофе'];   // 250 — сразу, без перебора
цены.десерт;    // 340 — то же самое, через точку
```

Используйте объект, когда нужно быстро находить данные по имени или id: справочники, счётчики, кэши,
настройки.

## Почему поиск по ключу мгновенный: хэш-таблица на пальцах

Как объект умудряется найти ключ среди миллиона, ничего не перебирая? Внутри работает
**хэш-таблица**. Идея простая: **хэш-функция** — это формула, которая превращает любой ключ (строку
«кофе») в число — номер ячейки памяти, где лежит значение. Один и тот же ключ всегда даёт один и тот
же номер.

Бытовая аналогия — гардероб в театре. У вас номерок 347 — гардеробщица идёт **сразу к крючку 347**,
а не осматривает тысячу пальто по очереди. Хэш-функция и есть автомат, печатающий номерки: и при
записи, и при чтении ключ «кофе» приводит в одну и ту же ячейку.

<Callout title="А если номерки совпадут?">
Иногда два разных ключа дают один номер ячейки — это называется **коллизия** (два пальто на одном
крючке). Тогда движок сравнит двух-трёх кандидатов в этой ячейке — всё равно пара сравнений, а не
миллион. Поэтому честнее говорить, что поиск в объекте и `Map` «почти всегда `O(1)`» — и на практике
так оно и есть.
</Callout>

## Map: словарь «по-взрослому»

**`Map`** — вторая реализация словаря в JavaScript, созданная именно как структура данных, а не как
«объект на все случаи жизни». Снаружи то же самое — пары «ключ → значение» и поиск за `O(1)`, — но
есть важные отличия:

| Что | Объект `{}` | `Map` |
| --- | --- | --- |
| Типы ключей | только строки (число превратится в строку) | **любые**: числа, объекты, `true/false` |
| Узнать размер | окольно: `Object.keys(obj).length` | просто: `map.size` |
| Порядок ключей | числовые ключи самовольно сортируются | строго порядок добавления |
| Доступ | `obj.ключ` или `obj['ключ']` | методы `get`, `set`, `has`, `delete` |
| Где силён | JSON, простые записи-«анкеты» | частые добавления/удаления, нестроковые ключи |

```js
const остаткиПоСкладам = new Map();
остаткиПоСкладам.set('Бишкек', 1240);
остаткиПоСкладам.set('Ош', 380);

остаткиПоСкладам.get('Ош');     // 380
остаткиПоСкладам.has('Каракол'); // false — такого склада нет
остаткиПоСкладам.size;           // 2
```

Практическое правило: описываете **одну сущность с известными полями** (товар: название, цена,
остаток) — берите объект. Строите **растущую коллекцию** «ключ → значение», где ключи приходят из
данных (id клиентов, названия городов, даты) — берите `Map`.

## Множество (Set): только уникальные

**`Set`** — коллекция **без повторов**. Кладёте значения — дубликаты отсекаются сами. Плюс быстрая
проверка «есть ли элемент» за `O(1)` — внутри та же хэш-таблица, только без значений, одни ключи.

```js
const теги = new Set(['sale', 'new', 'sale']);
теги.size;        // 2 — второй 'sale' не добавился
теги.has('new');  // true, мгновенно
теги.add('hit');  // добавить
теги.delete('sale'); // убрать
```

Типовые задачи для `Set`: «сколько **уникальных** покупателей за день», «этот промокод уже
использован?», «покажи города, где есть хоть один заказ — без повторов».

## Преобразования: Set ↔ массив, объект ↔ пары

Структуры не живут изолированно — данные постоянно «переливают» из одной коробки в другую. Два
приёма, которые нужны каждый день.

**Set ↔ массив.** Оператор «три точки» `...` раскладывает `Set` обратно в массив — так делают
дедупликацию одной строкой:

```js
const города = ['Бишкек', 'Ош', 'Бишкек', 'Каракол', 'Ош'];
const уникальные = [...new Set(города)];
// ['Бишкек', 'Ош', 'Каракол'] — порядок первого появления сохранён
```

**Объект ↔ массив пар.** `Object.entries` превращает объект в массив пар `[ключ, значение]` — а с
массивом уже можно делать всё, что умеют массивы: сортировать, фильтровать, брать топ:

```js
const выручка = { кофе: 12500, чай: 4800, десерты: 9100 }; // сом за день

const пары = Object.entries(выручка);
// [['кофе', 12500], ['чай', 4800], ['десерты', 9100]]

пары.sort((a, b) => b[1] - a[1]); // сортируем по выручке, по убыванию
// [['кофе', 12500], ['десерты', 9100], ['чай', 4800]] — готовый топ продаж

const обратно = Object.fromEntries(пары); // и снова объект, если нужно
```

Есть и облегчённые версии: `Object.keys(выручка)` вернёт только ключи `['кофе', 'чай', 'десерты']`,
`Object.values(выручка)` — только значения `[12500, 4800, 9100]` (удобно сразу просуммировать).

## Стек и очередь: порядок обслуживания

Иногда важно не «что хранить», а «в каком порядке доставать». Обе структуры в JavaScript делаются из
обычного массива — отдельного класса не нужно, важна дисциплина: пользоваться только двумя методами.

**Стек (Stack)** — «последним пришёл, первым вышел» (**LIFO**, Last In — First Out). Как стопка
тарелок: кладёте сверху и берёте верхнюю. Так работает кнопка «Отменить» (Ctrl+Z), кнопка «Назад» в
браузере и вызовы функций в самом JavaScript:

```js
const историяДействий = [];
историяДействий.push('ввёл заголовок');   // положить сверху
историяДействий.push('вставил таблицу');
историяДействий.push('удалил абзац');

const отмена = историяДействий.pop();     // 'удалил абзац' — снято последнее
// нажали Ctrl+Z ещё раз:
историяДействий.pop();                    // 'вставил таблицу'
```

**Очередь (Queue)** — «первым пришёл, первым вышел» (**FIFO**, First In — First Out). Как очередь в
кассу: обслуживают в порядке прихода. Так работают печать документов, обработка заказов, рассылка
SMS:

```js
const очередьПечати = [];
очередьПечати.push('счёт_1204.pdf');      // встать в конец
очередьПечати.push('договор_аренды.docx');

const наПечать = очередьПечати.shift();   // 'счёт_1204.pdf' — кто раньше встал
```

<Callout title="Осторожно: shift — дорогая операция">
`pop` снимает элемент с конца — это `O(1)`. А `shift` забирает элемент **из начала**, и всем
оставшимся приходится сдвинуться на одну позицию влево: в очереди из 100 000 заявок это 99 999
перестановок — `O(n)` на каждое извлечение. Для учебных задач и очередей на сотни элементов это
неважно, но высоконагруженные системы держат большие очереди в специальных структурах (кольцевой
буфер, связный список), где извлечение из начала стоит `O(1)`.
</Callout>

## Сводная таблица: сколько стоят операции

Буква n здесь — количество элементов. `O(1)` — «мгновенно, от размера не зависит», `O(n)` —
«пропорционально размеру»: на 1 000 элементов — примерно 1 000 шагов, на миллионе — миллион.

| Операция | Массив | Объект / `Map` | `Set` |
| --- | --- | --- | --- |
| Взять по индексу / ключу | `O(1)` | `O(1)` | — |
| Проверить «есть ли?» | `O(n)` — `includes` перебирает | `O(1)` — `has` / по ключу | `O(1)` — `has` |
| Добавить в конец | `O(1)` — `push` | `O(1)` — `set` | `O(1)` — `add` |
| Убрать с конца | `O(1)` — `pop` | `O(1)` — `delete` | `O(1)` — `delete` |
| Убрать из начала | `O(n)` — `shift` сдвигает всех | — | — |
| Перебрать всё | `O(n)` | `O(n)` | `O(n)` |

<BusinessNote>
Переведём таблицу в сомы. Кассовый сервер сети супермаркетов в Бишкеке проверяет карту лояльности
при каждом чеке: 40 касс, пиковая нагрузка — 15 чеков в секунду, база — 500 000 клиентов. С массивом
и `includes` это до 7,5 млн сравнений каждую секунду — «нужен сервер помощнее», ещё 15 000–20 000
сом аренды в месяц, и всё равно тормозит. С `Map` — 15 обращений в секунду по хэшу, справится самый
дешёвый тариф. Одна строка кода дешевле нового сервера.
</BusinessNote>

<Callout title="Как выбрать структуру за пять секунд">
Спросите себя, что важнее. **Порядок и перебор всего подряд** — массив. **Быстрый поиск по
ключу** — объект (одна сущность с полями) или `Map` (растущая коллекция). **Уникальность и проверка
«есть ли»** — `Set`. **Порядок обслуживания** — стек (`push`/`pop`, отмена действий) или очередь
(`push`/`shift`, обработка по порядку прихода). Один правильный ответ на этот вопрос часто в разы
упрощает и ускоряет код.
</Callout>

### Мини-лаборатория в консоли браузера

Виджет не нужен — хватит консоли. Откройте DevTools (клавиша F12 или Cmd+Option+I на Mac), вкладка
**Console**, и выполните три опыта:

1. Введите `new Set(['Ош', 'Ош', 'Бишкек']).size` — вы должны увидеть **2**: дубликат отсёкся при
   создании.
2. Введите `const m = new Map(); m.set(2026, 'бюджет'); m.get(2026)` — вы должны увидеть строку
   `'бюджет'`: `Map` спокойно принял **число** как ключ.
3. Теперь то же с объектом: `const o = {}; o[2026] = 'бюджет'; Object.keys(o)` — вы должны увидеть
   `['2026']` — ключ **в кавычках**: объект молча превратил число в строку. Это то самое отличие из
   таблицы Map против объекта, увиденное своими глазами.
