## Введение

Понедельник, 08:00. В интернет-магазине «Тянь-Шань Электроникс» (Бишкек) цены хранятся в долларах, а покупателям показываются в сомах по официальному курсу. Каждое утро скрипт спрашивает курс у стороннего сервиса и пересчитывает витрину. Сегодня сервис ответил «200 OK» («всё в порядке»), но в теле лежало `{ "usd": 0 }`. Скрипт честно умножил цены на ноль: к 08:40 телефон за 349 долларов стоил 0 сом, и три покупателя успели оформить заказ.

В другой день сервис курсов просто завис: не отвечал и не отказывал. Скрипт ждал. И ждал. До вечера.

Оба случая — про **внешний API**: чужую программу, к которой ваш код обращается по сети за данными или услугой (с `fetch` вы знакомились в лекции «Асинхронность и API»). Ключевое слово — «чужая»: её скоростью, форматом и настроением вы не управляете. Поэтому интеграции пишут по правилу: **чужой сервис подведёт, а магазин всё равно должен работать**.

<BusinessNote title="Сколько стоит доверчивость к чужому API">
Допустим, магазин выручает 600 000 сом за 12 часов торговли, то есть 50 000 сом в час. Если сайт «лежит» два часа из-за зависшего сервиса курсов, это до 100 000 сом недополученной выручки. Три заказа на телефон по 0 сом — это 3 × 30 520 = 91 560 сом товара (349 долларов по курсу 87.45). Защитный код из лекции — около 100 строк, примерно три часа работы: при 500 сом в час это 1 500 сом один раз.
</BusinessNote>

**Что вы узнаете:**

- что может пойти не так у чужого сервиса и как защититься от каждого сбоя
- как поставить таймаут через AbortController и не зависнуть вместе с чужим сервисом
- какие ошибки повторять, а какие нет, и как считать паузу между повторами: 1, 2, 4 секунды с потолком
- как проверять данные из ответа: курс 0, минус или строка не должны попасть в расчёт цен
- как кэшировать курс и что показывать, если API недоступен
- где хранить ключи API (не в коде) и что записывать в журнал ошибок интеграции

Пригодится из прошлых лекций: «Асинхронность и API» (fetch и промисы), «Числа, деньги и даты» (курс и округление до тыйынов), «REST API» (статусы и идемпотентность), «Скрипты на Node» (запуск по расписанию).

## Задача: пересчитать витрину по официальному курсу

Официальные курсы валют к сому публикует Национальный банк КР: на сайте nbkr.kg есть раздел с курсами и выгрузка в машиночитаемом виде (XML). **Машиночитаемый** формат — такой, который программа разбирает сама, без чтения глазами. Магазин чаще берёт курс через сервис-посредник, который отдаёт те же данные в привычном JSON. В лекции пользуемся вымышленным адресом `https://api.example.kg/rates` и ответом такого вида:

```json
{ "usd": 87.45 }
```

Каждое утро магазин запрашивает курс, умножает на него цены в центах и округляет до тыйынов один раз (правило из лекции «Числа, деньги и даты»). Первая версия — короткая и «у меня работает»:

```js
// Наивная версия: работает только в хорошие дни
async function getUsdRateNaive() {
  const response = await fetch('https://api.example.kg/rates');
  const data = await response.json();
  return data.usd; // число? ноль? строка? undefined? Никто не проверяет
}
```

В пяти строках функции дыр больше, чем строк. Найдём их все и к каждой подберём защиту.

## Что может пойти не так → защита

Чужой сервис — как поставщик, который возит вам товар: может опоздать, привезти брак, пропасть или тихо сменить упаковку. Составим список претензий и сразу решим, чем защищаться.

| Что может пойти не так | Защита |
| --- | --- |
| Завис или недоступен совсем (нет сети, домен не найден): `fetch` ждёт минуты | таймаут через AbortController, затем повтор и запасной курс |
| Вернул ошибку сервера (500, 503) | повтор с растущей паузой, затем запасной курс |
| Сказал «вы не правы» (400, 401, 404): виноваты запрос, адрес или ключ | не повторять, записать в журнал, позвать человека |
| Ограничил частоту (429) | подождать, учесть Retry-After, ходить реже: кэш |
| Вернул мусор: вместо JSON пришла HTML-страница | try/catch, повтор, журнал |
| Вернул неверное значение: статус 200, а курс 0, минус или строка | валидация до расчёта |
| Сменил формат без предупреждения: поля `usd` больше нет | валидация структуры, запасной курс, запись в журнал |

<Callout title="Правило интеграции: деградируй, но не падай">
Хороший код при сбое чужого сервиса не падает вместе с ним, а сознательно ухудшает сервис: показывает чуть менее свежий курс, но магазин продолжает продавать. Узнать о плохом дне поставщика должен журнал, а не покупатель.
</Callout>

Все защиты складываются в один маршрут. Запомните его: дальше реализуем по квадратику.

## Таймаут: сколько мы готовы ждать

**Таймаут** (timeout) — предел ожидания: ответа нет за заданное время, значит, перестаём ждать и считаем попытку неудачной. У `fetch` собственного предела нет: он ждёт, пока не сдастся сама сеть, а это минуты. Остановить ожидание можно вручную: **AbortController** — «кнопка отмены» для запроса. Его сигнал отдают в `fetch`, таймер в нужный момент нажимает `abort()`, и `fetch` сразу завершается ошибкой `AbortError`.

```js
// Запрос JSON с ограничением по времени. HTTP-ошибка получает поле status
async function fetchJson(url, timeoutMs, headers = {}) {
  const controller = new AbortController(); // «кнопка отмены»
  const timerId = setTimeout(() => controller.abort(), timeoutMs);

  try {
    const response = await fetch(url, { headers, signal: controller.signal });

    if (!response.ok) {
      // fetch не считает 503 или 401 ошибкой, поэтому статус проверяем сами
      const error = new Error('HTTP ' + response.status);
      error.status = response.status; // по статусу решим: повторять или нет
      error.retryAfter = response.headers.get('Retry-After'); // просьба сервера подождать
      throw error;
    }

    return await response.json(); // тело читаем ВНУТРИ try: таймер охраняет и его
  } catch (error) {
    if (error.name === 'AbortError') {
      throw new Error('Таймаут: сервис не ответил за ' + timeoutMs + ' мс');
    }
    throw error; // остальное (HTTP-ошибка, обрыв сети, не JSON) отдаём как есть
  } finally {
    clearTimeout(timerId); // таймер больше не нужен
  }
}
```

Две частые ошибки: читать тело ответа вне `try` (при зависшем теле таймер уже не поможет) и не выключать таймер в `finally` (в Node скрипт не завершится, пока таймер не сработает). Размер таймаута решает бизнес: 2–3 секунды, если ждёт покупатель, и до 10 секунд для ночного скрипта.

## Что повторять, а что нет

**Повтор** (retry) — вторая попытка того же запроса. Он лечит временные сбои: сервер перегружен, сеть моргнула. При постоянных он бесполезен: неверный запрос останется неверным и на сотой попытке, а чужой сервис разозлится и может вас заблокировать.

| Ситуация | Повторять? |
| --- | --- |
| 400, 404: запрос составлен неверно или такого адреса нет | нет, исправьте запрос |
| 401, 403: ключ неверный, просрочен или не хватает прав | нет, исправьте ключ |
| 429: вы спрашиваете слишком часто | да, но выждав, сколько просит сервер (заголовок Retry-After) |
| 500, 502, 503, 504: сервер сломан или перегружен | да, с растущей паузой (500 бывает и постоянной) |
| таймаут, обрыв сети | да |
| 200, но в теле мусор | да, пока есть попытки, затем запасной курс |

Заголовок **Retry-After** («вернитесь через столько-то секунд») разобран в лекции «Как открывается сайт: DNS, HTTP и HTTPS»: просьбу сервера уважают. Правила из таблицы — одна короткая функция:

```js
// Есть ли смысл пробовать ещё раз
function isRetryable(error) {
  if (error.status === undefined) return true; // статуса нет: таймаут, обрыв сети, мусор
  if (error.status === 408 || error.status === 429) return true; // «долго» и «часто»
  return error.status >= 500; // сервер нездоров и может оправиться
}
```

Всё это про **чтение** данных, его повторять безопасно. С записью (оплата, заказ) всё иначе: см. «Граничные случаи».

## Экспоненциальная пауза: 1, 2, 4 секунды и потолок

Повторять сразу — худший вариант: сервис и так перегружен, а тысяча клиентов, получивших ошибку одновременно, одновременно же вернётся и добьёт его. Правило такое: чем больше неудач подряд, тем дольше ждём. **Экспоненциальная пауза** (exponential backoff) удваивается с каждой попыткой: перед повтором номер n (счёт с нуля) ждём `1000 * 2 ** n` миллисекунд, то есть 1 с, 2 с, 4 с, 8 с, 16 с. Чтобы пауза не доросла до часов, ставят **потолок**, например 30 секунд: 32 секунды на повторе номер 5 срезаются до 30.

<Mermaid

  chart={`sequenceDiagram

Худший случай: 4 попытки по 3 секунды плюс паузы 1 + 2 + 4 секунды, то есть 12 + 7 = 19 секунд. Утреннему скрипту это не страшно. Покупатель столько ждать не станет, поэтому страницы магазина сами к API не ходят: берут курс из кэша, который обновляет фоновая задача раз в несколько часов. И ещё тонкость: к паузе добавляют случайные до 20 процентов (`pause * (1 + Math.random() * 0.2)`), чтобы тысяча клиентов, споткнувшихся одновременно, не вернулась к серверу одновременно.

Решили? Сверьтесь:

```js
function retryDelay(attempt, baseMs, maxMs) {
  if (attempt < 0) return 0; // отрицательного номера повтора не бывает
  return Math.min(baseMs * 2 ** attempt, maxMs); // 1000, 2000, 4000... но не выше потолка
}

// Пауза: промис, который завершится через ms миллисекунд (понадобится при сборке)
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
```

Две строки закрывают все шесть случаев.

## Проверка данных: «200 OK» ещё не значит «курс верный»

Статус 200 говорит лишь о том, что сервер ответил, а не о том, что ответил правильно. Данные из внешнего мира проверяют на границе, до расчётов и до кэша: это **валидация**. Проверяем структуру (есть ли поле `usd`), тип (число ли это) и здравый смысл (в разумных ли границах). Строки особенно коварны: JavaScript «чинит» их молча и по-разному (`'87.45' * 100` даёт 8745, `'87,45' * 100` даёт NaN, а `'87.45' + 1` даёт строку `'87.451'`), поэтому строку вместо числа лучше отвергнуть явно.

```js
const MIN_RATE = 40;  // границы здравого смысла для доллара в сомах: они ловят
const MAX_RATE = 200; // ноль, минус и потерянную запятую (0.8745 или 8745)

// Возвращает курс-число или бросает ошибку с понятной причиной
function validateRate(data) {
  // 1. Есть ли объект с нужным полем? Нет: формат, скорее всего, сменился
  if (data === null || typeof data !== 'object' || !('usd' in data)) {
    throw new Error('Формат ответа изменился: нет поля usd');
  }

  const rate = data.usd;

  // 2. Настоящее ли это число? Строка, null, NaN и Infinity не проходят
  if (typeof rate !== 'number' || !Number.isFinite(rate)) {
    throw new Error('Курс не число: ' + String(rate) + ' (тип ' + typeof rate + ')');
  }

  // 3. Здравый смысл: ноль, минус и слишком странное значение отвергаем
  if (rate < MIN_RATE || rate > MAX_RATE) {
    throw new Error('Курс вне допустимых границ: ' + rate);
  }

  return rate;
}
```

Границы 40–200 — страховка, а не закон природы: если курс действительно выйдет за них, проверка поднимет тревогу, и человек решит, что делать. Это лучше, чем молча пересчитать по странному числу весь каталог.

## Кэш и запасной вариант

**Кэш** — запомненный ответ, который используют повторно, пока он свежий. Официальный курс меняется раз в день, а покупателей тысячи: спрашивать у API на каждого бессмысленно.

<BusinessNote title="Цена запроса, который можно не делать">
Допустим, на сайт заходит 3 000 человек в день и каждый открывает четыре страницы с ценами: без кэша это 12 000 запросов курса в сутки. Бесплатный лимит в 1 000 запросов кончится в первый час торговли, пойдут ответы 429, и цены встанут. Платный тариф по 100 сом за 1 000 запросов — 36 000 сом в месяц за данные, которые меняются раз в сутки. Кэш на 6 часов оставляет максимум 4 запроса в сутки: около 12 сом в месяц и ни одного ответа 429.
</BusinessNote>

Правила кэша:

- **Храним курс вместе с моментом получения** (`fetchedAt`): курс без даты — мина замедленного действия, свежий от протухшего не отличить.
- **Свежесть проверяем по времени:** прошло меньше 6 часов — берём из кэша, больше — идём к API.
- **В кэш пускаем только проверенное,** иначе курс 0 продержится там все 6 часов.
- **Устаревший кэш не выбрасываем:** если API молчит, последний известный курс лучше пустоты, но витрина показывает его с пометкой даты в часовом поясе Бишкека (Asia/Bishkek, UTC+6): «Курс на 06.10.2026: обновление сейчас недоступно».

Кэш в переменной исчезает при перезапуске, поэтому скрипту по расписанию («Скрипты на Node») последний курс записывают ещё и в файл `last-rate.json`.

## Ключи API: в окружении, не в коде

Платные API просят **ключ** — строку-пропуск в заголовке запроса. Для поставщика это ваш пароль: кто знает ключ, тот тратит вашу квоту и деньги. Поэтому в код ключ не пишут: код попадает в Git, в чаты, на ноутбуки подрядчиков. Правильно — **переменные окружения**: настройки, которые задаются снаружи программы (в панели хостинга или в файле `.env` вне Git), а код их только читает:

```js
const API_KEY = process.env.RATES_API_KEY; // ключ приходит из окружения, в коде его нет
if (!API_KEY) {
  // падаем сразу: лучше увидеть проблему при запуске, чем получить 401 в день продаж
  throw new Error('Не задана переменная окружения RATES_API_KEY');
}
```

Файл `.env` вносят в `.gitignore`; запуск: `node --env-file=.env rates.js` (Node 20.6 и новее). Ключ живёт только на сервере: в браузере его увидит любой через F12 (лекция «Безопасность фронтенда»). Выпускайте ключ с минимальными правами («Доступы и учётки») и не пишите его в журнал.

<Callout title="Удалили ключ из кода, а он всё ещё в истории Git">
Git помнит каждый коммит: ключ, хоть раз попавший в репозиторий, остаётся в истории, даже если из файла его удалили, а боты находят такие ключи нередко за минуты. Надёжное лекарство одно: отозвать старый ключ у поставщика и выдать новый.

## Журнал интеграции: что записывать

Когда курс не обновился в 08:00, утром нужны три ответа: что случилось, сколько раз пробовали и чем кончилось. Их даст только **журнал** (лог) — построчная запись событий: время, событие, номер попытки, статус или текст ошибки, принятое решение. Не пишут ключи, персональные данные покупателей и тело ответа целиком.

```js
// Одна строка журнала — один JSON: его легко искать и считать
function logIntegration(level, event, details) {
  const line = { time: new Date().toISOString(), level, event, ...details };
  console.log(JSON.stringify(line)); // время в UTC: 02:00 в журнале — это 08:00 в Бишкеке
}
```

Раз в неделю смотрите, сколько раз брали запасной курс, а для курса старше суток настройте оповещение человеку.

## Собираем всё вместе

Все детали готовы. Файл `rates.js` — это функции и `API_KEY` из разделов выше плюс главная функция, которая раскладывает их по схеме маршрута:

```js
const RATES_URL = 'https://api.example.kg/rates'; // вымышленный адрес
const TIMEOUT_MS = 3000;                 // дольше 3 секунд сервис не ждём
const MAX_ATTEMPTS = 4;                  // первая попытка и три повтора
const BASE_DELAY_MS = 1000;              // пауза перед первым повтором
const MAX_DELAY_MS = 30000;              // потолок паузы
const CACHE_TTL_MS = 6 * 60 * 60 * 1000; // курс считаем свежим 6 часов

let cache = null; // последний проверенный курс: { rate, fetchedAt }

async function getUsdRate() {
  // 1. Свежий кэш? В сеть не ходим
  if (cache && Date.now() - cache.fetchedAt < CACHE_TTL_MS) {
    return { rate: cache.rate, fetchedAt: cache.fetchedAt, stale: false };
  }

  // 2. Идём к API: не больше MAX_ATTEMPTS попыток
  for (let attempt = 0; attempt < MAX_ATTEMPTS; attempt++) {
    try {
      const data = await fetchJson(RATES_URL, TIMEOUT_MS, { Authorization: 'Bearer ' + API_KEY });
      const rate = validateRate(data); // мусор и нули дальше не пройдут
      cache = { rate, fetchedAt: Date.now() }; // в кэш только проверенное
      return { rate, fetchedAt: cache.fetchedAt, stale: false };
    } catch (error) {
      const isLast = attempt === MAX_ATTEMPTS - 1;
      logIntegration(isLast ? 'error' : 'warn', 'rates.failed', {
        attempt: attempt + 1, status: error.status ?? null, message: error.message,
      });
      if (!isRetryable(error) || isLast) break; // 400, 401 или попытки кончились

      const ownPause = retryDelay(attempt, BASE_DELAY_MS, MAX_DELAY_MS); // 1, 2, 4 секунды
      const serverPause = Number(error.retryAfter) * 1000 || 0; // просьба сервера, если есть
      await sleep(Math.max(ownPause, serverPause));
    }
  }

  // 3. Не вышло: последний известный курс с пометкой «не свежий»
  if (cache) {
    logIntegration('error', 'rates.fallback', { fetchedAt: new Date(cache.fetchedAt).toISOString() });
    return { rate: cache.rate, fetchedAt: cache.fetchedAt, stale: true };
  }
  throw new Error('Курс недоступен, а запасного значения нет'); // первый запуск и сразу сбой
}
```

Сверьте код со схемой: шаг 1 — кэш, шаг 2 — цикл попыток с таймаутом, валидацией и решением «повторять или нет», шаг 3 — запасной курс. После последней попытки пауза не нужна: ждать, чтобы тут же сдаться, бессмысленно.

## Граничные случаи: где всё ломается

- **1. Статус 200, а курс 0.** Ситуация: у поставщика сбой, и он отвечает `{ "usd": 0 }` со статусом 200. Что происходит: все цены становятся 0 сом, а ноль оседает в кэше на 6 часов. Почему: 200 значит «сервер ответил», а не «ответ верный». Как правильно: валидация до расчёта и до кэша; ответ с нулём считать ошибкой, как 503: повтор, затем последний известный курс и запись в журнал.
- **2. Повторы без паузы.** Ситуация: после ответа 503 сотни клиентов повторяют запрос в цикле по 20 раз в секунду. Что происходит: больному сервису хуже, а вас заносят в чёрный список (сначала 429, потом блокировка ключа). Почему: повтор без паузы — не вторая попытка, а атака на своего поставщика. Как правильно: растущая пауза с потолком и случайной добавкой, лимит попыток, Retry-After.
- **3. Повтор оплаты.** Ситуация: запрос оплаты оборвался по таймауту, и код отправил POST ещё раз. Что происходит: первый запрос на деле дошёл и списал деньги, второй списал их снова. Почему: таймаут значит «не знаю, чем кончилось», а POST не идемпотентен (лекция «REST API»). Как правильно: автоповторы только для чтения; запись повторяют с ключом идемпотентности или сначала проверяют статус платежа.
- **4. Курс без даты в кэше.** Ситуация: курс сохранили просто как `cache = 87.45`, а поставщик неделю недоступен. Что происходит: магазин неделю продаёт по старому курсу; при закупке на 10 000 долларов расхождение в 1.5 сома — это 15 000 сом, а в журнале тишина. Почему: без даты свежее не отличить от протухшего. Как правильно: хранить момент получения, показывать пометку даты, включить оповещение «курсу больше суток».
- **5. Формат сменился без предупреждения.** Ситуация: поставщик переименовал поле: вместо `usd` теперь `USD`. Что происходит: `data.usd` равно `undefined`, `Math.round(priceCents * undefined)` даёт `NaN`, и на витрине «NaN сом». Почему: чужой договор меняется без письма, а тесты на старых примерах остаются зелёными. Как правильно: проверять структуру, при расхождении брать запасной курс и поднимать тревогу; держать в тестах образец настоящего ответа.
- **6. Ключ API на GitHub.** Ситуация: для скорости ключ вставили прямо в `rates.js` и выложили проект в публичный репозиторий. Что происходит: боты находят ключ за минуты, чужие запросы выбирают квоту или раздувают счёт, поставщик блокирует ключ, и курсы перестают обновляться. Почему: история Git хранит всё. Как правильно: ключи только в переменных окружения, `.env` в `.gitignore`; при утечке сразу отозвать ключ и выпустить новый.
