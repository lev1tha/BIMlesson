Массив хорош для списка однотипных значений. Но что, если у одной сущности много **разных**
свойств — у клиента есть имя, возраст, email, город доставки? Для этого есть **объект**, а для
передачи таких данных между программами — **JSON**. Это, без преувеличения, главная лекция курса
для будущего аналитика: 90% данных, которые вы встретите в работе, приедут к вам именно в виде
объектов и JSON.

<BusinessNote>
Любая интеграция — 1С с сайтом, платёжный шлюз, выгрузка в аналитику — это обмен данными в формате
**JSON**. Цена неумения его читать вполне конкретна. Платёжные API почти всегда передают суммы в
минимальных единицах: поле `amount: 125000` — это 125 000 **тыйынов**, то есть 1 250 сом. Аналитик,
который не заглянул в документацию и в сам JSON, покажет руководству выручку 125 000 сом — завысит
её в 100 раз. Обратная ошибка занижает выручку в 100 раз, и на её поиски уходит день работы двух
человек. Умение открыть ответ API и глазами проверить поля — навык, который окупается в первую же
неделю работы.
</BusinessNote>

## Объект: набор «ключ — значение»

**Объект** хранит именованные свойства в фигурных скобках. У каждого свойства есть **ключ** (имя) и
**значение**. Бытовая аналогия — анкета или карточка товара: у полей есть подписи («Имя», «Цена»),
и по подписи вы мгновенно находите нужное значение, не перебирая всё подряд.

```js
const пользователь = {
  имя: 'Айгерим',
  возраст: 20,
  студент: true,
};
```

К свойствам обращаются двумя способами:

```js
пользователь.имя;        // 'Айгерим' — через точку
пользователь['возраст']; // 20        — через скобки (когда ключ лежит в переменной)
```

Значением может быть что угодно, включая другой объект или массив — так получаются **вложенные**
структуры. Именно вложенность делает объекты «языком» для описания чего угодно — заказа, счёта,
отчёта:

```js
const заказ = {
  номер: 1024,
  клиент: { имя: 'Тилек', город: 'Ош' },
  товары: ['кофе', 'чай'],
};
заказ.клиент.город;  // 'Ош' — идём по цепочке через точки
заказ.товары.length; // 2
```

## Объект живёт и меняется

Объект — не застывшая форма. После создания свойства можно **добавлять**, **менять** и **удалять**:

```js
const товар = { название: 'Кофе', цена: 250 };

товар.цена = 280;          // изменили существующее свойство
товар.вНаличии = true;     // добавили новое свойство «на лету»
delete товар.вНаличии;     // удалили свойство целиком
```

Обратите внимание: `товар` объявлен через `const`, но менять его свойства можно. `const` запрещает
**переприсвоить переменную целиком** (`товар = другойОбъект` — ошибка), а внутренности объекта —
пожалуйста. Почему так — станет ясно в следующем разделе, и это одна из самых коварных тем JS.

## Копирование по ссылке: главная ловушка новичка

Число или строка при присваивании **копируются**. Объект — **нет**. Переменная хранит не сам
объект, а **ссылку** на него — адрес, по которому объект лежит в памяти. Бытовая аналогия: переменная
— это не квартира, а бумажка с адресом квартиры. Написали адрес на второй бумажке — квартира
осталась одна, просто теперь к ней ведут две бумажки.

```js
const a = { цена: 250 };
const b = a;        // скопировали ССЫЛКУ, а не объект!

b.цена = 500;
console.log(a.цена); // 500 — изменился «тот же самый» объект
```

Реальный сценарий этой ошибки: аналитик берёт прайс `const акционный = обычныйПрайс`, снижает цены
на 20% «в копии» — и обнаруживает, что основной прайс на сайте тоже подешевел. Если магазин делает
300 заказов в день со средним чеком 1 800 сом, то полдня торговли по ошибочной цене со скидкой 20%
— это около 54 000 сом недополученной выручки. Из-за одной строчки без настоящего копирования.

Настоящая (поверхностная) копия делается оператором **spread** — три точки «разворачивают»
свойства в новый объект:

```js
const копия = { ...обычныйПрайс };  // новый объект с теми же свойствами
копия.цена = 200;                   // оригинал не пострадал
```

<Callout title="Поверхностная копия — значит «на один этаж»">
`{ ...obj }` копирует только верхний уровень. Если внутри лежит вложенный объект
(`заказ.клиент`), то в копию попадёт **ссылка** на того же клиента, и правка `копия.клиент.город`
изменит и оригинал. Для полной («глубокой») копии простых данных используют трюк
`JSON.parse(JSON.stringify(obj))` или современный `structuredClone(obj)`. Запомните правило:
скопировал объект спредом — вложенные объекты всё ещё общие.
</Callout>

## Есть ли такое свойство? Проверки и optional chaining

Обращение к несуществующему свойству возвращает `undefined` — это не ошибка:

```js
const заказ = { номер: 7 };
заказ.скидка; // undefined — такого свойства нет
```

А вот шаг **вглубь** несуществующего свойства — уже падение программы:

```js
заказ.клиент.город; // TypeError: Cannot read properties of undefined
```

Это ошибка номер один в реальных данных: из 10 000 заказов у 30 не заполнен клиент — и ночной
отчёт падает на 31-й строке, а утром отдел продаж остаётся без цифр. Защищаются тремя
инструментами:

```js
'клиент' in заказ;              // false — проверка наличия ключа
заказ.клиент?.город;            // undefined вместо падения — optional chaining
заказ.клиент?.город ?? 'не указан'; // подставить запасное значение
```

**Optional chaining** (оператор `?.`, «опциональная цепочка») — это вежливый стук в дверь: если
свойства нет, цепочка просто возвращает `undefined` и не ломает программу. Оператор `??` добавляет
«а если пусто — возьми вот это». Вместе они превращают аварийную остановку отчёта в аккуратную
строку «не указан», которую легко отфильтровать и разобраться.

## Перебор объекта: Object.keys, values, entries

Массив перебирают циклом. А объект? Для этого есть три метода, которые превращают объект в массив
— а дальше работают все знакомые `map`, `filter` и `reduce`:

| Метод | Что возвращает | Для примера ниже |
| --- | --- | --- |
| `Object.keys(obj)` | массив ключей | `['Бишкек', 'Ош', 'Каракол']` |
| `Object.values(obj)` | массив значений | `[1250000, 640000, 210000]` |
| `Object.entries(obj)` | массив пар «ключ-значение» | `[['Бишкек', 1250000], ...]` |

```js
const продажи = { Бишкек: 1250000, Ош: 640000, Каракол: 210000 };

const итого = Object.values(продажи).reduce((s, x) => s + x, 0);
// 2 100 000 сом — сумма по всем городам
```

Попробуйте в песочнице: посчитайте долю каждого города в общей выручке.

<Sandbox code={`const продажи = { Бишкек: 1250000, Ош: 640000, Каракол: 210000 };

## Деструктуризация: распаковать объект в переменные

Писать `пользователь.имя`, `пользователь.возраст` по десять раз утомительно.
**Деструктуризация** — это «распаковка» свойств объекта сразу в отдельные переменные, как разбор
пакета с продуктами по полкам холодильника:

```js
const user = { имя: 'Айгерим', возраст: 20, город: 'Бишкек' };

const { имя, город } = user;   // взяли только нужные свойства
console.log(имя, город);        // 'Айгерим' 'Бишкек'

const { скидка = 0 } = user;    // значение по умолчанию, если свойства нет
```

Особенно удобна деструктуризация в параметрах функции — сразу видно, какие поля ей нужны:

```js
function приветствие({ имя, город }) {
  return 'Привет, ' + имя + ' из города ' + город + '!';
}
приветствие(user); // 'Привет, Айгерим из города Бишкек!'
```

Массивы деструктурируются по позициям: `const [первый, второй] = массив`.

## Массив объектов — самая частая структура данных

Список товаров, сотрудников, заказов — это почти всегда **массив объектов**: каждая строка
будущей таблицы — объект, каждый столбец — ключ. И вся сила методов массива (`map`, `filter`,
`reduce`) работает по свойствам:

```js
const товары = [
  { название: 'Кофе', цена: 250 },
  { название: 'Чай', цена: 120 },
];

const сумма = товары.reduce((s, t) => s + t.цена, 0); // 370
const названия = товары.map(t => t.название);         // ['Кофе', 'Чай']
```

## JSON: данные как текст

**JSON** (JavaScript Object Notation) — это текстовый формат записи объектов и массивов. Выглядит
почти как объект JS, но это **строка**, которую можно передать по сети или сохранить в файл.
Аналогия: объект в памяти — это собранный шкаф, а JSON — тот же шкаф, разобранный и упакованный в
плоскую коробку для перевозки. По сети и в файлы «ездят» только коробки.

```json
{ "имя": "Айгерим", "возраст": 20, "навыки": ["Excel", "SQL"] }
```

Две команды для работы с ним:

- `JSON.stringify(объект)` — «упаковать»: превратить объект в JSON-строку, чтобы отправить;
- `JSON.parse(строка)` — «распаковать»: разобрать JSON-строку обратно в объект, чтобы использовать.

```js
const строка = JSON.stringify({ имя: 'Айгерим', возраст: 20 });
// '{"имя":"Айгерим","возраст":20}'

const объект = JSON.parse(строка);
объект.возраст; // 20 — снова обычный объект

JSON.stringify(объект, null, 2); // третий аргумент 2 — красивые отступы для чтения
```

<Callout title="Строгие правила JSON">
В JSON ключи всегда в **двойных кавычках** (`"имя"`, а не `имя`), в конце нет висячих запятых, а
значения — только строки, числа, true/false, null, массивы и объекты (никаких функций и
`undefined` — при упаковке `JSON.stringify` их молча выбрасывает). Одна пропущенная кавычка — и
`JSON.parse` падает с ошибкой SyntaxError. Поэтому подозрительный JSON сначала прогоняют через
валидатор или `try/catch`.
</Callout>

## Как выглядит настоящий ответ API — и как читать его глазами

До сих пор наши объекты были игрушечными. Вот **реалистичный** ответ API интернет-магазина на
запрос «дай список заказов» — именно такое вы увидите в работе:

```json
{
  "status": "ok",
  "data": {
    "orders": [
      {
        "id": 10452,
        "created_at": "2026-08-15T14:32:00+06:00",
        "customer": { "name": "Айгерим", "city": "Бишкек" },
        "items": [
          { "sku": "COF-01", "title": "Кофе зерновой", "price": 25000, "qty": 2 },
          { "sku": "TEA-05", "title": "Чай улун", "price": 12000, "qty": 1 }
        ],
        "total": 62000,
        "currency": "KGS"
      }
    ],
    "page": 1,
    "total_pages": 7
  }
}
```

Читаем сверху вниз, как матрёшку:

1. **Обёртка**: `status` говорит, что запрос успешен; полезные данные лежат внутри `data` — это
   типовой приём почти всех API.
2. **Массив заказов**: `data.orders` — массив объектов; сейчас в нём один заказ, дальше будут
   страницы (`page` 1 из 7 — данные отдают порциями, это называется пагинацией).
3. **Вложенность**: город клиента первого заказа — путь `data.orders[0].customer.city`. Индекс
   `[0]` — потому что `orders` массив.
4. **Деньги**: `price: 25000` при `currency: "KGS"` — это 25 000 **тыйынов**, то есть 250 сом.
   Проверяем итог: 25000 × 2 + 12000 × 1 = 62000 тыйынов = 620 сом. Сошлось с `total`.
5. **Дата**: `created_at` в формате ISO, суффикс `+06:00` — часовой пояс Asia/Bishkek.

<BusinessNote>
Навык «пройти глазами по JSON и проверить сумму» — это входной контроль данных. Прежде чем строить
отчёт на выгрузке из API, аналитик берёт 2–3 записи и вручную сверяет: сходится ли `total` с суммой
позиций, в тех ли единицах цена, тот ли часовой пояс у дат. Пятнадцать минут такой проверки
регулярно спасают от отчётов, где выручка за месяц «вдруг» 100 млн сом вместо 1 млн — и от
неловкого разговора с директором после презентации.
</BusinessNote>
