## Введение

Айгерим — контент-менеджер интернет-магазина электроники в Бишкеке. В понедельник фотограф привёз
ей карту памяти с 300 снимками новых товаров. Фотоаппарат назвал файлы по-своему — `IMG_2041.jpg`,
`IMG_2042.jpg` и так далее, — а сайт магазина (допустим, shop.kg) ждёт имена вида `tovar-2041.jpg`:
по ним снимки привязываются к карточкам товаров. Вручную это выглядит так: выделить файл, нажать F2,
набрать новое имя, нажать Enter. Секунд пятнадцать на снимок — больше часа монотонной работы, и где-то
на двухсотом файле рука обязательно промахнётся мимо цифры. А в конце месяца та же Айгерим сводит
двенадцать выгрузок продаж в один отчёт: копирует строки из файла в файл, сверяет итоги — и теряет
ещё полдня.

Обе задачи — классика для **скрипта**: небольшой программы, которая делает одну рутинную работу и сама
завершается. Это не сервер из лекции «Свой HTTP-сервер на Node», который после запуска бесконечно ждёт
запросов, а разовый помощник: запустили командой — через пару секунд 300 файлов переименованы, отчёт
собран, программа вышла. Аналогия — карточка-рецепт на кухне: повар не придумывает блюдо заново, а идёт
по шагам; скрипт — такая карточка для компьютера, записанная один раз и работающая годами.

<BusinessNote>
Два часа в день на ручное переименование и сведение файлов — типичная нагрузка контент-менеджера или
помощника бухгалтера. Посчитаем: при зарплате 60 000 сом в месяц час работы стоит около 340 сом, значит
два часа в день — 680 сом, за 22 рабочих дня около 15 000 сом в месяц и почти 180 000 сом в год на
одного сотрудника. Это деньги, потраченные на работу, с которой справится программа в несколько десятков
строк. Скрипт же пишется за вечер (три часа — около 1 000 сом по той же ставке) и окупается в первый
же рабочий день. Именно поэтому «умею писать скрипты» — одна из немногих строчек в резюме аналитика,
которую работодатель способен перевести в сомы без калькулятора.
</BusinessNote>

**Что вы узнаете:**

- чем скрипт отличается от приложения и как запустить его командой `node`
- как читать, записывать, перечислять и переименовывать файлы модулем `fs`
- как защитить массовую операцию: сначала план (dry run), потом действие
- как собрать 12 CSV в один отчёт, переиспользуя функции из лекции про CSV
- как передать скрипту параметр, вернуть код выхода и повесить скрипт на кнопку `npm run`
- как поставить скрипт на расписание и не потерять данные: бэкап, идемпотентность, логи

## Что такое скрипт и как его запустить

Скрипт на Node — обычный текстовый файл с расширением `.js`. У него нет кнопки «Запустить»: его вызывают
из терминала командой `node имя-файла.js` — из того самого терминала, с которым вы познакомились в
лекции «Командная строка». Если вы умеете перейти в нужную папку командой `cd`, остальное — одна строка.
Для начала проверим, что Node на месте:

```bash
node --version
```

Терминал должен ответить версией, например `v22.11.0` (цифры у вас будут свои, главное — не старше 18).
Если вместо этого он пишет «command not found» (в Windows — «не является внутренней или внешней
командой»), установите Node.js (выпуск LTS) с сайта nodejs.org и откройте терминал заново. Теперь
самый маленький скрипт на свете:

```js
// hello.js
console.log('Привет из скрипта!');
console.log('Версия Node:', process.version);
```

```bash
node hello.js
```

```text
Привет из скрипта!
Версия Node: v22.11.0
```

<Callout title="Скрипт доходит до конца и сам завершается">
Сервер из прошлой лекции после запуска продолжает ждать — его останавливают клавишами Ctrl+C. Скрипт
устроен наоборот: выполнил последнюю строку и вышел, освободив память. Именно это свойство позволяет
запускать скрипты по расписанию: запустился, сделал работу, исчез.
</Callout>

Одна техническая деталь, чтобы потом не споткнуться. Строки `import` из лекции «Модули и npm» в файле
`.js` заработают, только если рядом лежит `package.json` с настройкой `"type": "module"` — ровно как в
лекции про HTTP-сервер. Заведите для скриптов отдельную папку и положите в неё файл `package.json` из
одной строки (позже мы превратим его в пульт с кнопками для коллег):

```json
{ "type": "module" }
```

## Модуль fs: руки вашего скрипта

Сам по себе JavaScript ничего не знает о файлах на диске — он умеет считать и работать со строками.
Файлами в Node занимается встроенный модуль **fs** (от file system, «файловая система») — «завхоз», который
по вашей просьбе заходит в любые папки, читает, записывает и переименовывает файлы. Как и `http` из прошлой
лекции, он идёт в комплекте с Node: ничего ставить через npm не нужно. Нам хватит четырёх действий. Первое —
прочитать файл целиком:

```js
import fs from 'node:fs';
import path from 'node:path'; // пригодится в шаге 4

// 1. Прочитать файл целиком — получим строку
const текст = fs.readFileSync('notes.txt', 'utf-8');
console.log('В файле символов:', текст.length);
```

`'utf-8'` — это кодировка (помните кракозябры из лекции «CSV и данные»?). Без неё вместо строки вернулся бы
`Buffer` — набор сырых байтов, а не текст. Если файла нет, скрипт упадёт с ошибкой `ENOENT` («нет такого
файла или папки»). Второе действие — записать:

```js
// 2. Записать файл: создаст новый или ПЕРЕЗАПИШЕТ старый
fs.writeFileSync('hello.txt', 'Привет, файл!\n');

// ...или дописать в конец — так ведут журналы
fs.appendFileSync('hello.txt', 'Вторая строка\n');
```

Третье — узнать, что лежит в папке:

```js
// 3. Прочитать папку — получим массив имён
const имена = fs.readdirSync('photos');
console.log(имена); // [ 'IMG_2041.jpg', 'IMG_2042.jpg', 'IMG_2043.jpg' ]
```

Это именно имена, без пути, причём файлы и подпапки вперемешку. Порядок документация не гарантирует, поэтому,
если он важен, добавляйте `.sort()`. Четвёртое — переименовать:

```js
// 4. Переименовать (или переместить) файл
fs.renameSync(
  path.join('photos', 'IMG_2041.jpg'),
  path.join('photos', 'tovar-2041.jpg'),
);
```

`path.join` склеивает путь разделителями вашей операционной системы: в Windows это обратная косая черта, в
macOS — прямая. Тот же `renameSync` умеет и **перемещать** файл (в другую папку того же диска). И
предупреждение на будущее: если файл с новым именем уже существует, он будет заменён без вопросов и без
корзины. Все функции — в одной шпаргалке:

| Функция | Что делает | Что возвращает | Чем опасна |
| --- | --- | --- | --- |
| `readFileSync(путь, 'utf-8')` | читает файл целиком | строку | нет файла — скрипт падает с ошибкой |
| `writeFileSync(путь, текст)` | записывает текст в файл | ничего | молча затирает прежнее содержимое |
| `appendFileSync(путь, текст)` | дописывает текст в конец | ничего | файл растёт, если его не чистить |
| `readdirSync(папка)` | перечисляет имена внутри папки | массив строк | файлы и подпапки вперемешку, порядок не гарантирован |
| `renameSync(старое, новое)` | переименовывает или перемещает | ничего | молча заменяет существующий файл |
| `existsSync(путь)` | проверяет, есть ли файл или папка | true или false | — |

Заметили окончание `Sync` у всех функций? Оно означает «синхронно»: скрипт стоит и ждёт, пока операция
закончится, — как в кассе банка: пока вас не обслужили, дальше вы не идёте. В сервере такая очередь
недопустима (помните лекцию «Асинхронность и API»?), а в скрипте она — плюс: код читается сверху вниз, как
рецепт, без колбэков и `await`.

<Callout title="Почему здесь нет песочницы">
На других страницах курса код запускается прямо в браузере. Здесь так нельзя: модуль `fs` существует только
в Node, а браузер намеренно не пускает код с сайта к файлам вашего компьютера — иначе любая страница могла бы
прочитать ваши документы. Это защита, а не поломка. Поэтому скрипты этой лекции мы запускаем локально, в
терминале, а в браузерном тренажёре проверим только «чистую» функцию, которой файлы не нужны.
</Callout>

## Анатомия скрипта: сначала план, потом действие

Почти любой скрипт, который массово что-то меняет, устроен одинаково: пять шагов от «получил вход» до
«доложил результат». Самый важный из них — третий: прежде чем изменить хоть один файл, скрипт показывает
**план** — что именно он собирается сделать — и ждёт вашего решения.

<Mermaid
  title="Анатомия скрипта: от входа до отчёта с репетицией посередине"
  chart={`flowchart TD
    A["Прочитать вход:<br/>readdirSync или readFileSync"] --> B["Преобразовать:<br/>построить план в памяти"]
    B --> C["ПОКАЗАТЬ ПЛАН (dry run):<br/>было → станет"]
    C --> D["Человек смотрит план:<br/>всё верно?"]
    D -->|"нет"| E["Править скрипт:<br/>файлы остались нетронутыми"]
    E --> A
    D -->|"да — запуск с флагом --apply"| F["Выполнить:<br/>renameSync по плану"]
    F --> G["Отчёт: сделано, пропущено,<br/>ошибки и код выхода"]`}
/>

<Callout title="Dry run: репетиция перед премьерой">
**Dry run** («сухой прогон») — режим, в котором программа показывает, что сделала бы, но ничего не делает.
Аналогия — примерка: ткань режут только после того, как выкройку приложили к заказчику. Профессионалы делают
репетицию режимом по умолчанию: команда `git clean -n` перечисляет файлы, которые удалила бы, а настоящее
удаление требует отдельного флага. Правило простое: опасное действие включается явным словом, а без него
скрипт только рассказывает. Для этого в наших скриптах и придуман флаг `--apply`.
</Callout>

Второй приём — разделить «придумать» и «сделать». Функция, которая строит план, ничего не знает про диск:
ей отдали список имён, она вернула список пар «было → станет». Такую функцию безопасно запускать хоть сто
раз и легко проверять тестами (лекция «Тестирование кода»). И только отдельный маленький кусок кода берёт
готовый план и выполняет его. Если в плане что-то странное, вы увидите это глазами, пока ни один файл
ещё не изменился.

## Сквозной пример 1: переименовываем выгрузку фото

Соберём скрипт Айгерим целиком. Сохраните его как `rename-photos.js`: он принимает путь к папке и
необязательный флаг `--apply`. Без флага — показывает план, с флагом — выполняет.

```js
// rename-photos.js — IMG_2041.jpg → tovar-2041.jpg
// Только план:  node rename-photos.js photos
// Выполнить:    node rename-photos.js photos --apply
import fs from 'node:fs';
import path from 'node:path';

function fail(сообщение) {
  console.error(сообщение);
  process.exit(1);
}

// 1. Вход: путь к папке и флаг --apply (про process.argv — в разделе ниже)
const аргументы = process.argv.slice(2);
const пути = аргументы.filter((арг) => !арг.startsWith('--'));
const выполнять = аргументы.includes('--apply');

if (пути.length !== 1) {
  fail('Нужен ровно один путь к папке (с пробелами — в кавычках): node rename-photos.js "Фото товаров"');
}
const папка = пути[0];
if (!fs.existsSync(папка)) {
  fail('Папка не найдена: ' + папка);
}

// 2. Преобразование: строим план в памяти, диск не трогаем
function buildPlan(имена) {
  const занято = new Set(имена);
  const план = [];
  for (const имя of имена) {
    const найдено = /^IMG_(\d+)\.jpe?g$/i.exec(имя);
    if (!найдено) continue; // чужой или уже переименованный файл
    const новое = 'tovar-' + найдено[1] + '.jpg';
    const конфликт = занято.has(новое);
    занято.add(новое);
    план.push({ из: имя, в: новое, конфликт });
  }
  return план;
}

const план = buildPlan(fs.readdirSync(папка).sort());
if (план.length === 0) {
  console.log('Нечего переименовывать: файлов вида IMG_номер.jpg нет.');
  process.exit(0);
}

// 3. Показываем план (dry run)
console.log('План для папки "' + папка + '":');
for (const шаг of план) {
  const пометка = шаг.конфликт ? '   ПРОПУСК: имя уже занято' : '';
  console.log('  ' + шаг.из + '  ->  ' + шаг.в + пометка);
}
const безКонфликтов = план.filter((шаг) => !шаг.конфликт);
const конфликтов = план.length - безКонфликтов.length;

if (!выполнять) {
  console.log('\nЭто репетиция: файлы не тронуты. Всё верно? Добавьте флаг --apply.');
  process.exit(0);
}

// 4. Выполняем план
let готово = 0;
let ошибок = 0;
for (const шаг of безКонфликтов) {
  try {
    fs.renameSync(path.join(папка, шаг.из), path.join(папка, шаг.в));
    готово++;
  } catch (ошибка) {
    console.error('Не удалось: ' + шаг.из + ' — ' + ошибка.message);
    ошибок++;
  }
}

// 5. Отчёт и код выхода: 0 — всё чисто, 1 — нужен человек
console.log('\nПереименовано: ' + готово + ', конфликтов: ' + конфликтов + ', ошибок: ' + ошибок);
if (конфликтов > 0 || ошибок > 0) process.exit(1);
```

Разберём по частям:

- **Вход.** `process.argv.slice(2)` — слова, которые вы напечатали после `node rename-photos.js` (подробнее — в
  разделе про аргументы). Если путь не один, скрипт отказывается работать: так он ловит забытые кавычки вокруг
  пути с пробелом.
- **`fail`.** Одна функция на все аварийные выходы: пишет сообщение в поток ошибок и завершается с кодом 1
  (подробнее — в разделе про коды выхода).
- **`buildPlan`.** Чистая функция: на входе имена, на выходе план. Регулярное выражение
  `^IMG_(\d+)\.jpe?g$` с флагом `i` ищет файлы вида `IMG_цифры.jpg` или `.jpeg` в любом регистре и запоминает
  номер из скобок. Всё остальное — `notes.txt`, уже готовые `tovar-…` — пропускается: чужое скрипт не трогает.
- **`занято`.** `Set` — «список без повторов» из имён, которые уже есть в папке или уже заняты запланированными
  переименованиями. Если новое имя в нём найдено, шаг помечается конфликтом и не выполняется: тихо затереть
  чужой файл скрипт не может.
- **Выполнение и итог.** Каждое переименование — в `try/catch`: одна неудача (файл открыт в другой программе)
  не останавливает остальные, а попадает в счётчик ошибок. В конце — строка отчёта и код выхода: 0 — всё
  чисто, 1 — нужен человек.

Отдельно отметим свойство, которое делает этот скрипт безопасным: его можно запускать повторно. Файлы, уже
получившие имя `tovar-…`, не подходят под шаблон `IMG_…` и пропускаются, поэтому второй запуск ничего не
сломает и ничего не сделает. Такое свойство называется **идемпотентностью**: сколько раз ни нажимай в лифте
кнопку «5-й этаж», он поедет на пятый этаж один раз. Для скриптов, которые могут упасть на середине или попасть
в расписание, это не роскошь, а условие выживания — подробности в разделе про граничные случаи.

## Тренажёр: безопасное имя файла

В реальных выгрузках имена приходят от людей и из чужих программ: `Отчет 2026.xlsx`, `IMG 2041.JPG`,
`price*final?.csv`. Пробелы и заглавные буквы путают сайт и командную строку, а часть символов Windows не
разрешает в именах вовсе: обе косые черты, двоеточие, звёздочку, вопросительный знак, двойные кавычки, знаки
меньше и больше, вертикальную черту. Поэтому в скрипты с переименованием почти всегда входит маленькая чистая
функция, приводящая имя к безопасному виду. Напишите её сами: в ней нет ни диска, ни Node, только строки —
поэтому она работает прямо в браузере.

## Сквозной пример 2: двенадцать CSV в один отчёт

Теперь задача аналитика. В папке `data` лежат помесячные выгрузки из 1С: `sales-2026-01.csv`,
`sales-2026-02.csv` и так до декабря. Колонки — `date,product,qty,price` (дата, товар, количество, цена в
сомах). Нужен один файл с выручкой по месяцам и общим итогом, который откроется в Excel одним кликом. Вот
два файла из этой папки. Январь, `data/sales-2026-01.csv`:

```text
date,product,qty,price
2026-01-05,Кофе зерновой,2,650
2026-01-05,Чай улун,1,420
2026-01-12,Наушники,1,2500
```

Февраль, `data/sales-2026-02.csv`:

```text
date,product,qty,price
2026-02-03,Кофе зерновой,3,650
2026-02-14,Флешка 32 ГБ,2,450
```

Хорошая новость: нужные приёмы вы уже писали в лекции «CSV и данные» — разбор по строкам и запятым,
превращение «1 234,56» в число, сборку CSV обратно. Но тогда они лежали внутри одного файла, а теперь
понадобятся в нескольких скриптах. Вот зачем придуманы **модули** — ящики с инструментами: упаковываем приёмы
в `csv-tools.js` один раз, и любой скрипт достаёт их через `import`. Нашли ошибку в одном месте — починили
во всех.

```js
// csv-tools.js — приёмы из лекции «CSV и данные», упакованные в модуль
export function parseCsv(текст) {
  // BOM — невидимый символ в начале файла, его любит добавлять Excel; убираем
  const чистый = текст.replace(/^\uFEFF/, '');
  // \r?\n — перенос строки и у Windows (\r\n), и у macOS/Linux (\n); пустые строки выбрасываем
  const строки = чистый.split(/\r?\n/).filter((строка) => строка.trim() !== '');
  if (строки.length === 0) return [];
  const колонки = строки[0].split(',').map((имя) => имя.trim());
  return строки.slice(1).map((строка) => {
    const значения = строка.split(',');
    const запись = {};
    колонки.forEach((колонка, i) => {
      запись[колонка] = значения[i];
    });
    return запись;
  });
}

export function toNumber(значение) {
  // «1 234,56» → 1234.56; пустое и нечисловое вернёт NaN — и мы это заметим
  const текст = String(значение ?? '').replace(/\s/g, '').replace(',', '.');
  return текст === '' ? NaN : Number(текст);
}

export function toCsv(записи, разделитель = ',') {
  if (записи.length === 0) return '';
  const колонки = Object.keys(записи[0]);
  const строки = записи.map((запись) => колонки.map((колонка) => запись[колонка]).join(разделитель));
  return [колонки.join(разделитель), ...строки].join('\n') + '\n';
}
```

Это знакомые приёмы с заплатками «из жизни»:

- **`parseCsv`** — те же `split` и заголовок, что в лекции про CSV, плюс защита от BOM и переносов строк
  Windows (`\r\n`); пустой файл превращается в пустой массив, а не в ошибку.
- **`toNumber`** — очистка «1 234,56» до числа. Пустое значение превращает в `NaN`, а не в ноль: `Number('')`
  равно 0, и пустая ячейка тихо стала бы продажей на ноль сомов.
- **`toCsv`** — обратная сборка через `join` с выбором разделителя: Excel с русской локалью ждёт `;`.

Теперь сам отчёт. Он берёт функции из модуля, находит файлы нужного года и считает выручку каждого месяца:

```js
// report.js — сводит помесячные файлы продаж в годовой отчёт
// Запуск: node report.js 2026   (без года берётся текущий)
import fs from 'node:fs';
import path from 'node:path';
import { parseCsv, toNumber, toCsv } from './csv-tools.js';

function fail(сообщение) {
  console.error(сообщение);
  process.exit(1);
}

// 1. Год — параметр: node report.js 2026
const арг = process.argv[2];
const год = арг === undefined ? new Date().getFullYear() : Number(арг);
if (!Number.isInteger(год) || год < 2000 || год > 2100) {
  fail('Год указан неверно: "' + арг + '". Пример: node report.js 2026');
}

// 2. Находим файлы года: data/sales-2026-01.csv ... data/sales-2026-12.csv
const папкаДанных = 'data';
if (!fs.existsSync(папкаДанных)) {
  fail('Нет папки data. Запускайте скрипт из папки проекта.');
}
const шаблон = new RegExp('^sales-' + год + '-(\\d{2})\\.csv$');
const файлы = fs.readdirSync(папкаДанных).sort().filter((имя) => шаблон.test(имя));
if (файлы.length === 0) {
  fail('В папке data нет файлов sales-' + год + '-MM.csv');
}
console.log('Файлов за ' + год + ' год: ' + файлы.length + ' из 12');

// 3. Считаем выручку каждого месяца: количество × цена
const строкиОтчёта = [];
let битых = 0;
for (const файл of файлы) {
  const месяц = шаблон.exec(файл)[1];
  const текст = fs.readFileSync(path.join(папкаДанных, файл), 'utf-8');
  let сумма = 0;
  for (const запись of parseCsv(текст)) {
    const стоимость = toNumber(запись.qty) * toNumber(запись.price);
    if (Number.isNaN(стоимость)) {
      console.error('Битая строка в ' + файл + ': ' + JSON.stringify(запись));
      битых++;
      continue;
    }
    сумма += стоимость;
  }
  строкиОтчёта.push({ месяц: год + '-' + месяц, выручка: сумма });
}

// 4. Итоги на экран
const итого = строкиОтчёта.reduce((накоплено, строка) => накоплено + строка.выручка, 0);
for (const строка of строкиОтчёта) {
  console.log(строка.месяц + '  ' + строка.выручка.toLocaleString('ru-RU') + ' сом');
}
console.log('ИТОГО    ' + итого.toLocaleString('ru-RU') + ' сом');

// 5. Отчёт — в НОВЫЙ файл, исходные CSV не трогаем
fs.mkdirSync('output', { recursive: true });
const файлОтчёта = path.join('output', 'report-' + год + '.csv');
const данные = toCsv([...строкиОтчёта, { месяц: 'ИТОГО', выручка: итого }], ';');
// BOM и «;» — чтобы Excel в русской локали сразу показал таблицу без кракозябр
fs.writeFileSync(файлОтчёта, '\uFEFF' + данные, 'utf-8');
console.log('Отчёт записан: ' + файлОтчёта);

if (битых > 0) fail('Пропущено битых строк: ' + битых + '. Проверьте исходные файлы.');
```

```bash
node report.js 2026
```

```text
Файлов за 2026 год: 2 из 12
2026-01  4 220 сом
2026-02  2 850 сом
ИТОГО    7 070 сом
Отчёт записан: output/report-2026.csv
```

Проверка вручную: январь — 2 × 650 + 420 + 2 500 = 4 220 сом, февраль — 3 × 650 + 2 × 450 = 2 850 сом, вместе
7 070. Что здесь сделано «по-взрослому»:

- **Шаблон имени собирается из года.** Подходят только файлы вида `sales-2026-03.csv`; копия
  `sales-2026-03 (копия).csv` не будет засчитана дважды. В обычной строке обратный слэш удваивается — отсюда
  `\\d` вместо `\d`.
- **«2 из 12».** Дешёвая защита от потерянного файла: пропажу десяти месяцев видно сразу, а не по странно
  маленькой выручке.
- **Битые строки не прячутся.** Где количество или цена не превратились в число, строка пропускается с
  сообщением в поток ошибок, а в конце скрипт завершается с кодом 1: отчёт записан, но человеку стоит
  заглянуть в исходники.
- **Оригиналы не тронуты.** Читаем из `data`, пишем в новую папку `output`: если отчёт посчитался неверно,
  скрипт заново прогоняется по тем же файлам.

## Параметры скрипта: process.argv

Скрипт, в котором год или папка вписаны прямо в код, придётся править при каждом запуске. Гораздо удобнее
сделать их **параметрами** — словами, которые вы печатаете после имени файла: `node report.js 2026`.
Аналогия — записка, приколотая к рецепту: «на этот раз — на 2026 год». Node складывает всё напечатанное
в массив `process.argv`. Посмотрим на него глазами:

```js
// args.js
console.log(process.argv);
```

```bash
node args.js 2026 --apply "Фото товаров"
```

```text
[
  '/usr/local/bin/node',
  '/Users/aigerim/office-scripts/args.js',
  '2026',
  '--apply',
  'Фото товаров'
]
```

| Элемент | Что в нём лежит | Пример |
| --- | --- | --- |
| `process.argv[0]` | путь к программе node | `/usr/local/bin/node` |
| `process.argv[1]` | путь к вашему скрипту | `/Users/aigerim/office-scripts/args.js` |
| `process.argv[2]` и дальше | ваши слова по порядку | `'2026'`, `'--apply'` |

Отсюда идиома, которую вы видели в `rename-photos.js`: `process.argv.slice(2)` отбрасывает первые два
элемента и оставляет только ваши слова. И два правила. Первое: **все аргументы приходят строками** — `'2026'`
это не число 2026, поэтому его превращают через `Number`. Второе: **входу нельзя доверять**. Человек или
планировщик может не передать год, написать «двадцать шестой» или вообще оставить пустую строку. Вот как
`report.js` встречает разные запуски:

| Запуск | `process.argv[2]` | Что делает скрипт |
| --- | --- | --- |
| `node report.js` | `undefined` | берёт текущий год |
| `node report.js 2026` | `'2026'` | считает 2026 год |
| `node report.js abc` | `'abc'` | `Number` даёт `NaN` — ошибка, код 1 |
| `node report.js 20.5` | `'20.5'` | число не целое — ошибка, код 1 |
| `node report.js ""` | `''` | `Number('')` равно 0, вне диапазона — ошибка, код 1 |

Слова с двумя дефисами вроде `--apply` — просто договорённость: мы решили считать их «переключателями», а
`аргументы.includes('--apply')` проверяет, есть ли такое слово. Когда параметров станет много, в Node есть
готовый разборщик `parseArgs` (модуль `node:util`).

И ещё одно понятие — **рабочая папка**. Относительные пути вроде `data` и `photos` отсчитываются от папки, из
которой вы запустили команду, а не от места, где лежит скрипт. Запустили из другой папки — скрипт не найдёт
`data`; поэтому в `report.js` стоит проверка с понятным сообщением, а планировщику рабочую папку приходится
указывать отдельно (см. ниже).

## Коды выхода и console.error

Когда скрипт запускает человек, он читает сообщения на экране. Но когда скрипт запускает другая программа —
`npm`, планировщик, коллега одной командой с `&&` — читать некому. Для таких случаев у каждой программы есть
**код выхода** (exit code): число, которое она отдаёт операционной системе при завершении. Договорённость
во всём мире одна: **0 — всё хорошо, любое другое число — что-то пошло не так**. Аналогия — справка о
выполнении работы: «принято» или «не принято».

```js
console.log('Отчёт готов');          // обычный вывод
console.error('Нет папки data');     // сообщение об ошибке
process.exit(1);                     // завершить скрипт с кодом 1
```

Заметьте, что для ошибок мы берём `console.error`, а не `console.log`. У программы две «трубы»:
**stdout** — для результата работы и **stderr** — для жалоб. На экране они выглядят одинаково, но их можно
развести по разным файлам: оператор перенаправления из лекции «Командная строка» умеет работать с каждой
трубой отдельно.

```bash
node report.js 2026 > report.log 2> errors.log
```

Результат уйдёт в `report.log`, а жалобы — в `errors.log`. Код выхода последней команды можно подсмотреть:

```bash
node report.js abc
echo $?
```

```text
Год указан неверно: "abc". Пример: node report.js 2026
1
```

В PowerShell код выхода печатает `echo $LASTEXITCODE`, в cmd — `echo %ERRORLEVEL%`. Тот самый `&&` из лекции
«Командная строка» смотрит именно на этот код: команда `node report.js 2026 && echo "Готово"` напечатает
«Готово» только тогда, когда скрипт завершился нулём. А если скрипт упадёт сам — скажем, `readFileSync` не
найдёт файл, — Node напечатает ошибку и тоже завершится с кодом 1 (лекция «Отладка и ошибки»). Поэтому для
ожидаемых проблем вроде неверного года мы выбираем понятную фразу и свой код, а не сырой стек вызовов:
коллеге нужно предложение, а не двадцать строк трассировки.

## Ступени автоматизации: от «руками» до «само»

Скрипт, который вы запускаете вручную, — только вторая ступень лестницы. Автоматизация растёт ступенями, и на
каждой следующей выигрыш в сомах и нервах выше. В лекции «Автоматизация рутины» вы поднимались по этой
лестнице без кода — макросами, фильтрами и формами. Скрипт умеет то, что кнопка записи макроса не умеет:
перебирать сотни файлов, принимать параметры и работать, пока вы спите.

## Кнопки для коллег: package.json scripts

Айгерим написала скрипты, и теперь её коллега Бакыт должен уметь ими пользоваться. Но помнить
`node rename-photos.js photos --apply` и порядок слов — лишний груз. В `package.json` (мы завели его ради
`"type": "module"`) есть раздел `scripts` — это **кнопки на пульте**: имя кнопки и команда, которая за ней
спрятана.

```json
{
  "name": "office-scripts",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "scripts": {
    "photos": "node rename-photos.js photos",
    "photos:apply": "node rename-photos.js photos --apply",
    "report": "node report.js"
  }
}
```

```bash
npm run photos           # только план — безопасная кнопка
npm run photos:apply     # выполнить
npm run report           # отчёт за текущий год
npm run report -- 2025   # отчёт за 2025: всё после двух дефисов уходит в скрипт
npm run                  # без имени — покажет список всех кнопок
```

Три правила хорошего пульта. Во-первых, опасную кнопку называют честно и держат отдельно от безопасной:
`photos` — репетиция, `photos:apply` — настоящее выполнение. Во-вторых, у кнопки есть бонус: `npm run` всегда
запускает команду из папки, где лежит `package.json`, поэтому пути `data` и `photos` находятся надёжно, даже
если Бакыт открыл терминал в другом месте. В-третьих, у наших скриптов нет сторонних зависимостей, так что
коллеге достаточно Node: никакого `npm install`.

## Расписание: отчёт сам собирается в 8:00 по понедельникам

Последняя ступень — убрать из цепочки человека совсем. В любой операционной системе есть **планировщик**:
программа-секретарь, которая в назначенное время запускает назначенную команду. Аналогия — будильник,
который вместо звонка запускает программу. Идея та же, что в лекции «Автоматизация рутины», только за
расписанием стоит ваш код. В macOS и Linux планировщик называется **cron**: расписание хранится в файле,
который открывается командой `crontab -e`, одна строка — одно задание. В строке пять полей времени и команда:

```text
# минута  час  день_месяца  месяц  день_недели  команда
0 8 * * 1  cd /Users/aigerim/office-scripts && /usr/local/bin/node report.js >> logs/report.log 2>&1
```

| Поле | Допустимые значения | В нашей строке |
| --- | --- | --- |
| минута | 0–59 | `0` |
| час | 0–23 | `8` |
| день месяца | 1–31 | `*` — любой |
| месяц | 1–12 | `*` — любой |
| день недели | 0–7, где 1 — понедельник | `1` |

Читается: «в 8:00 каждый понедельник зайди в папку проекта, запусти отчёт, а весь вывод допиши в файл
журнала». У cron есть четыре ловушки, на которых спотыкаются почти все:

- **cron — не ваш терминал.** У него урезанный список путей, поэтому `node` может не найтись. Пишите полный
  путь, узнать его можно командой `which node`; у вас он может отличаться от `/usr/local/bin/node`.
- **Рабочая папка — домашняя.** Поэтому в строке есть `cd` в папку проекта: без него скрипт не найдёт `data`.
- **Папка `logs` должна существовать заранее.** Иначе оболочка не сможет открыть файл журнала, и команда не
  запустится вовсе.
- **Время — системное.** На ноутбуке в Бишкеке это Asia/Bishkek (UTC+6), а облачный сервер чаще живёт по UTC:
  «8:00 по Бишкеку» там записывается как 2:00.

В Windows то же делает **Планировщик заданий**: Пуск → «Планировщик заданий» → «Создать простую задачу». Дальше
мастер задаёт те же вопросы по порядку:

1. Имя: «Отчёт продаж». Триггер: «Еженедельно», понедельник, 08:00.
2. Действие: «Запустить программу».
3. Поле «Программа или сценарий»: `cmd` (так вывод можно отправить в журнал).
4. Поле «Добавить аргументы»: строка из блока ниже.
5. Поле «Рабочая папка»: `C:\office-scripts` — самое важное поле: без него относительные пути не найдутся,
   потому что по умолчанию задача стартует в системной папке.

```text
/c node report.js >> logs\report.log 2>&1
```

Компьютер должен быть включён в 8:00, поэтому такие скрипты надёжнее держать на постоянно работающей машине
или сервере. И помните: в расписание ставят уже проверенную команду, а репетиции с подтверждением человеком в
режиме «без присмотра» никто не увидит — поэтому нужны остальные защиты, о них следующий раздел.

<BusinessNote>
Каждый понедельник аналитик отдела продаж тратил полтора часа: собрать выгрузки из 1С, свести в таблицу,
проверить итоги. При ставке около 340 сом в час это 510 сом в неделю — примерно 26 500 сом в год на
человека. Скрипт плюс строка в планировщике делают то же самое к 8:00, пока аналитик ещё едет на работу: на
экране готовый файл, а полтора часа уходят на то, что требует головы, — выяснить, почему просела выручка в
Оше. Настройка занимает один вечер. Но обратите внимание на цену ошибки: тот же скрипт, молча падающий
месяц подряд, обходится дороже сэкономленного, — поэтому следующий раздел не менее важен, чем все
предыдущие.
</BusinessNote>

## Границы ответственности скрипта

Скрипт — исполнитель, который делает ровно то, что написано, и ни разу не переспросит. Человек на месте
Айгерим засомневался бы: «Что-то файлов слишком много». Скрипт не засомневается никогда. Поэтому осторожность
приходится вшивать в сам код. Шесть правил профессионала:

| Правило | Что значит на практике | Где это уже есть |
| --- | --- | --- |
| Оригиналы не трогаем | читаем из одной папки, результат пишем в другую | `report.js`: читает `data`, пишет в `output` |
| Бэкап перед массовой операцией | копия папки до первого изменения | добавим ниже |
| Сначала план, потом действие | по умолчанию репетиция, опасное — по флагу | флаг `--apply` |
| Повторный запуск безопасен | уже сделанное пропускаем | шаблон `^IMG_` в `buildPlan` |
| Ничего не затираем молча | занятое имя — пропуск, а не замена | множество `занято` |
| Пишем журнал | что, когда и с каким результатом сделано | раздел про граничные случаи |

<Callout title="Оригиналы — священны">
Исходные выгрузки из 1С и банка — первичные данные: если скрипт «заодно подправил» оригиналы, проверять его
уже не на чем. Поэтому читаем из `data`, результат пишем в новую папку `output`, а программа, которой
всё-таки разрешено менять оригиналы (как наш переименователь), обязана сначала сделать копию.
</Callout>

Бэкап — это запасной ключ от квартиры: пока дверь открывается, он лежит без дела, но в тот день, когда
замок заклинит, окупает себя целиком. Копию папки можно сделать командой терминала до запуска скрипта:

```bash
cp -r photos photos-backup                  # macOS и Linux
Copy-Item photos photos-backup -Recurse     # PowerShell
```

А можно вшить страховку в сам `rename-photos.js` — этот фрагмент вставляется сразу после блока с проверкой
флага `выполнять`, перед шагом 4, поэтому копия создаётся только при настоящем запуске, а не на репетиции:

```js
// страховка перед массовой операцией
const копия = папка + '-backup';
if (fs.existsSync(копия)) {
  fail('Копия ' + копия + ' уже есть. Уберите её вручную: затирать бэкап скрипт не станет.');
}
fs.cpSync(папка, копия, { recursive: true });
console.log('Копия папки создана: ' + копия);
```

`cpSync` стабилен в Node 22 и новее. Обратите внимание на первую проверку: скрипт, затирающий собственный
бэкап, — бэкап только по названию. А чтобы откатиться и без полной копии, внутри цикла после `renameSync`
дописывайте строку в журнал «было → стало» — он станет «чёрным ящиком» вашего скрипта, как самописец в самолёте:

```js
fs.appendFileSync('rename-log.txt', шаг.из + ' => ' + шаг.в + '\n');
```

Гигабайт диска стоит несколько сомов, час ручного восстановления — около 340. Арифметика бэкапа всегда в
его пользу.

## Практика: сделай руками и проверь себя

Напоминание: скрипты мы запускаем локально — в браузерной песочнице модуль `fs` не работает. Вам понадобятся
Node, терминал и любой текстовый редактор (VS Code, Sublime, даже Блокнот — сохраняйте в кодировке UTF-8).
Команды даны для bash/zsh и PowerShell; для cmd отличия указаны в скобках.

### Шаг 1. Готовим рабочее место

Создайте рабочую папку и перейдите в неё:

```bash
mkdir office-scripts
cd office-scripts
pwd
```

**Ожидаемо:** `pwd` печатает путь, который заканчивается на `office-scripts` (в cmd вместо `pwd` — `cd` без
аргументов). Теперь в редакторе создайте в этой папке файл `package.json` с той же единственной строкой, что
в начале лекции (настройка type со значением module). В Блокноте при сохранении выберите тип файла «Все
файлы», иначе к имени припишется `.txt`. Затем создайте тестовую папку с тремя «фото» — на самом деле это
крошечные текстовые файлы, скрипту всё равно: он смотрит на имена, а не на содержимое:

```bash
mkdir test-photos
cd test-photos
echo foto > IMG_2041.jpg
echo foto > IMG_2042.jpg
echo foto > IMG_2043.jpg
cd ..
ls test-photos
```

**Ожидаемо:** `ls` (в cmd — `dir test-photos`) показывает три файла: `IMG_2041.jpg`, `IMG_2042.jpg`,
`IMG_2043.jpg`. Последний подготовительный шаг: сохраните скрипт `rename-photos.js` из лекции в папке
`office-scripts` — рядом с `package.json`, а не внутри `test-photos`.

### Шаг 2. Репетиция: смотрим план

```bash
node rename-photos.js test-photos
```

**Ожидаемо:**

```text
План для папки "test-photos":
  IMG_2041.jpg  ->  tovar-2041.jpg
  IMG_2042.jpg  ->  tovar-2042.jpg
  IMG_2043.jpg  ->  tovar-2043.jpg

Это репетиция: файлы не тронуты. Всё верно? Добавьте флаг --apply.
```

Проверьте, что репетиция действительно ничего не изменила: `ls test-photos`. **Ожидаемо:** по-прежнему три
файла `IMG_…`. Именно так выглядит безопасная привычка: сначала смотрим, потом решаем.

### Шаг 3. Выполняем и проверяем результат

```bash
node rename-photos.js test-photos --apply
ls test-photos
```

**Ожидаемо:** тот же план, что и в репетиции, а под ним строка итога `Переименовано: 3, конфликтов: 0, ошибок: 0`.
Команда `ls` показывает уже новые имена: `tovar-2041.jpg`, `tovar-2042.jpg`, `tovar-2043.jpg`. Теперь проверьте
идемпотентность: повторите ту же команду с `--apply`. **Ожидаемо:** одна строка
`Нечего переименовывать: файлов вида IMG_номер.jpg нет.` — повторный запуск ничего не сломал.

### Шаг 4. Проверяем защиту

Подстроим конфликт: новый снимок, номер которого уже занят.

```bash
cd test-photos
echo foto > IMG_2044.jpg
echo foto > tovar-2044.jpg
cd ..
node rename-photos.js test-photos --apply
echo $?
```

**Ожидаемо:** скрипт отказывается затирать и честно говорит об этом, а код выхода равен 1 (в PowerShell
код печатает `echo $LASTEXITCODE`, в cmd — `echo %ERRORLEVEL%`). Проверьте через `ls test-photos`: оба файла,
`IMG_2044.jpg` и `tovar-2044.jpg`, на месте.

```text
План для папки "test-photos":
  IMG_2044.jpg  ->  tovar-2044.jpg   ПРОПУСК: имя уже занято

Переименовано: 0, конфликтов: 1, ошибок: 0
1
```

Теперь забудьте кавычки у пути с пробелом — самая частая ошибка новичков:

```bash
mkdir "Фото товаров"
node rename-photos.js Фото товаров
node rename-photos.js "Фото товаров"
```

**Ожидаемо:** первая команда печатает `Нужен ровно один путь к папке (с пробелами — в кавычках)…` и завершается с
кодом 1: терминал разрезал имя на два слова. Вторая находит пустую папку и отвечает
`Нечего переименовывать: файлов вида IMG_номер.jpg нет.`

### Шаг 5 (бонус). Годовой отчёт и кнопки

Сохраните `csv-tools.js` и `report.js` из лекции, создайте папку `data` с двумя файлами из лекции и запустите
`node report.js 2026`, а затем `node report.js abc`. **Ожидаемо:** первая команда печатает пять строк (от «2 из 12»
до «Отчёт записан») с итогом 7 070 сом, вторая — `Год указан неверно: "abc". Пример: node report.js 2026`.
Добавьте в `package.json` раздел `scripts` из лекции и нажмите кнопку: `npm run report -- 2026`. **Ожидаемо:**
npm печатает две служебные строки с командой, а затем тот же отчёт.

**Самопроверка: типичные сбои.**

- `Cannot use import statement outside a module` — рядом со скриптом нет `package.json` с `"type": "module"`
  или команда запущена из другой папки.
- `Cannot find module` — вы не в той папке (проверьте `pwd`) либо файл сохранился как `rename-photos.js.txt`:
  Windows по умолчанию прячет расширения, включите их показ в проводнике.
- `Папка не найдена: test-photos` — скрипт запущен изнутри `test-photos`; выйдите на уровень выше: `cd ..`.
- Репетиция повторяется снова и снова — опечатка во флаге: слово вроде `--aplly` скрипт тихо принимает за
  неизвестное и просто показывает план.

## Граничные случаи: где всё ломается

- **1. Запустили без репетиции и без бэкапа — исходные имена потеряны.** Ситуация: в шаблоне скрипта
  опечатка — вместо номера из имени подставляется порядковый номер файла, а Айгерим не сделала ни репетиции,
  ни копии папки. Что происходит: за секунду 300 снимков получают имена `tovar-1.jpg`, `tovar-2.jpg` и так
  далее, а номера из `IMG_2041`, по которым фотограф и менеджер сверялись с прайс-листом, исчезают; отменить
  переименование нечем. Почему: `renameSync` — необратимый вызов операционной системы, а скрипт выполнил план,
  которого никто не видел. Как правильно: репетиция по умолчанию (опечатка видна глазами — в плане стоит
  `tovar-1.jpg` вместо `tovar-2041.jpg`), копия папки перед `--apply` и журнал «было → стало». Две минуты на
  репетицию — ничто рядом с 75 минутами ручного восстановления (300 снимков по 15 секунд, около 425 сом),
  и то лишь если сопоставить снимки с товарами вообще возможно.
- **2. Скрипт упал на середине.** Ситуация: на 187-м файле из 300 `renameSync` бросает ошибку — файл как раз
  открыт в другой программе (в Windows так бывает постоянно) или закончилось место на диске. Что происходит:
  половина файлов уже называется `tovar-…`, половина — всё ещё `IMG_…`. Если скрипт написан «в лоб» (счётчик с
  единицы: `tovar-1`, `tovar-2`, …), повторный запуск начнёт с начала, наткнётся на уже существующие имена и
  перезапишет готовые файлы или перепутает номера. Почему: такой скрипт считает, что каждый запуск начинается с
  чистого листа, а мир уже изменился. Как правильно: идемпотентность — план каждый раз строится по текущему
  состоянию папки. Наш `buildPlan` сам пропускает всё, что уже названо `tovar-…`, поэтому повторный запуск
  просто доделывает остаток. Плюс `try/catch` вокруг каждого файла, чтобы одна неудача не обрывала остальных, и
  код выхода 1, чтобы о проблеме узнал не только тот, кто смотрел на экран.
- **3. Файл с таким именем уже существует.** Ситуация: в папке лежат `IMG_2044.jpg` и `tovar-2044.jpg` от
  прошлой партии. Что происходит: наивный `renameSync` молча заменяет существующий файл — прошлая партия
  исчезла, без ошибки, без вопроса и без корзины. То же делает `writeFileSync` с существующим файлом. Почему:
  операционная система по умолчанию трактует переименование «в занятое имя» как замену; корзина — свойство
  проводника, а не программного вызова. Как правильно: проверять занятость на этапе плана (наше множество
  `занято`: пометка ПРОПУСК и код выхода 1) и, если пишете файл, просить Node отказаться при совпадении: у
  `writeFileSync` есть параметр flag со значением `'wx'` («писать, только если файла ещё нет») — при
  совпадении он бросит ошибку `EEXIST` вместо тихой перезаписи.
- **4. Кириллица и пробелы в путях.** Ситуация: папка называется «Фото товаров», а команда напечатана так:
  `node rename-photos.js Фото товаров`. Что происходит: терминал режет строку по пробелу, скрипт получает два
  слова. Наш скрипт отказывается работать, а наивный, читающий только `process.argv[2]`, возьмёт слово
  «Фото» — получит «папка не найдена» или, что хуже, обнаружит другую папку «Фото» и переименует там.
  Почему: пробел — разделитель аргументов, как в лекции «Командная строка». Как правильно: всегда брать путь с
  пробелами в кавычки, а в `package.json` экранировать их обратным слэшем:
  `"photos": "node rename-photos.js \"Фото товаров\""`. И помните про Windows: в строке JavaScript обратный
  слэш — служебный символ, поэтому в путях пишите прямые слэши (Node понимает их и в Windows) или
  удваивайте обратные: `'C:\\office-scripts\\photos'`.
- **5. Скрипт по расписанию месяц писал ошибки «в никуда».** Ситуация: cron запускает `report.js` каждый
  понедельник; в марте на сервере поменяли права на папку `data`, и скрипт начал падать. Что происходит: у
  запуска по расписанию нет экрана, `console.error` печатает в пустоту, отчёта нет, ошибки никто не видит —
  пока директор через месяц не спросит, где цифры. Почему: планировщик по умолчанию выбрасывает вывод, а о
  ненулевом коде выхода никого не извещает. Как правильно: направлять вывод в файл журнала (так же, как в
  разделе про расписание — и в cron, и в Планировщике Windows) или писать журнал из самого скрипта — с
  временем по Asia/Bishkek, иначе при разборе вы не поймёте, когда это случилось, — и хотя бы раз в неделю
  заглядывать в этот «чёрный ящик».

Вот как выглядит журнал, который пишет сам скрипт. Оберните тело скрипта в функцию `main` и ловите её падения:

```js
// logger.js — пишет сообщение и на экран, и в файл logs/report.log
import fs from 'node:fs';

export function log(сообщение) {
  const время = new Date().toLocaleString('ru-RU', { timeZone: 'Asia/Bishkek' });
  fs.mkdirSync('logs', { recursive: true });
  fs.appendFileSync('logs/report.log', время + '  ' + сообщение + '\n');
  console.log(сообщение);
}
```

```js
// в report.js
try {
  main(); // вся работа скрипта
} catch (ошибка) {
  log('ОШИБКА: ' + ошибка.message);
  process.exit(1);
}
```
