## Введение

Как одним движением проверить, что введён телефон, а не абракадабра? Или вытащить все суммы из
длинного лога платежей? Для этого есть **регулярные выражения** (regex) — компактный язык описания
текстовых шаблонов. Выглядит поначалу как «кот прошёл по клавиатуре», но принцип простой: вы
описываете не конкретный текст, а его **форму** — «плюс, три цифры, потом ещё девять цифр». Это как
трафарет: прикладываете к тексту, и всё, что совпало с вырезом, — ваше.

<BusinessNote>
Реальная задача из жизни бишкекской компании: в CRM накопилось 12 000 телефонов клиентов в шести
разных форматах — «+996 700 12-34-56», «0700123456», «(0555) 66 77 88» и так далее. SMS-рассылка
принимает только один формат. Оператор чистит вручную около 500 строк в час — это 24 часа, три
рабочих дня и, при ставке 280 сом/час, примерно 6 700 сом только зарплаты, не считая ошибок от
усталости. Одна регулярка с заменой делает то же самое за 20 минут вместе с проверкой результата.
Regex — это суперспособность аналитика: чистка «грязных» данных за минуты, а не за дни.
</BusinessNote>

**Что вы узнаете:**

- как описать шаблон текста из кирпичиков: классы символов, квантификаторы, якоря и экранирование
- как флаги переключают режим поиска, например игнорируют регистр или ищут все совпадения
- какие пять методов JavaScript проверяют, находят и заменяют текст по шаблону
- как группы захвата вытаскивают из совпадения нужные куски
- какие готовые шаблоны пригодятся для телефонов и дат и где ещё живут регулярки
- где регулярки ломаются на граничных случаях и как это проверить

## Идея: шаблон, а не точный текст

Обычный поиск (Ctrl+F) ищет точную строку. Регулярка описывает **шаблон**: «три цифры, потом дефис,
потом ещё цифры». Всё, что подходит под шаблон, — совпадение. Строят шаблон из кирпичиков.

### Спецсимволы для «класса» символов

| Кусочек | Что означает |
| --- | --- |
| `.` | любой символ |
| `\d` | цифра (0–9) |
| `\w` | буква латиницы, цифра или подчёркивание |
| `\s` | пробел, таб, перенос строки |
| `[abc]` | один из перечисленных: a, b или c |
| `[a-z]` | любая буква от a до z (диапазон) |
| `[^abc]` | любой символ, КРОМЕ a, b, c |

Полезное правило: **заглавная буква — это отрицание**. `\D` — любой НЕ-цифровой символ, `\W` — не
буква и не цифра, `\S` — не пробел. Запомните `\D`: именно им чистят телефоны от скобок и дефисов.

### Сколько раз — квантификаторы

**Квантификатор** — знак после кирпичика, который говорит, сколько раз он повторяется (от латинского
quantum — «сколько»).

| Кусочек | Сколько повторов |
| --- | --- |
| `+` | один или больше |
| `*` | ноль или больше |
| `?` | ноль или один (необязательный) |
| `{3}` | ровно 3 |
| `{2,4}` | от 2 до 4 |

### Якоря

`^` — начало строки, `$` — конец. Они важны для проверки «вся строка целиком»: шаблон `\d+` найдёт
цифры где угодно внутри, а `^\d+$` требует, чтобы **вся** строка состояла только из цифр.

<Callout title="Пример по кусочкам">
Шаблон `^\d{3}-\d{2}$` читается так: начало строки → ровно 3 цифры → дефис → ровно 2 цифры → конец.
Подойдёт `123-45`, но не `12-345` и не `123-456`. Собирая такие кирпичики, вы описываете почти любой
формат: `^\+996\d{9}$` — это уже готовая проверка кыргызстанского номера в международном формате.
</Callout>

### Экранирование: как найти настоящую точку

Точка, плюс, звёздочка, скобки — это спецсимволы со своими значениями. А если нужно найти именно
точку? Ставим перед ней обратный слэш — это называется **экранирование** (как экран, который
прикрывает спецзначение символа и оставляет его «просто буквой»):

```js
/2.500/.test('2.500'); // true
/2.500/.test('2x500'); // тоже true! Точка = «любой символ»
/2\.500/.test('2x500'); // false — теперь ищем именно точку
/2\.500/.test('2.500'); // true
```

Классическая ошибка новичка: проверять цену `2500.50` шаблоном `\d+.\d{2}` и удивляться, что
проходит строка `2500x50`. Экранировать нужно: `. + * ? ( ) [ ] { } ^ $ \` и вертикальную черту.

### Альтернация: или то, или это

Вертикальная черта — логическое ИЛИ между вариантами:

```js
/Бишкек|Ош|Каракол/.test('Доставка: Ош'); // true

// Скобки ограничивают, к чему относится ИЛИ:
/\.(kg|com|org)$/.test('shop.kg');  // true — домен в зоне kg, com или org
/\.(kg|com|org)$/.test('shop.net'); // false
```

Без скобок шаблон `^сом|доллар$` читается как «строка начинается с „сом“ ИЛИ заканчивается на
„доллар“» — почти никогда не то, что вы имели в виду. Со скобками `^(сом|доллар)$` — «вся строка
равна одному из двух слов».

## Флаги: переключатели режима поиска

**Флаг** — буква после закрывающего слэша регулярки, которая меняет режим всего поиска:

| Флаг | Название | Что меняет |
| --- | --- | --- |
| `g` | global | найти ВСЕ совпадения, а не только первое |
| `i` | ignore case | не различать большие и маленькие буквы |
| `m` | multiline | якоря `^` и `$` срабатывают в каждой строке текста, а не один раз |

```js
'сом СОМ Сом'.match(/сом/);   // ['сом'] — одно совпадение
'сом СОМ Сом'.match(/сом/g);  // ['сом'] — g есть, но регистр разный
'сом СОМ Сом'.match(/сом/gi); // ['сом', 'СОМ', 'Сом'] — все три

// Флаг m: ищем упавшие запросы в многострочном логе
const log = 'ok 200\nfail 500\nok 200';
log.match(/^fail.*$/m); // ['fail 500'] — ^ сработал на начале СТРОКИ лога
```

Без флага `g` невозможно «найти все суммы в тексте» — вернётся только первая. Это самая частая
причина вопроса «почему регулярка нашла только одно число?».

## Регулярки в JavaScript: пять методов

Сам по себе шаблон ничего не делает — его применяют методами. Вот рабочий минимум:

| Метод | Что возвращает | Когда брать |
| --- | --- | --- |
| `regex.test(str)` | true или false | проверка «подходит или нет» |
| `str.match(regex)` | массив совпадений или null | вытащить найденное |
| `str.matchAll(regex)` | перебор совпадений с группами | всё найденное + куски каждого |
| `str.replace(regex, замена)` | новая строка | почистить, переформатировать |
| `str.split(regex)` | массив кусков | разрезать по сложному разделителю |

```js
// test — проверка формата
/^\+996\d{9}$/.test('+996700123456'); // true

// match с флагом g — все совпадения
'Заказ 152: 2500 сом, доставка 300 сом'.match(/\d+/g);
// ['152', '2500', '300'] — массив СТРОК, не чисел!

// replace — замена всех совпадений (обязательно с g)
'+996 (700) 12-34-56'.replace(/\D/g, '');
// '996700123456' — выкинули всё, что не цифра

// split — разрезать по «точка с запятой ИЛИ запятая, потом пробелы»
'Бишкек; Ош, Каракол'.split(/[;,]\s*/);
// ['Бишкек', 'Ош', 'Каракол']
```

<Callout title="Ловушка: match возвращает null">
Если совпадений нет, `match` возвращает не пустой массив, а `null` — и попытка тут же вызвать
`.map()` уронит программу с ошибкой. Защитный приём — запасной пустой массив:
`const nums = (text.match(/\d+/g) || []).map(Number);` Теперь при любом тексте получится массив,
пусть и пустой. Это граничный случай, который обязан быть в ваших тестах.
</Callout>

## Группы захвата: вытащить куски совпадения

Круглые скобки в шаблоне — не только границы для ИЛИ. Это **группы захвата**: они запоминают, что
именно совпало внутри скобок, и позволяют этим пользоваться. Как маркер в договоре: вы не просто
нашли абзац, а выделили в нём сумму и дату.

```js
// Дата в формате ДД.ММ.ГГГГ: три группы
'17.08.2026'.match(/(\d{2})\.(\d{2})\.(\d{4})/);
// ['17.08.2026', '17', '08', '2026', ...]
//  всё совпадение, группа 1, группа 2, группа 3

// В replace группы доступны как $1, $2, $3 — меняем формат даты:
'Отчёт за 17.08.2026'.replace(/(\d{2})\.(\d{2})\.(\d{4})/, '$3-$2-$1');
// 'Отчёт за 2026-08-17' — готово для сортировки и Google Sheets
```

А `matchAll` перебирает все совпадения вместе с их группами — так вытаскивают данные из логов:

```js
const log = 'оплата 2500 сом; возврат 300 сом; оплата 1200 сом';
for (const m of log.matchAll(/(\d+) сом/g)) {
  console.log(m[1]); // '2500', '300', '1200' — только числа, без слова «сом»
}
```

<Callout title="Осторожно: \w не знает кириллицы">
`\w` — это только латиница, цифры и подчёркивание. Шаблон `/^\w+$/` примет `report`, но отвергнет
`отчёт`! Для русских букв используйте диапазон `[а-яё]` (с флагом `i` он покроет и заглавные):
`'сумма 2500 сом'.match(/[а-яё]+/gi)` вернёт `['сумма', 'сом']`. Это регулярно ловит новичков,
проверяющих ФИО или названия городов.
</Callout>

<Callout title="Жадный захват: почему .* берёт слишком много">
Квантификаторы жадные: захватывают максимум возможного. Шаблон `/«.*»/` в строке с двумя цитатами
`«ош», потом «бишкек»` совпадёт со ВСЕМ куском от первой « до последней » — включая текст между
цитатами. Ленивая версия `.*?` (знак вопроса после звёздочки) останавливается на первом же
подходящем месте и вернёт только `«ош»`. Правило: вытаскиваете что-то «между скобками/кавычками» —
почти всегда нужен ленивый вариант.
</Callout>

## Готовые шаблоны для работы

Шпаргалка под типовые задачи аналитика в КР — можно копировать в свой код:

| Задача | Шаблон | Комментарий |
| --- | --- | --- |
| Телефон КР, международный | `^\+996\d{9}$` | плюс, код 996, ровно 9 цифр |
| Телефон КР, местный | `^0\d{9}$` | ноль и 9 цифр: 0700123456 |
| Дата ДД.ММ.ГГГГ | `^\d{2}\.\d{2}\.\d{4}$` | точки экранированы! |
| Все числа из текста | `\d+` с флагом `g` | match может вернуть null |
| Сумма с тыйынами | `^\d+\.\d{2}$` | 2500.50 — сомы точка тыйыны |
| ИНН КР | `^\d{14}$` | у налогоплательщика КР 14 цифр |
| Email, грубая проверка | `.+@.+\..+` | фильтр от мусора, не гарантия |

<Callout title="Не гонитесь за идеалом">
«Правильная» регулярка для email по стандарту — чудовищная строка на несколько строк. На практике
берут простую и достаточную (`.+@.+\..+` — «что-то, собака, что-то, точка, что-то») и дополняют
проверкой на сервере: письмом со ссылкой подтверждения. Регулярка — фильтр от явного мусора, а не
абсолютная истина. Заметьте: шаблон даты выше пропустит и `99.99.9999` — проверку «а бывает ли
39 февраля» регулярке не поручают, это работа обычного кода с условиями.
</Callout>

<BusinessNote>
Ещё один денежный кейс. Маркетплейс в Бишкеке сверяет выгрузку платёжного шлюза (8 000 строк текста
вида «2026-08-15 14:32 оплата заказа 8821: 3 450 сом OK») с банковской выпиской. Вручную такая
сверка не делается вообще. Аналитик регуляркой `(\d+) сом` через `matchAll` вытащил все суммы за
10 минут, сравнил итоги и нашёл расхождение: 37 платежей на 214 000 сом зависли в статусе «OK» у
шлюза, но не дошли до счёта. Без этой сверки компания заметила бы недостачу только в конце квартала.
</BusinessNote>

## Где ещё живут регулярки

Синтаксис, который вы учите здесь, почти без изменений работает во всех инструментах аналитика:

- **Google Sheets** — функции `REGEXMATCH`, `REGEXEXTRACT`, `REGEXREPLACE`. Вытащить сумму из
  столбца с текстом: `REGEXEXTRACT(A2; "\d+")`. Классический Excel регулярки из коробки не умеет —
  и это частая причина перейти в Sheets для чистки данных.
- **VS Code и любой редактор кода** — в поиске Ctrl+F включите кнопку `.*`, и можно искать и
  заменять по шаблону сразу в сотне файлов.
- **SQL** — PostgreSQL и MySQL умеют фильтровать строки по регулярке в WHERE.
- **Командная строка** — утилита `grep` ищет по шаблону в файлах и логах сервера.

Выучили один раз — пользуетесь везде.

## Практика

### Разминка в консоли браузера

Проверьте регулярки вживую, без всяких установок:

1. Откройте DevTools: клавиша F12 (на Mac — Cmd+Option+I), вкладка Console.
2. Введите `'Итого: 4500 сом, доставка 300 сом'.match(/\d+/g)` и нажмите Enter.
   Вы должны увидеть массив `['4500', '300']`.
3. Введите `'+996 (700) 12-34-56'.replace(/\D/g, '')` — должно получиться `'996700123456'`.
4. Введите `/^\+996\d{9}$/.test('996700123456')` — получите `false`. Почему? В строке нет плюса,
   а шаблон требует его первым символом. Добавьте плюс в строку и убедитесь, что стало `true`.
5. Введите `'нет чисел'.match(/\d+/g)` — увидите `null`, а не пустой массив. Та самая ловушка.

Связка последних двух задач — готовый рабочий процесс: сначала `cleanPhone` приводит грязный ввод
к цифрам, потом добавляете код страны и проверяете результат через `isKgPhone`. Именно так устроена
обработка телефонов в реальных формах заказа.

## Граничные случаи: где всё ломается

- **Пустая строка.** `/^\d+$/.test('')` — `false`, потому что `+` требует хотя бы одну цифру. А вот
  `/^\d*$/.test('')` — уже `true`: звёздочка допускает ноль повторов. Перед сдачей проверки формы
  всегда тестируйте именно пустой ввод — это самый частый пропуск в валидации на защите проекта.
- **match без совпадений возвращает `null`, а не `[]`.** `'нет чисел'.match(/\d+/g)` — `null`.
  Код вида `text.match(/\d+/g).map(Number)` упадёт с ошибкой `Cannot read properties of null` в
  проде, как только придёт текст без цифр. Лечится защитой `(text.match(/\d+/g) || [])`.
  Обратите внимание: `matchAll` в этом смысле безопаснее — на пустой результат он просто не
  вернёт итераций, без `null`.
- **Жадный квантификатор на строке с несколькими совпадениями.** `/«.*»/` на тексте
  `«Ош», отчёт, «Бишкек»` захватывает всё от первой « до последней » целиком, включая «отчёт»
  между ними — потому что `.*` по умолчанию берёт максимум. Без ленивого `.*?` парсер вместо
  одной цитаты вернёт весь кусок текста.
- **Незаэкранированная точка в цене.** Шаблон `\d+.\d{2}` для суммы «2500.50» пропустит и мусор
  «2500x50», потому что `.` без слэша значит «любой символ». Разница в одном символе (`\.` вместо
  `.`) — а на выходе валидатор либо ловит опечатки клиента, либо молча их принимает.
