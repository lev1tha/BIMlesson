Откройте любой интернет-магазин и наберите что-нибудь в поле поиска на странице каталога. Список
товаров меняется на лету — без перезагрузки страницы и без похода на сервер за новым HTML-файлом.
Нажмите «Добавить в корзину» — цифра в углу экрана обновилась мгновенно. Ничего мистического: браузер
хранит страницу не как текст, а как дерево объектов в памяти, и JavaScript умеет находить в этом
дереве нужные узлы, менять им текст и внешний вид, добавлять новые узлы и реагировать на действия
человека — клик, набор текста, отправку формы. Это дерево называется **DOM**, и вся эта лекция — про
то, как с ним работать.

<BusinessNote>
Любой интерфейс, который аналитик показывает руководству, — фильтр в отчёте, обновляющийся дашборд,
форма заявки на сайте — устроен по одной схеме: данные (из API, из выгрузки, введённые пользователем)
превращаются в элементы на странице и оживают через события. Именно эту работу и выполняет DOM.
Интернет-магазин в Бишкеке, который заменил перезагрузку страницы при каждом клике по фильтру на
мгновенный отклик прямо в браузере, ускоряет путь от «зашёл» до «оформил заказ» на секунды — а по
отраслевым оценкам, лишняя секунда ожидания на странице способна снизить конверсию на несколько
процентов. Понимать DOM — значит понимать, из чего вообще состоит любой сайт и любая веб-панель,
с которой работает бизнес.
</BusinessNote>

## Что такое DOM: дерево, а не текст

**DOM** (Document Object Model, «объектная модель документа») — это то, во что браузер превращает
HTML-файл, прежде чем показать его на экране. Сам HTML-файл — просто текст на диске: последовательность
тегов и символов. Но браузеру с этим текстом нужно работать — находить элементы, менять их, реагировать
на клики, — поэтому первым делом он разбирает (**парсит**) файл и строит из него дерево объектов в
памяти компьютера. Каждый тег становится отдельным **узлом** (node) этого дерева, а вложенность тегов
друг в друга превращается во вложенность «родитель — потомок».

Хорошая аналогия — чертёж и дом. HTML-файл — это чертёж: плоский, статичный, сам по себе ничего не
делает. DOM — это уже построенный по чертежу дом, где можно переставить мебель (поменять текст),
перекрасить стену (поменять класс) или пристроить комнату (добавить новый элемент), не трогая исходную
бумагу. Когда JavaScript что-то меняет на странице, он меняет именно дом, а не чертёж на сервере:
исходный HTML-файл остаётся прежним, что бы ни происходило в браузере.

<Callout title="Чертёж и дом — разные вещи">
Если открыть просмотр исходного кода страницы (`view-source:`), браузер покажет HTML-файл ровно таким,
каким он пришёл с сервера, — чертёж. Если открыть вкладку «Elements» («Элементы») в инструментах
разработчика (клавиша F12), браузер покажет текущий DOM — со всеми изменениями, которые уже сделал
JavaScript. На современных сайтах, где почти всё дорисовывается скриптами уже после загрузки, эти две
картинки могут отличаться очень сильно — и это нормально.
</Callout>

Верхний узел дерева всегда один — тег `html`. Обратиться ко всему дереву целиком можно через глобальный
объект `document`: это входная точка, с которой начинается практически любой поиск и любое изменение
страницы. Дальше в этой лекции `document` встретится в первой же строчке кода.

## Ищем элементы: querySelector и querySelectorAll

Чтобы что-то поменять на странице, сначала нужно найти нужный узел дерева. Для этого есть два метода
объекта `document`, и оба принимают **тот же синтаксис селекторов, что и CSS** — если вы писали стили
в курсе веб-разработки, эти правила уже знакомы.

| Метод | Что возвращает |
| --- | --- |
| `document.querySelector('селектор')` | первый подходящий элемент — или `null`, если ничего не найдено |
| `document.querySelectorAll('селектор')` | список всех подходящих элементов (может быть пустым) |

| Селектор | Что находит | Пример |
| --- | --- | --- |
| `p` | все элементы этого тега | абзацы на странице |
| `.card` | элементы с этим классом | `.product-card` — карточки товаров |
| `#header` | элемент с этим id (на странице такой id должен быть один) | `#search-form` |
| `ul li` | li, вложенные в любой ul | пункты списков |
| `input[type="email"]` | элемент по значению атрибута | поле именно для email |

```js
const кнопка = document.querySelector('#submit-btn');        // первый элемент с этим id
const карточки = document.querySelectorAll('.product-card'); // список всех карточек
const абзац = document.querySelector('p');                   // просто первый p на странице
const ничего = document.querySelector('.не-существует');     // null — такого класса нет
```

<Callout title="querySelectorAll — не совсем массив">
Результат `querySelectorAll` называется **NodeList**. По нему можно пройтись циклом `for` или методом
`forEach`, но методов `map`, `filter` и `reduce`, как у обычного массива, там нет. Если они нужны —
оберните результат в `Array.from(...)`: `Array.from(document.querySelectorAll('.card'))`, и дальше
работайте как с массивом. Ещё вам может встретиться старый метод `document.getElementById('id')` — он
появился раньше `querySelector`, работает чуть быстрее, но понимает только id и не умеет CSS-селекторы.
В новом коде обычно достаточно `querySelector`.
</Callout>

## Меняем то, что на экране: текст, классы, стили

Элемент нашли — что дальше? Три самые частые операции: поменять текст, поменять класс (а через него и
внешний вид средствами CSS) и, реже, поменять стиль напрямую.

**`textContent`** — свойство, которое читает и меняет текст внутри элемента как обычную строку:
`элемент.textContent = 'Готово'` заменит всё содержимое на это слово. Способ безопасный: даже если в
переменной случайно окажется чужая разметка — например, текст из формы обратной связи, — `textContent`
вставит его как обычный текст, а не выполнит как HTML. Похожее свойство **`innerHTML`** вставляет именно
HTML-разметку: удобно, когда нужно вставить сразу готовый кусок вёрстки, но опасно для непроверенного
чужого текста — через `innerHTML` можно случайно протащить на страницу чужой скрипт. Практическое
правило: для простого текста — `textContent`, для разметки, которую формирует сам код, — `innerHTML`.

| Метод | Что делает |
| --- | --- |
| `classList.add('x')` | добавляет класс, если его ещё нет |
| `classList.remove('x')` | убирает класс, если он есть |
| `classList.toggle('x')` | добавляет класс, если его нет, и убирает, если есть |
| `classList.contains('x')` | проверяет, есть ли класс — вернёт `true` или `false` |

```js
const строка = document.querySelector('.order-row');

строка.classList.add('overdue');     // подсветили как просроченный заказ
строка.classList.remove('overdue');  // сняли подсветку
строка.classList.toggle('overdue');  // переключили: было — не стало, не было — появилось

if (строка.classList.contains('overdue')) {
  console.log('Заказ просрочен, нужно напомнить клиенту');
}
```

Стили можно менять и напрямую через свойство `элемент.style`, но имена CSS-свойств здесь пишут в
camelCase, без дефисов: не `background-color`, а `backgroundColor`. Строка
`строка.style.backgroundColor = 'red'` подкрасит фон немедленно. На практике так делают редко: удобнее
завести CSS-класс с нужным оформлением заранее и переключать его через `classList`, как в примере выше, —
тогда правила оформления живут в одном месте, в CSS, а JavaScript только решает, когда какой класс
нужен.

## События: addEventListener оживляет страницу

Всё, что было до сих пор, выполнялось один раз при загрузке скрипта. Чтобы страница реагировала на
действия человека, нужны **события** (events) — и метод `addEventListener`, который есть у любого
элемента:

```js
элемент.addEventListener('click', function (событие) {
  // код, который выполнится при клике
});
```

Первый аргумент — тип события строкой, второй — функция-обработчик (её ещё называют колбэком: она
сработает не сразу, а когда событие произойдёт). В обработчик браузер передаёт **объект события**:
`событие.target` — тот конкретный элемент, по которому кликнули (это понадобится в разделе про
всплытие), `событие.type` — тип события строкой, а для полей ввода `событие.target.value` — текущее
содержимое поля.

| Событие | Когда срабатывает | Где чаще всего используют |
| --- | --- | --- |
| `click` | клик мышью (или тап на телефоне) | кнопки, ссылки, пункты списка |
| `input` | при каждом изменении текста в поле — на каждую нажатую клавишу | живой поиск, счётчик символов |
| `submit` | при отправке формы — по кнопке или клавише Enter | проверка данных перед отправкой на сервер |

Проверьте `click` и связку textContent + classList на живом примере — счётчик для отдела продаж,
который помечает посетителя «горячим» лидом после нескольких кликов:

У формы (`form`) есть особое поведение по умолчанию: при отправке браузер сам перезагружает страницу.
Обычно это мешает — мы хотим сначала проверить данные или отправить их сами через `fetch` (тема лекции
про асинхронность и API), без перезагрузки. Отменяет поведение по умолчанию вызов
`событие.preventDefault()` внутри обработчика `submit`:

```js
const форма = document.querySelector('#order-form');

форма.addEventListener('submit', function (событие) {
  событие.preventDefault(); // не даём странице перезагрузиться

  const количество = document.querySelector('#qty').value;
  if (количество === '' || Number(количество) <= 0) {
    alert('Укажите количество больше нуля');
    return;
  }
  console.log('Заказ на ' + количество + ' шт. готов к отправке');
});
```

<Callout title="preventDefault — первой строкой">
Вызывайте `событие.preventDefault()` в самом начале обработчика, до всех проверок. Если поставить его
после проверки, а проверка прервёт функцию раньше, — со страницей случится перезагрузка по умолчанию, а
введённые пользователем данные потеряются.
</Callout>

## Главный приём аналитика: из массива — в список на странице

Вот приём, которым аналитик пользуется чаще всего: есть массив данных — пришёл из API, посчитан в коде,
выгружен из отчёта, — и его нужно показать на странице списком или таблицей. Схема всегда одна и та же:
перебрать массив и на каждый элемент создать кусок разметки.

```js
const заказы = [
  { id: 101, сумма: 3200 },
  { id: 102, сумма: 890 },
  { id: 103, сумма: 15400 },
];

const список = document.querySelector('#orders-list');

заказы.forEach(function (заказ) {
  const пункт = document.createElement('li');
  пункт.textContent = 'Заказ #' + заказ.id + ' — ' + заказ.сумма + ' сом';
  список.appendChild(пункт);
});
```

`document.createElement('li')` создаёт новый узел в памяти — но он ещё нигде не показан. Строка
`textContent` записывает в него текст, а `appendChild` пристраивает узел последним ребёнком внутри
контейнера — только после этого он появляется на экране. Есть и более короткий способ: собрать одну
строку HTML через `map` и `join`, а потом вставить её целиком через `innerHTML`. Это компактнее, но если
в данных может оказаться текст от постороннего человека — комментарий, имя из формы, — используйте
первый способ с `textContent`: он вставит любой текст как текст, а не как разметку.

Важная деталь для списков, которые перерисовываются заново — например, при вводе в поиск: контейнер
сначала нужно очистить, иначе новые пункты будут добавляться поверх старых, а не заменять их:
`список.innerHTML = '';` в начале функции отрисовки, и только потом — цикл. Именно так устроена
песочница ниже: массив товаров с ценами в сомах генерирует список, а поле поиска фильтрует его на
каждое нажатие клавиши через событие `input`.

## Всплытие и делегирование: один обработчик вместо ста

Клик по конкретному пункту списка — это не событие «только для этого пункта». Браузер сначала запускает
обработчики на самом элементе, где произошёл клик, а потом поднимает то же событие вверх по дереву DOM —
к родителю, к его родителю, и так до самого `html` и `document`. Это называется **всплытие** (bubbling),
и по умолчанию так себя ведут почти все события, включая `click`.

<Mermaid
  title="Путь клика при всплытии: от пункта списка до document"
  chart={`flowchart TD
    A["Клик по li (кнопка Купить)"] --> B["Всплывает к ul.product-list"]
    B --> C["Всплывает к main"]
    C --> D["Всплывает к body"]
    D --> E["Всплывает к html"]
    E --> F["Всплывает к document — выше некуда"]`}
/>

Из всплытия следует полезный трюк. Обработчик необязательно вешать на каждый из ста пунктов списка —
достаточно один раз повесить его на общий контейнер (например, на `ul`) и внутри смотреть, по какому
именно пункту на самом деле кликнули, через `событие.target`. Это называется **делегирование событий**
(event delegation): контейнер как бы «делегирует» проверку клика одному общему обработчику.

```js
// Плохо: отдельный обработчик на каждую строку — сто строк, сто обработчиков
строки.forEach(function (строка) {
  строка.addEventListener('click', function () {
    console.log('Открыть заказ', строка.dataset.id);
  });
});

// Хорошо: один обработчик на общий контейнер — работает и для новых строк
таблица.addEventListener('click', function (событие) {
  const строка = событие.target.closest('tr');
  if (!строка) return; // кликнули мимо строки — например, по заголовку таблицы
  console.log('Открыть заказ', строка.dataset.id);
});
```

Метод `closest('tr')` поднимается вверх от точки клика и находит ближайший родительский элемент `tr` —
это нужно, потому что кликнуть могли не по самой строке, а по тексту или иконке внутри неё. Делегирование
особенно ценно для списков, которые перерисовываются данными, — как список товаров в песочнице выше:
обработчик на `ul` продолжит работать для любых новых пунктов после фильтрации, потому что клик по ним
всё равно всплывёт к тому же самому `ul`, на который навешан единственный обработчик.

<Callout title="preventDefault и stopPropagation — это разное">
`preventDefault()` отменяет действие браузера по умолчанию (переход по ссылке, перезагрузку формы).
`stopPropagation()` решает другую задачу — останавливает всплытие события дальше вверх по дереву. Их
часто путают, но нужны они в разных ситуациях, и вызов одного не заменяет другой.
</Callout>

## Граничные случаи: где всё ломается

**querySelector вернул null, а код обращается к нему как к элементу.** Причина — опечатка в селекторе
(например, `.produkt-card` вместо `.product-card`) или элемент, который в момент вызова ещё не появился
в DOM. `querySelector` не выбрасывает ошибку, если ничего не нашёл, — он молча возвращает `null`.
Ошибка выскакивает позже, на следующей строке, когда код пытается вызвать метод у `null`: «Cannot read
properties of null». Правильно: перед использованием проверять `if (элемент) { ... }`, а при отладке —
вручную вызвать тот же `querySelector` в консоли и посмотреть, что он на самом деле возвращает.

**Скрипт выполнился раньше, чем до конца прогрузился HTML.** Если тег `script` стоит в `head` без
атрибута `defer`, браузер запускает его сразу, как только до него доходит при чтении файла сверху
вниз, — то есть раньше, чем разобраны элементы, написанные ниже в `body`. Симптом тот же, что и в
предыдущем пункте: `querySelector` возвращает `null`, хотя селектор написан без единой ошибки и элемент
точно есть в файле — просто браузер до него ещё не добрался. Правильно: добавить атрибут `defer` тегу
`script` (он подождёт, пока HTML разберётся до конца, и сохранит порядок скриптов), либо разместить
`script` в самом конце `body`, перед закрывающим тегом.

**`input.value` — всегда строка, даже если в поле только цифры.** Два поля со значениями «2» и «2», код
делает `поле1.value + поле2.value` в надежде получить 4 — а получает «22». Причина: значение `input`
всегда хранится и возвращается как текст, независимо от атрибута `type`, а плюс между двумя строками —
это склейка (конкатенация), а не арифметика. Правильно: оборачивать в `Number(...)` перед вычислениями —
`Number(поле1.value) + Number(поле2.value)`.

**Обработчик клика навешан дважды.** Код настройки (например, функция инициализации формы) случайно
вызывается дважды — и при каждом вызове создаёт новую анонимную функцию-обработчик и передаёт её в
`addEventListener`. Браузер автоматически отбрасывает повторную регистрацию, только если это буквально
та же самая функция (тот же объект в памяти); две разные анонимные функции с одинаковым кодом внутри —
для браузера два разных обработчика, и оба выполнятся на один клик. Итог — заказ, отправленный на
сервер дважды. Правильно: держать обработчик в именованной функции, объявленной один раз, оберегать
код настройки от повторного вызова (например, флагом) или вызывать `removeEventListener` с той же
ссылкой на функцию перед повторным добавлением.

**Список меняется прямо во время перебора.** Код убирает из таблицы все строки дешевле 500 сом циклом
`for` по `document.getElementsByClassName('row')`, вызывая `.remove()` внутри цикла. После каждого
удаления и коллекция, и её длина мгновенно пересчитываются, поэтому следующий элемент сдвигается на
место удалённого — а цикл уже перешёл к следующему индексу и пропускает его. Причина: в отличие от
статичного `NodeList`, который возвращает `querySelectorAll`, методы `getElementsByClassName` и
`getElementsByTagName` отдают «живую» коллекцию, обновляющуюся сама при любом изменении DOM. Правильно:
перебирать с конца к началу, заранее превратить коллекцию в обычный массив через `Array.from(...)`, или
использовать `querySelectorAll` вместе с `forEach`.
